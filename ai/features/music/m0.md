**测试曲集**（全部是合成信号和内置音景的和弦配方，可以随意分发）：

- `formats/`：FLAC 16/44.1（带内嵌封面）、24/96、24/192（各带一个只有 Hi-Res 才装得下的超声音和一个只有 24 bit 才留得住的 −110 dBFS 音）；ALAC 16/44.1、24/96；AAC 256（带 ©lyr 歌词和封面）；MP3 320（ID3v2.3 标题是 GBK 字节却标成 ISO-8859-1，普通读法显示 `ÓêÌìµÄ´°±ß`，修复后应为「雨天的窗边」）；WAV 24/48、32 位浮点；AIFF；Ogg Opus、WebM Opus、Ogg Vorbis；WavPack；4 分钟 CD 级 FLAC（拖动测试）；30 秒 24/192 FLAC（串流测试，14.8 MB，Free 计划也传得上去）
- `gapless/`：45 秒连续滑音做成的整轨 `album.flac` + GBK 编码的 `album.cue`（3 段），同样内容的三个分轨文件，以及 WavPack 版整轨（代替 APE 测「需要转换」）
- `lyrics/`：5 首内置音景渲染成的 FLAC（带 ReplayGain 标签）：同名逐句 .lrc、同时间戳双语 .lrc、逐字 .lrc、GBK 编码的 .lrc、只有内嵌歌词
- `manifest.json`：每个文件的 SHA-256、解码后 PCM 的 MD5、编码参数和各浏览器是否该能放
- ffmpeg 编不出 APE 和 DSF：测转换流程时从自己的曲库里拿一首 APE（+CUE）和一首 DSF

**和方案书的一处不同**：私有曲目的文件不再搬到 `<world>/p/<owner>/`。原件统一放在 `<world>/orig/<sha256>.<ext>`，能不能读由数据库判断（上传者本人，或这个文件属于一首对 TA 可见的曲目），所以切换「仅自己」不用搬文件、立即生效。往 `orig/` 上传必须先有一条属于自己、状态为「上传中」的 `music_files` 预留记录；`r/`（Worker 写的派生文件）只读；`tmp/<自己>/` 是可删的临时区，M0 验证页就用它。

## 二、需要你做的（按顺序）

1. **Supabase 计划**：先用 Free（用户 10-03 定）。单个对象上限 50 MB，一期把更大的文件（Hi-Res、整轨）拆成 45 MiB 的分片存，不用升级；以后升 Pro：Storage → Settings 把全局单文件上限设到约 5 GB，Billing 里关掉花费上限或设用量提醒，再把 `src/lib/music/upload.ts` 的 `DEFAULT_MAX_OBJECT_BYTES` 调大。
2. **应用迁移**（二选一）：
    - SQL Editor：先把 `supabase/migrations/20261001100000_music_library.sql` 全文粘贴运行，再运行 `20261003100000_music_ingest.sql`（一期的入库 RPC、分片、实时通知）。都可以重复运行，顺序不能反。
    - CLI：先在 Dashboard → Account → Access Tokens 生成新令牌（TODO 记录旧的已失效），`supabase link --project-ref xrscspcqnsxvfshskfpy`，再 `supabase db push`。仓库还没有基线迁移，这次只会推这两份音乐迁移。
    - 运行后核对：`select id, public from storage.buckets where id = 'music';` 有一行；`select polname from pg_policy where polname like 'music%';` 能看到 `music: read / upload / remove scratch` 和各表的策略。
3. **真机验证**：
    - 电脑上：`python3 scripts/make-music-fixtures.py`（需要 ffmpeg）；`pnpm dev --host`；浏览器打开 `http://localhost:5173/dev/music-check`，在第 2 节上传 `formats/` 里的 01、03、04、07、11、15、16 号，再加一首自己的 FLAC（有的话再加 APE、DSF 各一首）。
    - iPhone 连同一个 Wi-Fi，Safari 打开 `http://<电脑的局域网 IP>:5173/dev/music-check`（同一个账号）：第 1 节点「点一下检测」；第 2 节每个文件点「测试」（会出声几秒）；第 3 节做锁屏测试；第 4 节「复制结果」，贴回对话。
    - 有安卓手机、Mac Safari 的话各跑一遍更好。
    - 局域网 http 下没有锁屏控制条（Media Session 只在 HTTPS 下可用）和一键复制（会改成选中全文），其余测试不受影响。
4. **拍板**：在方案书页面投票，或直接回复 D1–D8 的选择和 Q1–Q8 的答案。
5. （可选）Dashboard → API Keys 生成 `sb_publishable_…`，替换 `.env.local` 里 `VITE_SUPABASE_ANON_KEY` 的值（变量名可以先不改）；Supabase 计划在 2026 年底前停用旧的 anon key。

## 三、结果怎么读

| 检查                     | 通过                                                                      | 不通过意味着什么                                                                       |
| ------------------------ | ------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| 两字节 Range 请求        | `206`，`bytes 0-1/文件大小`                                               | 回 `200` 或失败：iOS 会拒播（supabase#35866 很可能就是这个原因）→ D6 改 S2，由 R2 出流 |
| 出声（每个文件）         | FLAC 16/44.1 能放；Wi-Fi 下出声 < 1.5 s                                   | 所有文件都放不了：存储侧问题，先别往下做；个别格式放不了：对照下面的格式矩阵           |
| 24/192 FLAC              | 能放                                                                      | iPhone 放不了：Hi-Res 原件需要 Worker 另出一份 24/96 或 24/48 的无损串流版（M7）       |
| 拖动后恢复               | < 0.5 s                                                                   | 偏慢：看网络；之后的播放器要复用同一个签名 URL 命中 CDN                                |
| Web Audio                | 有信号                                                                    | 静音：存储没有回 CORS 头，增强模式（响度、淡化）用不了；纯净直出不受影响               |
| 锁屏                     | 继续播放                                                                  | 停了：记下 iOS 版本。纯净直出锁屏就停是阻塞问题，要先解决再进 M3                       |
| 脚本改音量               | iPhone 上「被锁定」（预期）                                               | —                                                                                      |
| 系统输出采样率           | 记下来（常见 48000 Hz）                                                   | 这是信号路径面板里「输出」那一格的真实值                                               |
| ALAC / Opus / WavPack 等 | 与格式矩阵一致：ALAC 只有 Safari、Opus 要 iOS 17.4 / 18.4、WavPack 都不行 | 不一致：更新 music.md 和方案书里的格式表                                               |

## 四、本地复现

```bash
sudo apt install ffmpeg postgresql-16 postgresql-16-pgtap    # Ubuntu；macOS 用 Homebrew 的 ffmpeg / postgresql / pgtap
bash scripts/check-music-db.sh                                 # 迁移连跑两遍 + 62 条权限断言
python3 scripts/make-music-fixtures.py                         # 生成 tmp/music-fixtures/
pnpm dev                                                       # 另开一个终端
DIARY_NODE_MODULES=<含 playwright 的 node_modules> node scripts/check-music-probe.mjs
```

## 五、留给 M1 的

- 入库 RPC：`existing_hashes`（批量查重）、预留与完成上传、`music_ingest`（一个事务写曲目、文件、歌词、海报、原件播放版本），以 SECURITY INVOKER 运行，让上面的 RLS 继续把关。
- 曲库变化走 `realtime.broadcast_changes()` 推到 `world:{id}`。
- 边界情况：同一世界里文件按哈希唯一，如果 TA 把同一个文件设成了私有，你再传会撞唯一约束，RPC 里要给出明确提示。
