# 全项目 UI / UX 统一

> 2026-09-12。盘点与计划已完成、产品尚未改造；本文定义目标与实施顺序，不代表目标已实现。已定范围与待确认建议见 §8。
> 任务状态只记在 [TODO](../../TODO.md)；当前代码事实见 [审计](audit.md)；视觉登记见 [UI 总览](../../design_system/uiux/cinnaglass/ui-system.html#ui-unification)。

## 1. 这次要收敛什么

视觉签名：**映着小屋暖光的细纹磨砂玻璃**。场景给氛围，UI 给清楚稳定的操作。三类按使用方式与载体划分，共用颜色语义、文字、控件与交互规则，不能变成三个互不相干的主题。

| 体系          | 用途与范围                                                                        | 材质方向                                                                               | 状态                                      |
| ------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- | ----------------------------------------- |
| A 场景悬浮 UI | 导航、天气、聊天窄窗、音乐两态、纪念卡、头顶状态、附着小菜单                      | 导航的中性细纹磨砂玻璃，按内容密度调厚度                                               | 用户指定导航为基准，其他待迁移            |
| B 任务界面    | 设置、世界设置、日历/闹钟、完整聊天、确认/选择/错误提示；登录/重置/大厅为页面形态 | **建议：同源较厚中性磨砂壳 + 稳定阅读/表单底**；留细边与暖光，不沿用全窗旧纸、苔绿包边 | 推荐方向，需先看设置标准板再定参数        |
| C 专属物件 UI | 日记等有专属几何、材质、开合方式的实体载体                                        | 物件自身定义，外部公共控件遵循共有规则                                                 | 本 session 日记冻结；其他专属载体另案设计 |

**入口不决定材质**：点唱片机仍开 A 音乐浮窗，点挂钟仍开 B 时钟，相框与导航照片入口进同一界面。照片墙、心愿单暂列 B；只有以后批准相册/许愿罐专属形态才迁为 C，不能仅因物件可点击就重做。

**日记冻结范围**：阅读、写作、详情、书本资产、翻页、遮罩、布局、物件资源、C 的任何清理，及这些路径依赖的共享规则。后续改 `surfaces/object-surfaces.tsx`、`materials.css`、公共 `.modal/.paper` 前必须证明只覆盖 A/B，不能顺手清理看似过时的日记文件。房间美术和活物光照引擎也不随 UI 换肤重做。

## 2. 导航母材质：现状与建议

### 2.1 已核实的实现

机制（固定纹理图、`backdrop-filter` 透景、`conic-gradient` 模拟边光、mood 预设驱动暖冷、只有房间底图换图）见 [navigation-glass.md](../navigation-glass.md)，数值与逐项验证见 [navigation-implementation.md](../../design_system/uiux/cinnaglass/journal-room-object/navigation-implementation.md)；本文不复述。

此处只留结论：**导航不直接消费天气或灯位置**，晴转雨改变后方场景但不改 `--nav-rim`；任何文档都不得再称其为"真实场景反射"。

### 2.2 保留的基准

- 桌面 74×384，圆角 25，左距 38，垂直居中；窄/矮屏 292×62 底部横条。五入口保持房间、聊天、音乐、工具、设置。
- 透明、中性、细纹与局部强弱不同的薄边，保持已认可的暖光反馈；不统一成固定绿色面板，也不回到整条糖果渐变边。
- 导航小菜单已是同源加厚变体（模糊 8px，底色透明度至少 0.5），是扩大复用的起点，不是另一套材质。
- 纹理、环境高光、交互高光分层，图标与文字处于独立清晰层。

### 2.3 推荐的最终规则（待标准板验收）

1. **纹理静止**。同一中性纹理源；宽面板先验平铺接缝与颗粒尺度，多个面板明显"复制同一块云纹"时给组件固定取样偏移。不随 render、打开、时辰或动画重新抽样，不做噪声闪动。
2. **光照参数同源**。场景向 UI 提供时辰/天气/主光暖冷与方向，A/B 消费同一份环境描述。先保留导航三档观感；以后边缘高光可随参数缓慢变化，仍属艺术化模拟。
3. **不把逐帧场景采样、反射贴图、法线/光追当本轮前置**。这类方案须单独证明视觉收益与常驻性能成本，换房间不能要求重画每个 widget 外壳。
4. **厚度跟着内容走**。同源纹理与边缘不等于所有面板同一模糊和透明度：图标导航薄，聊天/播放器有稳定阅读底，任务弹窗更厚。文字区域不透出干扰细节。

### 2.4 原画与环境光照工作流（2026-09-12）

`art-relighting` 技能覆盖原画定稿、材质/光色拆分、环境变体与还原验收，职责与事实见 [原画分层与环境光照](../../design_system/research/art-relighting.md)；它只是工作流，不代表已有中性房间底图或真实反射。M1 须先定天光、窗光与室内灯的职责，再验 A/B 外壳响应；具体值与图层/shader 取舍未定稿，运动与动态阴影后置。

## 3. 共用视觉与组件规范

推荐约束，具体色值/尺寸在 M1 标准板上确定，不把未验证数值写成"已定稿 token"。材质/字体/色语义的行为面规则见 [interaction.md §8](../../design_system/uiux/interaction.md)。

### 3.1 风格与组件基线

- 色与光：中性烟灰、柔和米白、暖金、身份蓝、身份粉五类，红/绿只作错误/成功/在线语义、不作装饰底色；环境只影响外壳细微暖冷与边光，操作反馈用暖金，身份/成功/危险不因时辰换义；照片原色不受外壳滤镜污染。
- 质感与形状：静止细纹、轻雾透景、薄局部反光、柔和接触阴影，表单底稳定，旧纸只属于获准的内容/物件；柔圆矩形为主，胶囊只给短条/状态，圆形只给确有需要的图标动作，不把按钮都做成发光球。
- 字体：A/B 正文与控件统一圆润无衬线（延用 Noto Sans SC/system 回退），手写/衬线只给物件和内容，禁止每弹窗一套标题字体。正文 14–16px、辅助 12–13px，小窗减布局不缩字。
- 层级：基础值（排版/间距/形状/阴影/图标度量）→ 语义值（A/B 两种壳与内容底、主次文字、边线、focus/hover/selected/danger/disabled）→ 公共控件（Button、IconButton、Field、Switch、Segmented、Slider、列表行、Badge、Tooltip、Popover、Dialog、确认框、状态提示）→ 功能组合。同一语义只有一个定义位置；功能组合只管内容与行为，不在各自 `<style>` 里重复整套材质；`icons.tsx` 导航线性图标是视觉锚点，保留路径资产后统一用法。
- 状态：控件至少覆盖 default / hover / pressed / focus-visible / selected / disabled / pending / error；高光之外须有轮廓、文字或选中标记，键盘/触屏/降动效时也能识别状态。语义先定，动画后置。

### 3.2 Token 迁移建议

`--nav-*`、`--cg-*`、`--shell-* / --glass-*`、`--craft-*` 各有消费者（清单见 [审计 §1](audit.md#1-当前不是一套-ui-材质)）。顺序：先加 A/B 明确入口逐个迁移 → 旧名降为兼容别名 → 最后清无消费者的旧值。目标关系（命名示意，未写入产品）：环境参数 → 共用玻璃材质（tint/grain/blur/rim/shadow）→ A、B 两个表面族，其上叠共有控件；C 继续用自己的物件材质。

不要把"改造 B"做成一次全局替换 `--craft-paper`，也不要用不断增长的全局选择器清单猜组件属于哪种文字色域；新 A/B 用显式表面作用域，旧别名在有消费者时继续存在。

`data-glass` 的云朵/天空/暮光旧开关不能一致控制导航和 widgets。建议最终只留一套产品材质，"减少透明效果"作为功能性偏好单列；旧存储值兼容与设置项移除跟迁移一起做，不留无效果的开关。

## 4. UX 契约

### 4.1 层级与关闭

| 层             | 规则                                                                 |
| -------------- | -------------------------------------------------------------------- |
| 房间           | 场景与音频按各自生命周期运行                                         |
| A 常驻/悬浮    | 可与场景交互，不开全屏暗幕；多浮窗用固定停靠区与避让规则             |
| A 附着层       | 跟触发控件定位、超边缘翻转；同组只开一个；Esc/点外关闭并回焦点       |
| B 遮罩与任务窗 | 在 A 之上；打开时背景与 A 不可操作也不参与 Tab；不叠多层全屏磨砂遮罩 |
| B 内附属层     | 选择器/确认框在所属任务窗之上；Esc 只关最上层，不连关多窗            |

B 需统一 dialog 语义、标题关联、初始焦点、焦点限制、关闭归还焦点和隐藏 `inert`；保存失败留输入，带未保存内容的点外/Esc 按该任务草稿策略处理，成功提示只在真实成功后出现。不要顺带替换日记现有的关闭/草稿逻辑。

### 4.2 响应式

- 桌面以左导航为锚点，给左下聊天、右下音乐、顶部天气/纪念卡划停靠区；展开态不能盖住自己必须使用的控件。
- 中等/矮屏降密度、留主要入口与当前任务、允许信息卡折叠，不靠整体缩放解决；窄屏底部导航留安全区，聊天/音乐展开优先互斥，天气与纪念卡错开，所有宽度受容器上限约束。
- B 小屏改为留安全边距的全高任务页或底部面板，标题/关闭、输入区与主动作可达，软键盘打开后仍可提交或收起。
- 触控目标 44px 起验收（细图标可小但点击区不缩小），另查焦点可见、长文本换行、200% 文本缩放。

### 4.3 功能状态必须诚实

1. 音乐的播放/暂停、展开/收起、进度与曲目各自来自实际状态，不能用展开态冒充播放态；隐藏 widget 不销毁音频引擎，导航音乐入口能恢复被隐藏的播放器。
2. "修改密码/绑定邮箱/应用锁"先核对真实能力再决定接通或收起，不能只改本地文字就显示成功；世界设置恢复到"设置 → 我们的小世界"。
3. Presence、天气实况失败、闹钟提醒、共享音乐同步等未接通的状态必须明确，不加占位在线绿点或虚构更新时间。
4. 纪念卡、日历与世界设置共用纪念日来源；本地数据与双人同步数据的能力边界清楚。
5. 保留聊天已有的历史加载、发送失败重试、编辑/删除、reaction 与贴纸；只收起服务器/好友导航外壳，数据层冻结保留。

## 5. 全组件处置

组件地图与建议归属见 [审计 §2](audit.md#2-入口与组件地图)，清理边界与依赖证据见 [审计 §4](audit.md#4-清理时不能踩的依赖)，改造批次见 §6，冻结范围见 §1，导航基准见 §2.2；本节不复制这些清单。唯一补充的规则：旧值（固定石墨/灰绿 `--cg-*`、旧 `.glass` 布局假设、B 全窗暖纸覆盖、重复控件与旧 widget 注册项）一律**迁移后才清理**，且只清按审计 §4 证明无消费者的部分。

## 7. 验收矩阵

| 维度       | 后续实施必须检查                                                                                                                                                                          |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 场景与尺寸 | golden/twilight/night × 晴/雨，明窗、暗墙、暖灯附近；1440×900、1280×720、960×640、390×844，另含 640×400 矮屏、320px 边界与 125%/150% 系统缩放。新房间上线前补验收，缩略图不能冒充花园实景 |

| 视觉与降级 | 对真实合成背景采样，正文 ≥4.5:1、主要图标/焦点线 ≥3:1，同组件三时辰保持身份与状态语义；减少动态效果、减少透明效果、不支持 backdrop-filter 时，稳定不透明底与可见焦点仍可用                |
| 性能与保护 | 对比迁移前后同场景同数量面板；仅外壳做背景模糊、禁止列表项单独 blur、静止纹理不驱动逐帧重绘；不迁移日记、不删数据链，共享材质改动涉及 C 时收窄选择器，无法证明隔离则延后                  |

## 8. 决策状态

**已确定的范围**（用户已定）：导航是 A 基准；全项目按 A/B/C 组织；日记本 session 不处理；动画后置；先出文档与可验收计划。

**本轮建议，待标准板确认**：B 同源厚磨砂/稳定阅读底；A/B 统一暖金操作反馈；纹理按组件稳定取样；光照按共享场景参数模拟；材质三选项收敛为产品默认材质 + 减少透明效果；照片/心愿暂按 B 处理。

这些建议在确认前不得登记成"用户已批准全部 UI"或"全站已迁移"。
