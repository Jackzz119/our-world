## 一、功能目标

用户 2026-09-27 原话要点：「优先完成书房的开发（翻新现在的书房）。第一期目标就是完成男女角色的场景和角色基本动作还有个别物品交互。手机版本 layout 和电脑版本同步开发。」

1. **翻新书房**：把现有的水彩书房（上一期，双犬角色）换成对坐书房——镜头就是你，桌子对面坐着对方的半身角色，前景是你自己的手和杯子。构图沿用对坐首张主视觉（雨夜城市窗边桌，左台灯、右唱片机）。
2. **先做她的视角**：用户说「我们先模拟对方视角开发，假设我登入的是她的账号，我本人是女角色」。所以第一期默认：**我 = 小满**（前景奶油色针织袖口），**对面 = 阿屿**。他的视角（对面是小满、前景炭灰卫衣袖口）随后做。
3. **男女角色的基本动作**：看书、抬眼、眨眼、呼吸、写字（对方输入中）、喝一口、酣睡（对方主动设为睡着）、摸头反应、戳一下反应、离开留痕。用户最喜欢的是摸头、酣睡，以及和对方当前操作绑定的倒一杯咖啡、TA 在输入时低头写字。
4. **个别物件交互**：台灯拉绳（真的开关灯）、倒一杯咖啡给对方、唱片机（落针放歌，唱片角先放进书房）、日记本（打开现有日记）、对方身上的戳一下 / 摸头。
5. **手机与电脑同步**：桌面横屏看完整构图；手机竖屏以对方的脸为焦点裁切；现有 Cinnaglass UI 停靠规则不变，头顶信息改锚到对方头部。

不在第一期：声音名片录制与存储（Storage 目前只收图片格式，需要改桶配置）、共享同听、掌心相贴 / 碰杯这类必须双方同时在线的互动、其他九个房间、大厅、自定义形象。

## 二、调用链路

```
WorldPage
 └─ RoomScene (room-scene.tsx)                 React 壳：挂 Pixi、气泡与名牌落位、dev 对方状态面板
          └─ buildTableScene(app, STUDY_TABLE, cast, init, events)      table-scene.ts
               ├─ 底图组：时辰 × 晴 / 雨，开灯版在下，关灯版按台灯亮度盖上
               ├─ 窗面雨层（窗格遮罩）                 rain-layer.ts
               ├─ 外套留痕（离开 / 离线）
               ├─ 对方人物：姿势、眨眼、呼吸、触碰区    partner-layer.ts ← partner-state.ts（导演）
               ├─ 对方的杯子 + 蒸汽                     steam-layer.ts
               ├─ 台灯拉绳（拦截 lamp 热区）
               ├─ 热区星芒（timeline / music / photos）  affordance.ts
               └─ 前景：我的手和杯子 + 蒸汽（按我的形象）
```

- 对方状态 → `PartnerState`（`reading | writing | away | offline | asleep`）→ 人物姿势、留痕、杯子热气和睡着时的台灯亮度；互动反应（`glance | sip | poked | patted`）临时覆盖姿势，结束后回到状态姿势。
- `lamp` 热区在场景里拦截（拉绳）；其余热区照旧经 `onHotspot` 交给 WorldPage 映射到功能。
- 第一期形象固定为 `viewer = xiaoman, partner = ayu`（`room-scene.tsx` 的 `CAST`），账号级形象归属之后再做。

## 四、时间线 / 参数

| 参数               | 值（已实装，2026-09-27 实测）                                                                                                                                                                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 姿势切换           | 看书、抬眼、写字、摸头、戳一下之间：420ms 光流形变（easeInOut），旧姿势沿光流弯向新姿势的形状、新姿势从旧形状松回来，新姿势在 25%–75% 之间显形、盖满后旧姿势在最后 20% 淡出。进出喝一口：引导形变（书和手从书的框走到杯子的框、头从脸框到脸框），420ms，换图窗口收窄到 35%–65%。进出酣睡：引导形变（头），900ms，同样的窄窗口。所有姿势贴图在场景建好时预先上传 GPU |
| 眨眼               | 闭眼 140ms，间隔 2.4–6.5s 随机，15% 概率连眨；闭眼帧已按光流对齐到睁眼帧；形变过程中不眨；喝一口暂不眨眼（闭眼帧不合格）                                                                                                                                                                                                                                            |
| 呼吸 / 微摆 / 头发 | 网格顶点间距 24px（姿势画布），权重图 `public/characters/ayu/idle-<姿势>.png`（R 呼吸、G 头发，marionette 的 weights 步骤生成；酣睡不认头发，头枕在深色袖子上会被认成头发）；呼吸 3.6s 周期、按权重上抬最多 3.2px；上半身 7.4s 周期 ±0.004rad 绕躯干底部中点，只作用于随呼吸动的部分；头发 4.2s / 2.3s / 3.1s 三个周期叠加，发梢最多 4.5px，相位沿头发往下传        |
| 抬眼               | 看书时每 20–60s 随机一次，持续 2.5–4s；写字时不抬眼                                                                                                                                                                                                                                                                                                                 |
| 喝一口             | 看书时每 90–180s 随机一次，持续 2.4s，杯子离开桌面；「递一杯咖啡」目前由 dev 按钮立即触发，倒咖啡仪式做好后改在杯子滑到对面后触发                                                                                                                                                                                                                                   |

| 摸头               | 按住头部并移动超过 12px 进入，按住期间保持，松手后 0.8s 回到状态姿势；触碰只在看书 / 写字时生效                                                                                                                                                                                                                                                                     |
| 台灯               | 开 / 关交叉淡化 420ms；关灯时活物 tint 再乘 `0xb8c0d8`（约 ×0.72 / 0.75 / 0.85，偏冷）；对方睡着时 1.6s 内自动调暗到 55%                                                                                                                                                                                                                                            |

## 五、待实现 / 已知问题

- **Presence 权限未知**：Realtime 私有频道的 presence 需要 `realtime.messages` 的对应策略。Supabase 管理访问（MCP）401 的原因已查明：`.mcp.json` 从用户环境变量 `SUPABASE_ACCESS_TOKEN` 读个人访问令牌，服务端拒收，令牌已过期或被吊销；需要用户在 Supabase 后台重新生成令牌、更新环境变量并重启应用。app 自身的连接（`.env.local` 的地址与 anon key）不受影响。
- **声音名片存储**：`memories` 桶只允许 png / jpeg / webp / avif，音频要改桶配置，同样需要 Supabase 访问。
- **形象归属**：第一期没有账号级形象字段，先用本地设置「我是：小满 / 阿屿」；之后加 `profiles` 字段或形象表。
- **手机清晰度**（2026-09-28 用户在 iPhone 上看到模糊与锯齿）：
    - 已修：渲染分辨率原来封顶 2 倍，3 倍屏被浏览器再拉伸 1.5 倍，线稿发糊发锯齿；现在按屏幕实际密度渲染（最多 3 倍，总像素不超过 800 万），晴天不跑无效的天气调色滤镜，省回一部分开销。
    - 雨天另有一处（已修）：天气调色滤镜按 Pixi 默认的 1 倍分辨率渲染，雨天整幅画面被压到 1 倍再拉回，锯齿最明显；滤镜现在跟随画布分辨率。
    - 不做：素材本身精度不够手机（竖屏下底图约放大 2.5 倍、人物约 1.44 倍，所有高密度手机都一样，不只 iPhone）。重新出高精度版本无法保证和现有底图、人物一模一样，用户 2026-09-28 决定不做。
- **线上还没有真实在场**：接 Realtime Presence 之前（ST-6），生产环境里对方默认坐着看书，不能表达离开 / 离线 / 睡着，和「人不在就是空椅」的铁律有差距；开发环境用面板模拟。
- **阿屿第一批姿势的缺陷**（Codex 自审报告 `arts/characters/ayu/source/codex-report.md`）：
    - 喝一口的闭眼帧重画了袖子——2026-09-28 重出，喝一口也眨眼了；
    - 喝一口的躯干截断线「低约 16px」其实是反的：brief 定的截断线 y=900 本身估错了，桌面远沿在画布 y=968（底图 y 646 经配准换算）。截断线停在 900 附近时，躯干和桌面之间露出一截椅背，就是那道「硬边」；其他姿势的手臂和书正好盖住，只有双手举杯的喝一口露了出来（见下）；
    - 其余三组闭眼帧原来眼外有 2–5% 像素偏移（逐帧生成时眉毛、镜框、发丝跟着挪了一两个像素，用户看得出）；2026-09-28 按光流把闭眼帧对齐回睁眼帧，看书 3.6% → 1.3%、抬眼 2.2% → 0.8%、写字 5.1% → 1.1%；
    - 「被戳」只有笑，没有缩一下（为了肩线不漂移放弃了缩身）——2026-09-28 由运行时手势补上（见 §四「戳一下反应」）；
    - 「被戳」的发型比看书胖一圈（右侧发缘整条外扩约 10px，并多画了一缕头发）。2026-09-28 重出（见下），多画的那一缕没有了，剩下的几何差由 `align_to` 对齐。
- **2026-09-28 重出与复查**（批次 `ai/design_system/codex-visual/20260928-194257Z/`，每张 3 个候选，用 `rig.py pick` 按「对齐后头发轮廓还剩多少对不上」挑，再人看一眼）：

- **反应**：戳一下、摸头（按住保持、松手 0.8s 回去）、喝一口（杯子离桌）正确。
- **光**：三档时辰 × 晴 / 雨，开 / 关灯正确。
- **tsc / eslint / prettier**：本轮文件全部通过。

测试中发现并修掉的问题：

- **开发面板把画布往下推了 88px**：`.table-dev` 的优先级输给全局 `.ui-surface { position: relative }`，面板掉进了文档流。改用和气泡一样的复合选择器。
- **宽屏看不到我的手**：旧取景把脸放在屏幕中间，在 1.9:1 的屏幕上前景整片被裁掉。改成宽屏从头顶往下取。
- **手机上头顶的气泡被顶栏盖住**：时辰 / 天气圆钮和纪念卡就在头顶上方。改成贴右边缘。
- **贴边气泡被挤成 56px 窄条**：绝对定位加 `left` 时，收缩适配只剩 12px 可用宽度。改用 `right` 定位。
- **换时辰时画面变暗一下**：旧的交叉淡化让新旧两张同时半透明，中途约 25% 透出背景。改成新组整组盖上、旧组事后再暗。
- **摸头时头发右边多出一块**（2026-09-28 用户发现）：盖上再淡出时，旧姿势（看书）的发型轮廓比摸头姿势宽，新姿势盖满后那一块还露在外面，直到旧姿势淡掉。改成光流形变：旧姿势先弯成新姿势的形状，交接时两者轮廓一致。
- **抬眼时眨眼，眉眼和原图有偏移**（同日）：逐帧生成的闭眼帧把眉毛、镜框、刘海挪了一两个像素，一眨眼整张脸跳一下。改成光流对齐。第一版对齐让局部光流也作用在眼睛里，把闭眼的睫毛线拖成了 S 形（闭眼的眼睑被匹配到睁眼的虹膜边缘）；改为眼睛那一带只跟头部整体运动。
- **喝一口的形变把书拖扁**：第一版给所有姿势对都做了形变，喝一口的书被光流压到桌沿、手留下虚影。加了轮廓检查（形变后和目标轮廓对不上的比例：合格的对 ≤ 2.5%，喝一口的对 ≥ 6.8%，阈值 5%），喝一口退回盖上再淡出。
- **被戳时头发还是多一块**（2026-09-28 用户再次发现）：形变让它变柔和了但没消失——问题不在过渡，在被戳这张图本身（发型胖一圈 + 多画一缕）。几何部分用反应对齐修掉，多画的一缕要重出；同时给被戳加了一缩再笑的手势，原来只是换一张笑脸，很干。
- **形变场位移被截断**：旧格式每个顶点的位移用一个字节存（值 = 位移 + 128），只能表示 ±127px，写字 ↔ 被戳这一对的手要移 140px，最后十几像素被截掉。迁到 marionette 后是 12 位格式（±256px、1/8px 精度）。
- **组件里的 ref 在渲染时赋值**：原来靠一条 `eslint-disable` 让 React Compiler 的检查整组件跳过，所以没被发现。改到 `useLayoutEffect` 里赋值。
