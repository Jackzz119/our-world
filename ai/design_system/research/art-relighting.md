> 2026-09-12 建立 `art-relighting` 技能与光层预览。资产制作流程首版，**产品的房间资产与光照实现尚未改造**。

## 目标

先生成并确认原画，再从定稿制作能稳定重组的材质与光照资产（场景 / 物件 / 角色）；未来由同一环境描述同时驱动场景与 UI，保持手绘质感又有接近三维的连续受光。物件运动（`living-props`）与动态阴影独立建设。

## 技能入口

用户级 **Codex** skill `art-relighting`，遵循项目 AGENTS 的用户级 skill 规则。**入口路径因机器而异**（各人 Codex skills 目录下的 `art-relighting/SKILL.md`）；其他环境必须读本机实际可用的 skill，不假设目录自动同步。自带 `scripts/compare_renders.py` 做同尺寸渲染比较（平均差 / p95 / alpha 差，无阈值时只报告）。**项目专有参数留在本文与房间配置**，技能不写死书房路径、三档 mood 或 Pixi 版本。

## 当前原画与光层事实

### 定稿原画

三张 1586×992：真源 `arts/rooms/study/source/{golden,twilight,night}.png`，运行时底图 `public/rooms/study/<mood>.png`。窗光、台灯、反光与阴影已经画进图里；运行时版本只为活物装配清理了唱片和唱臂区域，**不能称为已去光的中性 base**。mood 三档与项目目标里的四时辰不是一回事。

[渐变光层预览](art-relighting-preview/index.html)（三张原画 × 晴雨六配方，纹理可下载）、[静态对照图](art-relighting-preview/gradient-textures.png)。预览页原画走 `/arts/...` 绝对路径，**必须 `pnpm dev` 后经 Vite 根路径打开**，双击本地文件会丢图。

### 渐变不是另一张房间原画

`src/themes/cinnaglass/room/pixi-scene.ts` 的 `RECIPES` 加两个小画布函数生成：

- **wash**：64×64 线性 RGBA 渐变，方向 115°，拉伸覆盖房间，现有配方均 normal 叠加。
- **glow**：256×256 径向 RGBA 渐变，中心浓边缘透，按窗位放大，screen 叠加。
- 雨天另有深色径向层（`breathAlpha`）做云影呼吸；world 容器另有天气饱和度/亮度修正，角色与钟针走 `actorTint`、唱臂走 `armTint`。

这些是手写画面配方，**当前没有使用 Pixi 的 AmbientLight 灯对象**；预览页也不拿「原图 + 一张渐变」冒充完整运行时合成。预览是 2026-09-12 的代码快照，`art-relighting-preview/recipes.json` 记源文件与 SHA-256；产品配方一改就要重新导出——**它不是与源码双向同步的编辑器**。

### 唱片给出的边界

v5 盘面是**旋转对称基底 + 标签印花 + 固定 add/multiply 光层**（细节见 [living props](living-props.md)）。「拆出了光和 tint」不能概括盘面：基底仍含沟槽与部分对称的绘制光影，**不是严格去光的 albedo**；**角向统计只适用于旋转对称物体**，不能套到房间或角色。以 `study-room.ts`、`pixi-scene.ts`、`build-turntable-parts.py` 为准，旧命名注释里的 albedo 不作物理语义证明。

## 资产工作流的两条路线

| 路线         | 交付                                            | 何时选                           |
| ------------ | ----------------------------------------------- | -------------------------------- |
| 保持定稿外观 | 各 mood 外观底图 + 可控光层，写明保留了什么光   | 稳妥还原、状态少（如现有唱片）   |
| 共享中性母版 | 同一材质本色/纹理 + 光/色温/遮罩 + 必要辅助地图 | 要扩展天气、局部灯或连续环境组合 |

「中性」= 去掉特定环境影响，**仍保留木头颜色、布纹、毛发和笔触**，不是把物体变白或去饱和。单张图无法唯一分清深色材料与阴影，遮挡信息也可能缺失；补绘/生成区域必须记录来源并验证。

法线=表面朝向，高度=局部起伏，深度=远近；能帮受光和有限视差，但不能从一张画恢复任意视角、背面和真实三维透视。**只为当前可验证用途生成需要的地图。**

## 待验证的设计问题（不是已实现结论）

1. 天光 / 窗光 / 室内局部灯 / 整体调色要分开。**台灯若要真能关掉，底图须有不含该灯贡献的状态**，不能只关新增 glow。
2. 共享环境输入 → 屏幕位置的映射：天气变冷、窗光移动、局部暖灯如何同时影响房间与玻璃外壳，且 UI 文字与语义状态仍可读。
3. 图层叠加 vs 小范围 shader 的收益 / 性能 / 资源；**不把全资产迁为法线光照当作前置**。
4. 先在一件物体上验证「原画重组 + 新环境 + UI 响应」，再决定哪些写回技能、哪些留作项目配方。
5. 物件运动与动态投影消费这里的轮廓、定位点和地图，技能职责分开。

已过：技能结构检查、比较脚本 12 项自测、预览三档原画 × 晴雨六配方 × 窄屏（**纹理与当前源码函数输出逐像素一致**，无报错、390px 无横向越界）。这只证明工具与说明可用——**新资产分层、物理材质恢复、shader 接入、新环境运行时验收都还没做**，后续真实资产任务需分别报告。
