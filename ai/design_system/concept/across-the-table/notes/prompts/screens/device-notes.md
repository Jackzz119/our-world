# 跨端组交付记录

## 范围与方法

- 模式：design。范围仅 UI-pip.png、UI-widget.png、UI-devices.png。
- 已直接查看 A1-keyart.png、A2-desktop.png、A3-mobile.png；每次内置 image_gen 调用都带 A1 绝对路径，按用途叠加 A2/A3。
- 生成执行：内置 image_gen；无 CLI / API-key fallback。提示词全文与每次参考路径见 device-prompts.json。
- 每张结果均直接查看像素；初稿明显问题只做单张定向修改，保留 -initial。没有重绘整个批次，也没有改写参考源图。
- 本记录为概念产物自检及已收到的独立 QA 汇总，最终主美裁决仍由 Monet 进行。未验证桌面置顶、锁屏交互、真实天气、跨设备同步或无障碍实现。

## UI-pip.png

### 展示与对坐价值
通用文档编辑器以《周末计划》为主作业，小满的小窗位于右下角，保持暖灯、雨夜、木桌、蓝花杯、奶油针织外套、星星发夹；她手持打开的书，抬眼微笑，旁有“加油～”。底部可见观者炭灰袖、手、桌前杯。悬浮条保留“戳一下 / 语音 / 放大 / 静音”，整体与 A2 的中性磨砂玻璃一致。人物是另一位真实用户的头像状态示意，不能被实现成自主持续鼓励的 AI。

### 直接观察与弱点
- 小窗约占屏幕 27% 宽、42% 高；正文主要阅读列保留可读。尺寸仍比最紧凑驻留状态大，适合作为悬停展开状态。
- 小满完整半身和书、桌面成立，没有第二个人或强反射，没有互动光环。
- 系统栏图标为中性圈、文件夹和纸页，没有真实产品标识。
- Medium：图中“加油～”并没有可见发送来源或时间；实装必须来自 TA 主动消息或预先授权的声音名片，不能由在线状态推断意图。
- Low：静音图标为划线扬声器，同时标“静音”，当前状态与下一动作的语义仍需在真实界面统一。
- Low：截图可示意悬停展开，但静态图不能证明 hover、缩放、置顶和阅读状态触发。

### 单图修复证据
UI-pip-initial.png 原先有四窗格系统标志与过大的小窗，违反无品牌及低干扰要求。最终稿将品牌图标改为通用图形，缩小小窗并还原被遮挡的文档区域；未改源图。

### 制作拆层、动画与预算
- 层：雨夜窗景 / 暖灯背景 / 桌面 / 小满半身 rig / 书页与杯道具 / 炭灰观者袖手 / Cinnaglass 控制条与消息泡。
- 动画：读取真实阅读状态后呼吸、眨眼、轻缓翻页；收到 TA 真实消息才弹泡；悬停显示控制条。
- 绑定：发梢、眼、口、头部、持书双手分别可控，书与杯独立；控制条使用真实 DOM 字体和可访问按钮。
- 估算预算（未压缩实测）：小窗 512–768 px 背景 WebP/AVIF 100–250 KB；裁切角色图集 0.5–1.2 MB；书、杯、袖手 100–250 KB；共享 UI 图标与字体按缓存复用。小窗增量目标约 0.7–1.7 MB，不把整张桌面 PNG 当成产品运行资源。

## UI-widget.png

### 展示与对坐价值
左侧是无品牌锁屏，21:14、周五、雨窗壁纸；一块横向玻璃卡片包括小满半身对坐、名字、在听歌、雨天的星期天和戳一下。右侧是主屏，2×2 对坐天气小组件与面积约四分之一的 1×1“在一起 1221 天”卡并列。两处场景都可见木桌、双方杯子与观者炭灰袖，微型画幅仍保留对坐关系。

### 直接观察与弱点
- 金星发夹、棕发、奶油开衫与耳机、双杯、雨窗可识别；左右各只有一位小满，未画额外人物。
- 右侧 2×2 卡约 280×300 图上像素，1×1 纪念卡约 135×145；面积层级约 4:1，概念成立。与图中普通 app 占位块并非精确 OS 网格尺寸，真实系统适配另验。
- 已修复的 Medium：左“戳一下”按钮原末尾是播放三角，在歌名附近容易被当作播放；最终稿已通过内置 image_gen 定向改为小手指图标，独立 QA 确认语义歧义消除，文字与主体布局保留。
- Low：右侧八个纯色 app 占位块属于中性主屏示意，未完成真实 OS 或具体应用图标设计。
- 小组件画的是雨天状态，不能据此证明已接入实时天气。锁屏是否允许该动作、刷新频率及后台权限须按目标平台验证。
- 实际导出为 1671×941，较目标宽度少 1 px；保留工具原生输出，没有人为重采样掩盖差异。

### 单图修复证据
UI-widget-initial.png 原先右上卡片过近，读作胸像，缺少桌面和观者存在。最终稿仅将卡内镜头拉远，补上木桌、双方杯与炭灰袖，保持两手机壳、网格、文字与卡位。

UI-widget-initial-2.png 保留上述构图修正后、图标修正前的版本；最终 UI-widget.png 再把“戳一下”右端播放三角替换为小手指图标。最早 initial 未覆盖。

### 制作拆层、动画与预算
- 层：中性系统壁纸 / 对坐场景预渲染快照 / 状态文字与图标 / 戳一下动作 / 纪念日文本。操作系统 UI 不作为应用资产。
- 动画：以低频状态快照和发送回执为主；若系统不支持实时 rig，显示同一场景静态快照。天气只取有依据的共享天气状态。
- 绑定：复用场景 rig；独立裁切半身、桌面、前景杯、袖，必须预留安全裁切框。
- 估算预算（未压缩实测）：每个 384–512 px 场景快照 80–180 KB；同场景复用缓存；单次两种 widget 切图目标总计 160–360 KB，文字与纪念天数用系统布局渲染。不能把原始 PNG 体积误记为运行预算。

## UI-devices.png

### 展示与对坐价值
干净浅灰展示板中，左笔记本为完整网页场景；中间显示器的文档工作区右下角嵌入小窗；右手机为竖屏同场景。三处小满均托腮、另一手摊掌，掌上同一颗金色心；雨夜、暖灯、杯与炭灰观者袖保持一致。设备下方分别写“网页 / 桌面小窗 / 手机”。这将“同一个人的同一次心意”连接到不同使用情境。

### 直接观察与弱点
- 三端均是一名半身小满，金心与掌心位置及面部姿态基本一致；没有第三方人物或强玻璃反射。
- 网页左侧五项导航、时钟/天气、纪念日和边角聊天/音乐卡可辨；手机保留上下边缘 UI；中间明确是通用编辑器加小窗，没有画成第三个全屏场景。
- Medium：设备板上的 PIP 控件和部分中文在缩略尺度较小，适合概念沟通，不可据此判定生产环境的字号或触控目标已达标。
- 已修复的 Medium：网页播放器原为暂停按钮而手机原为播放三角；最终稿已将手机按钮定向改为暂停双竖条，进度保持 01:27，与网页显示一致。此为静态视觉一致性修正，不代表已实现播放同步。
- Low：三画幅经生成式绘制，局部头发、手掌与裁切仍有细微差别，不是同一帧像素的确定性复制。实现时应让同一事件和同一 rig 状态驱动三端，而不是三份独立动画。
- 本图仅说明同一事件的设计目标；未做任何网络延迟、去重、顺序、离线重放或多设备同步实测。心由 TA 主动触发，不能随机冒泡伪造对方动作。

### 制作拆层、动画与预算
- 层：共享雨夜背景 / 灯 / 角色 rig / 桌面杯与观者袖手 / 独立心粒子 / 各端 DOM UI。硬件展示壳只用于概念板，不随产品下发。
- 修复归档：UI-devices-initial.png 保留手机按钮修正前的完整设备板；UI-devices.png 为局部按钮修正后最终稿。
- 动画：同一个已确认的送心事件驱动抬掌、柔笑、心上浮与消散；手机可裁切但保留掌心与心的安全区，小窗可用低帧率档。
- 绑定：眼口、头发、托腮手臂、送心手臂独立；心用轻量 sprite/矢量，在本地渲染但事件由真实对方发送。
- 估算预算（未压缩实测）：共享场景首载背景 300–700 KB、角色图集 1.5–3 MB、道具前景 200–450 KB、心与特效 20–80 KB；共享首载目标约 2–4.5 MB，端间变体尽量只换裁切与 UI。概念板图片不代表该预算已实现。

## 本组三图的独立 QA
- UI-pip：独立 reviewer 逐像素复查，无 high/blocker；确认品牌图标修复、文档优先、小窗人物与袖口成立，标记静音语义为 low。
- UI-widget：独立 reviewer 逐像素复查，无 high/blocker；确认半身/桌面/双杯/炭灰袖、雨夜歌名与 1221；二次复查确认“戳一下”小手指图标已解决原 medium，主屏占位图标仍为 low。
- UI-devices：独立 reviewer 首轮逐像素复查，无 high/blocker，送心同步概念表达通过；最终复查确认手机暂停双竖条、网页暂停按钮及两端 01:27 一致，同刻金心、人物及设备构图未破坏，原 medium 已解决。
