# A「对坐」角色与互动专项 · Codex 设计报告

## 1. 模式与归一化任务

- **模式：design。** 本批深化已批准的 A「对坐 Across the Table」，交付两张角色设定页、一张十人预设板、六张双视角／互动／在场状态图，共 **9 张指定终稿**。
- 产品对象是真实伴侣和朋友的头像形象；镜头是桌前的本人，场景画面只出现对面的一个人。角色设定页／多格分镜是明确的展示例外，每个场景格独立遵守人数要求。
- 身份锚点：小满的栗色肩发、琥珀眼、左侧金星夹与细金项链；阿屿的深蓝黑乱发与细圆眼镜。阿屿视角前景穿炭灰帽衫，小满视角前景穿奶油针织。
- 美术目标：精细 2D 动漫 CG、成人半写实比例、细线、柔和赛璐璐与绘画渐变、暖实用灯和冷环境边光；角色仍是焦点。场景中不增加标题、热点圈、描边、定位针或明显人形倒影。
- 状态约束：在线、阅读、输入、暂离、本人显式睡眠分别表达。离线／暂离保留空椅与物件，不由程序冒充真人作答。
- 本次仅交付静态概念图及制作说明。**未制作分层角色、骨骼、动画、实时通信或手机版实装。** 主设计师 Monet 的最终审定尚未发生。
- 生成路径：全部使用内置 `image_gen`；每次传入 A1 和／或 A5 的绝对路径。未使用 CLI、API Key、生图脚本或手工图像拼补。请求最大横版，实际返回原生尺寸以产物清单为准，未放大伪造分辨率。
- 每张图的完整提示词、参考路径、生成源路径及修订理由保存在同目录三份 `*-generation.json` 中。

## 3. 执行结论

这套图已经把 A 的核心从“对面有一张漂亮脸”扩展成“我以自己的袖口和手参与，对方的头像承接小仪式”：贴掌、碰杯、盖毯和四种触碰均有清楚的动作对象；空椅状态同时保留温暖而不伪装在线。

**优先推进：双视角规则、阅读／输入／暂离／显式睡眠，以及碰杯小样。** 小满和阿屿两张设定页可用于沟通角色轮廓、衣装和表情范围；进入生产前仍需描定脸部结构和独立部件。贴掌与头部触碰对手指遮挡和接触位置要求更高，应作为专门动作制作。

已完成三处单张修订：小满左右转向、双视角持杯姿势、盖毯夜灯。保留的限制：一些轻微表情仍相似；预设 1、2 与主角原型接近；镜头跨画面的室内细节不是经过平面图校验的空间模型；静帧不能证明动画无穿插、交互同步或真实设备性能。

## 5. 逐图观察与制作说明

以下“观察”来自实际像素；“拆层／动画／预算”是拟议生产方法。预算统一为粗估的压缩传输量，不是当前 PNG 文件大小，也不是 GPU 内存。

### 5.1 CH-xiaoman-sheet.png

![小满角色设定](../img/CH-xiaoman-sheet.jpg)

**观察与用途。** 左列三个角度分别正面、朝画面左和朝画面右；中间是一排 8 个表情，右列 4 套半身衣装。栗发、星夹、琥珀眼、圆坠细链贯穿。家居奶油针织、咖啡馆棕衬衣、夏日浅蓝、冬日围巾明显区分，又保持同一人。它提供 A 角色换装不换身份的基准。

**弱点与修订。** 初稿两个侧转同向，并自行加入长文案，已经单张重做；初稿保留 `CH-xiaoman-sheet-initial.png`。终稿方向正确、冗余文案移除。表情细微项仍较相近，三视角实际上是正面与两个 3/4 角度，不是完整 360° 转面；裁切偏胸像，量产半身绑定还需补齐肩臂与躯干结构。

**生产。** 头部拆前／中／后发、星夹、脸、双眉、眼睑／眼白／虹膜、鼻部阴影、嘴、颈与链坠；身体按衣装切换胸肩和袖，星夹与脸一起转。先做眨眼、低幅呼吸、轻侧头和 8 套表情参数；不把 15 个人像直接剪成逐帧动作。目标：一个默认半身角色图集约 **2–4 MB**，每套额外衣装 **0.8–1.8 MB**，按需加载。

### 5.2 CH-ayu-sheet.png

![阿屿角色设定](../img/CH-ayu-sheet.jpg)

**观察与用途。** 与小满采用相同三栏设计：三方向、八表情、四衣装。深蓝黑乱发和细圆镜在所有肖像中保留；家居帽衫、衬衫毛衣、短袖、冬季大衣区分清楚。暖光与冷发缘使人设页仍属于同一 A 世界。

**弱点。** 无奈、宠溺与微笑的区分主要靠眉眼和头倾，缩略后不够鲜明；这页用于表情意图沟通，不能替代最终表情参数验收。转向图偏胸像裁切，半身绑定还需补完整肩臂与躯干。

**生产。** 眼镜的左右镜框／镜片高光与后镜腿单独分层，不能把眼睛和镜片亮斑烘成同一张；刘海要遮挡镜框而不吃掉表情。帽衫领口、抽绳与手臂分别处理。默认角色 **2–4 MB**，额外衣装 **0.8–1.8 MB／套**，同类网格可复用但脸部形变要单独校验。

### 5.3 CH-presets.png

![十种形象预设](../img/CH-presets.jpg)

**观察与用途。** 两排五列，编号 1–10 完整。可见浅、中、深肤色，直发、波浪、卷发和紧密卷曲；有圆镜、雀斑、胡须、包住头发与颈部的头巾，以及柔和、中性、偏男性的呈现。全板光向和精细 CG 处理一致，适合证明“同一个系统可以承载不同真人形象”。

**弱点。** 成人年龄只能由胡须、脸部和衣着暗示，不能从图上精确证实岁数、国籍或身份。预设 1／2 与两位主角接近；多个托腮姿势重复。年龄与脸型差异后续可继续深化。

**生产。** 这是预设范围设计，不是已完成的捏脸零件库。紧密卷发、短卷和头巾需各自轮廓与遮挡；头巾作为一组独立头部造型，不简单套在外露发丝上。先载入预设缩略图 **50–120 KB／个**，选中后再载角色 **2–4 MB／个**；不同时下载十套完整骨骼与贴图。预览灯光采用同一配方，方便比较。

### 5.4 CH-mirror.png

![互为对面](../img/CH-mirror.jpg)

**观察与用途。** 两半各只有一个对面角色；阿屿视角前景是炭灰袖和素蓝杯，小满视角前景是奶油袖和花杯。灯在两半的相反外侧，杯的归属互换，底部“阿屿看到的／小满看到的”不遮脸。它把“用户在自己屏幕看到对方”说清楚。

**修订与限度。** 初稿左边小满一手托脸，右边代表她的双手却握杯，不符合“同一时刻”；已针对左半姿势修正，初稿保留 `CH-mirror-initial.png`。窗景只是互视构图证据，尚未用统一房间平面图验证。阿屿脸上暖光与右侧灯位也存在美术化偏差，量产时需统一光向。

**生产。** 一个共享桌面状态配两个观看机位；角色和自己的前景手各一层，两只杯都有稳定归属与桌面位置。轻呼吸、杯蒸汽、眨眼独立。角色默认图集复用，前景手／杯增量约 **0.3–0.7 MB／视角**；背景约 **0.4–0.9 MB／视角**。

**家庭桌面循环（拟议）。** 双方真实进入 → 各自以本人袖口坐下 → 看见对方的当前动作 → 物件变动同步到另一视角 → 双方选择时才存共同瞬间。独处时对面为空椅。

### 5.5 CH-palm.png

![掌心相贴](../img/CH-palm.jpg)

**观察与用途。** 炭灰袖从前景进入，小满奶油袖从对侧进入；掌面在桌中段竖直贴合，小满闭眼柔笑。暖光局限在接触处，脸保持清楚，没有环形提示。小幅度动作即可形成强烈的两人联系。

**弱点。** 指部高度重叠，掌边可辨、腕部来源可追踪，但被遮挡的指关节不能从静帧证明正确。这也是本批最需要人工手部制作的一张。

**生产。** 背景、桌与杯、身体、交互两臂／两掌、发丝、接触光独立。固定双方掌心的接触锚点；接触光只在事件到达后短暂出现，不能长期发亮。复用角色外，手和光增量 **0.3–0.7 MB**；共享背景 **0.4–0.9 MB**。

**互动循环（拟议）。** 双方在线并接受邀请 → 两只手靠近 → 掌心贴合 → 暖光和约定表情回应 → 可选记录共同瞬间。离线只留下邀请，不自动演出双人回应。

### 5.6 CH-cheers.png

![咖啡馆碰杯](../img/CH-cheers.jpg)

**观察与用途。** 阿屿坐在对面笑，细圆镜与黑发清晰；前景拿杯的是小满奶油袖。两只杯上缘相碰，接触位置有小闪点和少量可可滴。青绿卡座、咖啡设备、街边雨窗、吊灯构成独立咖啡馆，区别于家庭书桌。观众脸本来就在镜头外，所以“双人开心”由阿屿笑容和观众举杯动作表达。

**弱点。** 杯子占前景较大；横版能保住脸，手机不能直接中心裁切整个构图。可可滴应是很短的反馈，不形成持续飞溅。

**生产。** 咖啡馆背景、阿屿主体、眼镜与表情、双方前臂／手／杯、杯内液面、可可滴、接触闪点分别处理。杯口和液面需不同遮罩；两杯不相互穿透。背景 **0.4–0.9 MB**，阿屿图集 **2–4 MB**，手／杯／粒子增量 **0.4–0.9 MB**。

**咖啡馆循环（拟议）。** 选择／留下饮品 → 发起举杯 → 对方真实参与碰杯 → 双杯触碰并短暂笑／飞滴 → 可选保存饮品纪念。异步状态把饮品留在对方桌上，等回来领取。

### 5.7 CH-blanket.png

![盖毯子](../img/CH-blanket.jpg)

**观察与用途。** 小满闭眼趴在自己的交叠前臂上，星夹和项链仍在。两只炭灰袖前景手分别抓住毯角，毯子盖在肩背，脸不被挡；灰褐毯与奶油衣有区分，小“晚安”语音片在脸侧留白处。关怀通过物件留存表达，适合异步关系。

**修订与限度。** 初稿灯罩过亮，已单独降低台灯输出并保持人物暖肤色，初稿保留 `CH-blanket-initial.png`。制作子代理还记录了固定 ROI 的非线性 sRGB 加权通道采样：灯罩 215.22→106.56，脸部 140.53→131.59；它辅助确认局部减亮，不是物理光强或感知亮度测量。图中的笑容是显式睡眠状态的姿态设计，不是“对方睡着时收到了操作并实时回复”的证据。

**生产。** 使用睡姿专用躯干与折叠前臂，不强弯正常坐姿骨骼。毯后片、前缘、双抓握手、人物发丝与脸分别遮挡；微弱呼吸、毯起伏、雨分开。语音片用真实 UI 文本和实际录音，不能伪造语音内容。背景 **0.4–0.9 MB**，睡姿角色 **2–3 MB**，毯／双手 **0.5–1 MB**。

**互动循环（拟议）。** 本人显式设为睡眠 → 对方拖起毯子 → 双手盖到肩背 → 毯和真实晚安留言留存 → 醒来查看。未在线时保留物件／消息，不合成真人回应。

### 5.8 CH-touches.png

![四种轻互动](../img/CH-touches.jpg)

**观察与用途。** 四格分别是摸头、别星夹、喂饼干、猜拳；所有观众袖口都是炭灰。摸头闭眼笑、别夹脸红、饼干接到嘴边、猜拳欢呼均可读。右下小满明确张开五指出布，观众是石头，所以“她赢”由动作本身表达，没有分数或排行。短字幕落在分隔条中。

**弱点。** 四格展示动作关键瞬间，不展示开始、返回或被打断时的安全路径；投喂图画的是饼干入口接触瞬间，没有可确认的咬缺结果，嘴部遮挡与咬痕需要单独制作。头部触碰不能通过任意拉伸前景手实现。

**生产。** 四套独立手势／腕部绑定；星夹有明确固定位置；饼干完整／咬缺状态分开；猜拳需要双方实际选项后揭示，不默认小满总赢。复用主角色、背景后，四套手势道具图集约 **0.7–1.4 MB**；表情由角色图集复用。

**互动循环（拟议）。** 选择轻互动并发出 → 真人在线参与或接受预设互动 → 手与目标接触 → 对侧出现约定动作／道具变化 → 可选留存。异步时留下饼干／邀请，不把已离线的人画成正在配合。

### 5.9 CH-presence.png

![四种在场状态](../img/CH-presence.jpg)

**观察与用途。** 四格固定桌面：小满持书抬眼；看手机输入并带省略点；空椅挂奶油衣、桌上花杯与“马上回来”；趴睡并有猫在后方蜷卧，睡格灯较暗。观众炭灰袖与杯贯穿，角色消失时“自己仍坐在这里”也成立。暂离格没有人影／假替身。

**弱点。** 傍晚画成偏深蓝的晚间光感，而非更柔亮的傍晚；暂离格花杯从左侧移到中央，生产切状态必须保持杯锚点固定。暂离杯口蒸汽细，缩小时辨识弱。四格不能证明真实状态后端、延迟和跨端同步已经存在。

**生产。** 四格共享房间底图，不各下载一张整幅成片；书／手机／空椅上的外套／便条／趴睡姿态／猫是可切换部件。输入点在真实输入事件结束后消退；便条必须是本人留下的内容，不能默认替他许诺“马上回来”。阅读状态只表示明确选择的活动，不监测用户其他应用。背景 **0.4–0.9 MB**，一个主角色 **2–4 MB**，睡姿增量 **1–2 MB**，书／手机／衣／猫／纸条合计增量约 **0.5–1.2 MB**。

**状态循环（拟议）。** 本人活动或显式状态变化 → 同步真实状态 → 对侧切换相应姿态或空椅 → 允许留下物件／留言 → 回来查看未读心意。真正离线也应为空椅；“睡着了”不由连接断开或算法猜测触发。

### 共用制作边界

- 图像交付是合成 PNG，没有透明部件、PSD、法线图或可重光照资产。灯光目前烘焙在图中；正式角色要重新拆清材质与受光，避免简单全局染色破坏皮肤与针织纹理。
- 半身角色优先保留发、脸、眼镜／发夹、颈、胸肩、两臂和手的可控关系。背部与被杯遮挡区域需要补画，不能假设生成图里存在。
- 预算是以一名半身角色、按需动作包和单个可见房间估算的传输目标，不含音频、程序和字体。共享项不可逐图重复相加；实际数值需在分层及压缩后测量。
- 传输量不是显存：一张 2048×2048 RGBA8 原始贴图约 16 MiB，一张 4096×4096 约 64 MiB（不含 mipmap 等额外开销）。因此换装与动作包需按需加载，不能用整板十张人物常驻。
- 手机竖版需要重新安排头部、手与互动中心；本批未提供手机竖屏图片、响应式实现或真机测试。静态像素检查也不证明帧率、触控命中和可访问性。

## 6. 不确定性与可比性限制

1. A1 是单人横版原画，A5 是带编辑器的近景，A4 是多人聚会，A3 是双手机展示。它们不是同内容同视口的候选，未做虚假的横向数值排名。
2. 本批的设定页、分镜和英雄图任务不同，采用“是否完成指定内容”的矩阵，不给没有测量依据的百分制。
3. 角色关键特征保持连续，但不声称每张脸是同一个精确网格或逐像素一致。手部遮挡后结构、镜片厚度、关节活动范围需要生产资产验证。
4. 睡眠是 brief 明确设定；从一个闭眼图像本身无法判断真人是否在睡眠。在线与输入也需要真实事件驱动。
5. 全部图像为原创生成意图，未调用已有 IP 名称或在世艺术家／工作室名字；没有做全网角色相似性穷尽检索。
6. 内置工具没有在本轮暴露独立尺寸参数；提示词请求最大横版，实得原生 1672×941。没有为了标称 4K 进行插值放大。
7. 新产物只在本批目录；未修改现役设计规范、程序、源参考图或协议文件。工作区技能保底脚本 `--dry-run` 返回退出码 1 且没有错误文本，已直接确认技能可读并完成规定上下文读取，没有因此修改协议。
