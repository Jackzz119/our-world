## 为什么是对坐

![三个方向的主视觉：对坐、并肩、灯火小楼](sheets/direction-overview.jpg)

2026-09-25 比较了三种镜头关系：**对坐**（镜头就是你，对面一个人看着你）、**并肩**（镜头在两人身后，一起看风景）、**灯火小楼**（一栋楼里每扇亮着的窗是一个人）。用户选了对坐，理由是符合产品定位、更突出和对方的交互、可以把角色想象成对方、适合手机电脑互通。并肩的活窗景并进对坐的窗外，灯火小楼的「亮着的窗」做大厅。比较过程与落选方向的图在 [方向比稿档案](../../../../arts/archive/v3-direction-proposals/scene-concepts.md)。

![十个房间](sheets/sheet-rooms-overview.jpg)

## 这一版定下来的结构（2026-09-27 用户确认）

- **镜头就是你**：画面里只有对面那个人，你出现在前景的手、袖口和杯子里。你是阿屿时看到小满和自己的炭灰卫衣袖口；你是小满时看到阿屿和自己的奶油色针织袖口。
- **对面是真人**：角色的每个主动动作都来自对方的真实状态，或 TA 亲手留下的东西（录音、便条、送来的咖啡）。人不在就是空椅留痕，不装作在。
- **房间 = 一个功能 + 一个小游戏**：十个房间各对应一个现有或规划中的功能。玩法都是「动手 → 对面有回应 → 结果留在对方那边 → 变成回忆」，对方不在线也能玩，只加不减。
- **光和天气是场景的状态**：同一张桌子、同一套分层，只换光和天气，不重画房间。
- **动作来自一份动作表**：同一套半身 rig 的 9 个基础动作（姿势库），每个动作对应一种真实状态。

## 同一张桌子：时辰与天气

![同一张桌子的十种光与天气](sheets/sheet-lighting.jpg)

同一机位、同一家具、同一个人，只换光和天气：清晨、阴天午后、黄昏金光、蓝调时刻、雷雨夜（闪电瞬间）、雪夜、春日樱花、夏夜萤火、秋日午后、停电烛光。它证明一套场景分层加上每种状态的一组光层和天气层就够用，不必每种天气重画房间（Codex 估算每种状态增量 0.7–2.6 MB，未实测）。雷雨的闪电要给减弱和关闭选项。

## 每个房间也有自己的时辰和天气

![姿势库与房间的时辰天气变体](sheets/sheet-variants.jpg)

咖啡馆的晴朗早晨与打烊前、温室的雨天与夜晚、书房通宵后的清晨、海边的暴风雨前与星夜、列车的清晨海岸线、天台的夏日阵雨、木屋的雪后晴天、暗房的开灯整理。房间布局和道具保持不变，只换光、天气、衣服和动作。海边小屋一共有三种状态（日出、暴风雨前、星夜），可以直接当作一个房间的一整天来看。

## 产品界面

![产品界面九张](sheets/sheet-screens.jpg)

UI Tailor 定的概念模型：**大厅**是所有空间的总览，每扇亮着的窗是一个人或一群人；进去就是和 TA 对坐。**房间**是今天坐在哪里，两个人看到同一个房间，换房间会同时带上 TA。**入座**是配对和加入。

| 界面         | 看点                                                                                                         |
| ------------ | ------------------------------------------------------------------------------------------------------------ |
| 大厅         | 一栋雨夜小楼：小满的窗亮着（悬停卡片「小满 · 在听歌 · 进入」），周末桌游的窗里三个朋友，室友们的窗暗着只剩猫 |
| 房间选择     | 场景虚化，底部十张房间卡，选中温室显示「一起养一盆花」，按钮「一起去」                                       |
| 桌面置顶小窗 | 你在写文档，右下角她在看书，冒一句「加油～」；控件：戳一下、语音、放大、静音                                 |
| 锁屏与小组件 | 锁屏上「小满 · 在听歌」和戳一下按钮；桌面小组件是她在当前真实天气里的桌子和在一起天数                        |
| 三端互通     | 她送出一颗心，网页、桌面小窗、手机同时出现                                                                   |
| 邀请入座     | 第一次打开：空椅子前摆好第二个杯子；TA 接受后坐下挥手，「TA 来了」                                           |

| 声音名片     | 录早安、戳我干嘛、想你了、晚安；录音时自己的形象跟着对口型                                                   |
| 完整聊天     | 手机竖屏，上半是她读到你消息时的样子，下半是消息、语音和贴纸                                                 |

## Monet 审图

**成立的部分**

- 「对面是真人」有了完整证据链：互为对面、在场四态、邀请入座、桌面小窗、三端互通，从第一次打开到日常挂着都讲通了。
- 十个房间是十个真正不同的地方，各有自己的光：暗房的红灯、唱片角的霓虹、木屋的炉火、温室的光束，不是一套公寓换颜色。
- 光影组和变体组证明了「同一场景、多种状态」的做法，这正是动态壁纸级效果能在网页上保持轻量的前提。

**需要在正式制作里改的**

1. **托腮用得太多**：第一波里很多张都是托腮捧杯，房间选择卡片更是全部托腮。姿势库和变体批已经修正；正式制作规定每个房间至少用 3 种动作，托腮只是其中一种。
2. **构图几乎一样**：所有房间都是对方居中、你的手在下方。好处是 rig 和界面布局通用，代价是房间之间主要靠环境区分；建议列车（靠窗斜坐）、天台（低桌）这类房间做斜向座位增加变化。
3. **图里的中文会错字**：「戳」「捂」都出现过错字。正式界面全部用真实字体，概念图里的字只作示意。
4. **房间卡片应该从主视觉裁切**：现在的卡片是另画的，唱片角还画成了唱机。
5. **窗外城市需要原创**：多张图用的是同一种通用天际线，正式美术要画我们自己的城市。
6. **这仍是静态概念图**：没有分层文件、rig 和动画，下表体积都是 Codex 的估算。

| 资源             | Codex 估算（压缩下载，未实测）  |
| ---------------- | ------------------------------- |
| 单个房间首次进入 | 4–12 MB                         |
| 一个半身角色图集 | 2–4 MB，每套衣服另加 0.8–1.8 MB |
| 每种光与天气状态 | 另加 0.7–2.6 MB                 |
| 单个物件玩法     | 另加 0.2–2.4 MB（猫最贵）       |
| 形象预设缩略图   | 每个 50–120 KB                  |

下载体积不等于显存：一张 2048×2048 的透明贴图解码后约 16 MiB，所以房间、衣服和状态都要按需加载，不能常驻。

## 建议的下一步

1. **先做一个能跑的切片**：家里雨夜的桌子 + 在场四态 + 戳一下（播放声音名片）+ 台灯拉绳（真实光层）。用双账号验证「对面是真人」的感觉，同时实测网页和手机的帧率与包体。
2. **首批房间按已有功能挑**：唱片角（音乐）、暗房（照片墙）、书房（日记）；温室作为第一个新玩法。
3. **角色定稿**：做一轮我们自己的角色设计（五官、发型轮廓、比例），再出 rig 用的分件图。
4. **写进设计系统**（2026-09-27 已完成）：角色、场景、物件、效果规则已写进领域文档；大厅、房间选择、入座、声音名片等界面流程等书房之后细化，再由 UI Tailor 写进 uiux。

## 用户的决定（2026-09-27）

1. **结构认可**，首批房间按已有功能：唱片角、暗房、书房，温室作第一个新玩法。唱片角的「落针一起听」先放进书房：桌上的唱片机就是音乐入口（交由 Monet 决定）。
2. **互动边界认可**：摸头、投喂随时能做、对方之后看到；掌心相贴、碰杯、猜拳必须两人同时在线；盖毯子要对方主动设为「睡着了」。
3. **第一期先做书房**：翻新现有书房，完成男女角色的场景、基本动作和个别物件交互，手机与电脑布局同步开发。先做她的视角（对面是阿屿）。用户最喜欢的动作：摸头、酣睡，以及和对方当前操作绑定的倒一杯咖啡、TA 在输入时低头写字。
