沉浸感 · 明度层级比稿

诊断「场景亮 + UI 更亮 = 没有前后关系」· 三方案 × 日间/夜晚双场景 · 记忆内容卡为主角
① 诊断：明度阶梯错了

沉浸 = 外框沉下去，内容浮上来

行业共识（Spotify / Netflix / Apple Photos / Day One）：暗的外框让内容成为主角——影院、博物馆都是这个原理。暗背景上照片和文字会显得更鲜活，界面「退到幕后」。当前问题不是白色本身，而是明度阶梯：UI 比场景还亮，两者互抢，画面变成一张「过曝的白纸」。

✕ 现状：UI 最亮，压过记忆

UI 壳 96% 内容纸 100% 场景 82%
三层挤在高明度区，差值 <20%。眼睛找不到主角，画面「平」且刺眼——沉浸感消失的根因。

✓ 目标：壳最暗 → 场景中 → 内容最亮

UI 壳 26% 场景 62% 内容纸 100%
阶梯拉开 >35%：外框沉进暮色，场景成为「房间」，白色的记忆卡片像放在暗室里的照片一样跳出来。
大耳狗怎么办？——它本来就有夜晚形象：躺在弯月上、抱着小熊、睡在星空里。大耳狗 ≠ 只能白底，它的灵魂是「柔软的天蓝 + 腮红粉 + 圆形」。把天蓝从「背景色」升级为「发光的点缀色」，深蓝夜空当底，反而更像它的星空插画。

同组件 · 日间明亮房间 vs 夜晚房间

组件：悬浮胶囊 rail + sidebar + 记忆卡弹窗（照片 + 文字 = 本产品真正的主角）。观察点：眼睛第一眼落在哪里？UI 是「框」还是「墙」？

③ 场景侧的两个开关

不只改 UI —— 场景也要学会「让位」

a. 暗角 vignette：场景四周压暗，中心保持明亮 —— 眼睛自动看向房间中央的你们俩。博物馆打光法则。
b. UI 侧局部压暗：sidebar/弹窗背后横向渐变压暗一条，玻璃壳身后不再是刺眼高光，浮起感立刻成立。
c. 记忆卡打开时全局降噪：打开时间线/照片时，场景整体亮度 ×0.8 —— 「进入回忆」的仪式感（现有 modal-scrim 已有雏形，加大即可）。
这三个开关对 A/B/C 任一方案都适用，本比稿里 B/C 已开启，A 保持关闭作对照。
④ 裁决点

待拍板

1. 明度方向：A 维持现状 / B 薄暮纱（保守，改 token + 场景滤镜）/ C 星夜书房（UX 推荐，沉浸最强）
2. 是否随光照自动切换：黄昏/夜晚走 C 的夜蓝壳，正午/晴天走 B 的雾蓝壳 —— 「UI 明度永远比场景低一档」的动态规则（已有 data-mood 基建，纯 CSS 可实现）
3. 场景三开关：暗角 / UI 侧压暗 / 打开记忆时全局降噪 —— 建议全开
