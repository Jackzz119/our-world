# 棕皮旧纸日记 · 竖直翻页实装

2026-09-07。保持已批准的书本美术、导航、纸色与排版。本轮把真实内容接到竖起的纸面上，不恢复已经否决的旧平面翻折引擎。仅本地实施，未部署、未提交。

## 2. 决策：用真实网页内容做三维纸面，不用自定义 shader

shader 是控制显卡绘制的程序。它适合复杂曲面，但需要先把网页正文、字体、图片转换成贴图，并处理贴图更新、签名图片跨域与清晰度。本轮不增加这条绘制链：直接把已经排好的书页复制到同一张纸的正反两面，再将纸分为 24 条相接的窄片，在三维空间一起转动。

每条窄片包含对应的纸纹、日期、文字和照片；它们不是独立淡出。窄片角度连续变化，形成浅弯曲，书脊固定不动，纸面总长度不变。底层由浏览器合成器绘制，**没有自定义 WebGL shader，也不是视频贴图播放**。静止后移除所有动画副本，恢复可选择、可复制、可点详情的原始书页。

三维层级保持 `preserve-3d`（子层保留前后深度）；只在平面的纸面内容上裁剪和混色，不能在三维父层加透明度、滤镜或裁剪，否则会压平深度。背面采用 `backface-visibility: hidden`，只显示朝向读者的那一面。依据：[MDN 三维层级与压平条件](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/transform-style)、[MDN 正反面可见性](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Properties/backface-visibility)。

### 正反面与底下的内容

以正读第 1、2 页，向后翻到第 3、4 页为例：

| 位置 | 内容与行为 |
| --- | --- |
| 移动纸的正面 | 第 2 页；照片和正文保留到正面转离视线，不提前撤掉 |
| 同一纸的背面 | 第 3 页；经过竖直位置后逐渐朝向读者，不把第 2 页的字镜像印在背面 |
| 底下右页 | 第 4 页；上面纸页移开多少，就显露多少，不等落地才换图 |
| 底下左页 | 第 1 页；逐渐被落下来的第 3 页盖住 |

反向翻阅按相反顺序处理。窄屏延续现有单页模式，书脊在左侧，翻出去的部分自然离开视口；没有为了显示双页把字号缩小。

## 3. 时值与输入规则

- 单张 980 毫秒，起落放缓，中段通过竖直位置。实体翻书是本功能的有意例外，不套普通弹窗 ≤500 毫秒的限制。
- 连续点击或目录跨页：每张 470 毫秒，上张行程达到 38% 时可接下一张，同时最多 3 张。改变速度时保留已经转到的位置，不从头播放。
- 左右页按钮和键盘方向键都累加目标；目录跳转也是逐张翻过已加载内容。中途反向会先收好已经出发的纸，再向新目标翻，不瞬间把纸扭回去。
- 关闭、调整窗口或打开写作时，落到最接近的一组书页并清空后续队列；保留对应正文阅读位置。没有把半张翻页留在屏幕上。
- 输入框、写作区和目录内的方向键不触发翻页；动画副本不能获取焦点、不能打开重复详情。读屏使用原书页与页码播报，不重复读 24 份副本。
- 系统选择“减少动态效果”，或浏览器不支持三维层级时，直接换到目标；切到后台时收好动画。停止翻阅后不保留翻页专属的逐帧循环。房间本身按原有 30 帧上限继续播放，打开日记不再暂停雨景。

## 4. 加载与连续翻阅：不伪造历史

当前后端一次返回 20 条回忆，前端根据实际内容排成书页。目录只列已载入的日期，页数也只代表已载入内容。所有已经加载的中间页仍是清晰真字、真照片，**本轮没有启用模糊文字降级**。

没有从数据库取到的历史不能算成真实页码，更不能当成写满假字的纸。更早的回忆继续由目录里的“载入更早的回忆”获取；成功后重新排页，让原来读到的段落仍在当前跨页中，随后可以继续翻。失败保留原内容，按钮可再次尝试。当前不自动预取整个历史，也不提供跳到尚未载入日期的假目录。

缩略图沿用既有签名机制。网址续签时同时更新原书页与空中书页的图片，未签名的图片保留“照片加载中”，不编造照片；详情仍使用原来的原图链路。没有修改 `useFeed`、`posts.ts`、`storage.ts` 或数据库。

### 实测与纠正

- 实际连续三张测试曾测得中位帧间隔 13.9ms，95% 帧间隔不超过 34.6ms，总翻阅约 0.85 秒；这只是当前电脑的无头 Chrome 样例，不承诺所有设备稳定 60 帧。
- 图片网址刷新测试同时覆盖原页与动画副本，全部切换到新网址；历史请求模拟失败保留原页，重试成功后原阅读段落仍在可见跨页中。
- 逐帧审查纠正了纸片接缝和竖直位置的阴影：窄片边缘轻微重叠消除漏缝，阴影宽度先收窄再围绕书脊定位，不再错误地跳到左页边缘。
- 四尺寸回归发现背景唱片在缩放后抛出 `BindGroup.setResource` 空值异常。通过已安装 Pixi 8.19.0 源码核实：网格虽然换了新贴图，共享绘制资源要到下一帧才换绑；旧贴图立即销毁会一并销毁仍在使用的绑定组。现在等下一次绘制完成才释放旧贴图；场景退出也清理队列。没有修改库代码、唱片素材或旋转参数。
- 修改的日记模块 ESLint 检查通过；Vite 前端生产打包通过，有既有大包提示。完整类型构建仍有下方 `Msg` 错误，不能标为全项目构建通过。
- 最终动画检查与四尺寸/三时辰静态回归均未捕获页面脚本异常。长文和九图保序、选择十图保留九图、Esc 保草稿、取消清空、详情开关通过；设计系统已核对实际翻页样式与两张实景 GIF 均可加载。静态原始结果见 [book-verification/results.json](book-verification/results.json)。
- 工作区有其他任务的改动与 Windows 换行，原始 `git diff --check` 会将大量 CRLF 行尾报为空白；不为本轮大范围改写无关文件。按 CRLF 合法的方式检查差异，日记新模块另做格式检查。

## 6. 已知边界

这是有浅弯曲的三维纸片近似，不是布料物理模拟；局部纸边仍来自同一张旧纸底图，未制作新的厚度模型。没有新增鼠标拖页角、音效、羽毛笔交互、拿起/收回开场，也未改变其他功能弹窗的材质。

当前性能测量来自这台电脑的无头 Chrome，不能推断 Safari 或低端手机帧率。真实花园、低端设备、系统 125%/150% 显示缩放、低带宽端点照片完整呈现、双账号发布仍未覆盖；没有向共享数据库发布测试内容。

完整类型构建仍受原有 `shell/chat-card.tsx` 的 `Msg` 导入错误阻断。局部检查与前端打包结果会单独记录，不能用局部成功冒充全项目构建通过。
