## 0. 产品分层：场景伴生与内容页（2026-10-01 用户定，贯穿以后的开发）

用户原话的意思：音乐、聊天、房间切换、回忆入口这些是**场景伴生**功能，陪着你待在房间里，可以半开；日记和照片墙从回忆入口点开，代表要**进入非场景伴生的内容页面**——是来看内容的，所以手机上直接展开、桌面正中弹窗，不缩在一边。回忆是产品的另一大特点，入口不该是扳手。

| 层                | 现在有谁                                               | 桌面                                   | 手机                                                             | 场景                       |
| ----------------- | ------------------------------------------------------ | -------------------------------------- | ---------------------------------------------------------------- | -------------------------- |
| **场景伴生**（A） | 房间、聊天、一起听、回忆入口（菜单）、时辰 / 天气      | 贴边浮窗、右侧停靠栏、导航弹出的小菜单 | 底部托盘，可半开 / 拉满；导航展开成托盘的标签栏；关闭按钮 + 下拉 | 不暂停，TA 完整可见        |
| **内容页**        | 日记、照片墙（回忆的内容）；以后要「进去看」的都归这里 | 屏幕正中的大窗，房间压暗、虚化         | 直接全屏，从底边升起，没有半开；页头关闭按钮 + 下拉关闭          | 压暗退后，关掉内容页再回来 |
| **任务窗**（B）   | 设置、日历·纪念日、时钟、心愿单、完整聊天              | 正中小窗                               | 从底边升起、顶部圆角（2026-09-30 用户保留）                      | 压暗                       |

- **手机一次只开一个窗口**：开任何托盘、内容页或任务窗，别的自动收起，不叠在一起。桌面上伴生浮窗可以同时开（聊天卡 + 停靠栏），内容页和任务窗盖在它们上面。
- **关闭永远有按钮**：拖动、下拉、Esc 都是快捷方式，不是唯一的路。
- 新功能先问「它是陪着你，还是你要进去看」，再选载体。

## 总原则

- **任何交互都有反馈**（用户：这是游戏 app，不必过分克制）：按下缩、放开弹、悬停亮、成功有小庆祝、失败轻摇；低动效模式兜底。
- **TA 优先**（场景伴生的功能）：手机上从底部升起，只盖住我这边（手和杯子），对面的人完整可见；桌面上贴边或停靠在右侧一列，不挡对方的脸。内容页是例外：进去看内容时房间压暗退后（§0）。
- **退场快于进场，动作可打断**：弹层从触发它的地方长出来；拖动跟手，甩一下就走；中途反向不跳帧。
- **低动效**：设置 → 主题外观 → 动效（跟随系统 / 完整动效 / 低动效）。位移、缩放、回弹归零，只留淡入淡出；循环和粒子关掉；房间的视差、微动、蒸汽停止。

**弹簧按苹果的模型**（2026-10-02 用户要求参考苹果设计师的弹簧曲线；WWDC23「Animate with springs」）：一根弹簧只由「感觉多长」（duration）和「回弹多少」（bounce）定，质量 1、刚度 (2π / duration)²、阻尼比 1 − bounce。CSS 曲线是这些弹簧采样出的 `linear()`，时长取弹簧真正停稳的时刻，由 [spring-curves.mjs](../../../../../scripts/spring-curves.mjs) 从 [spring.ts](../../../../../src/themes/cinnaglass/ui/spring.ts) 生成，改弹簧改那里。

| 名称                                 | 弹簧（感觉 · bounce）                                           | 停稳   | 回弹  | 用在哪                                     |
| ------------------------------------ | --------------------------------------------------------------- | ------ | ----- | ------------------------------------------ |
| `--spring-smooth`（`--ease-drawer`） | 0.42s · 0                                                       | 621ms  | 0     | 托盘、手机内容页升起                       |
| `--spring-snappy`（`--ease-spring`） | 0.36s · 0.15                                                    | 504ms  | 0.6%  | 面板、弹窗、卡片、列表逐项、唱片滑出       |
| `--spring-bouncy`（`--ease-toggle`） | 0.42s · 0.3                                                     | 692ms  | 4.6%  | 标签滑块、回忆页的样子切换                 |
| `--spring-pop`（`--ease-pop`）       | 0.34s · 0.42                                                    | 667ms  | 10.7% | 放开按钮、开关圆钮、小红点、印章、拍立得   |
| release / fling / away（JS）         | 0.38 · 0.12 / 0.34 · 0.22 / 0.32 · 0                            | 随速度 | —     | 拖完松手 / 甩出去（> 0.5 px/ms）/ 往下收起 |
| `--ease-out`                         | `cubic-bezier(0.23, 1, 0.32, 1)`                                |        |       | 进场、退场、按下                           |
| 其它时长（ms）                       | 按下 90 · 悬停 160 · 进场 260 · 退场 150 · 托盘收起 280         |        |       |                                            |
| 幅度                                 | 按压 0.95（大块 0.97）· 悬停上浮 1px · 进场位移 10px、缩放 0.96 |        |       |                                            |

- **拖动**（WWDC18「Designing Fluid Interfaces」）：移动 6px 才算拖，之前按下还是按下；之后 1:1 跟手；过了边缘是 iOS 滚动视图的橡皮筋 `(x · d · 0.55) / (d + 0.55 · x)`（d 是被拖的东西的高度）；放手按减速率 0.998 推算落点（`v · 0.998 / 0.002`，v 取最后 100ms 的速度），停在离落点最近的位置，弹簧从手指的速度起步；半路再按住会停在手指下。低动效时不用弹簧，直接到位。

## 1. 手机托盘 · 定稿（2026-10-01 改：关闭按钮、一次一个；10-03 改：往上推展开；托盘打开时的导航第二轮比稿中）

2026-09-30 用户：从下面升起的模式很喜欢，保留。2026-10-01 用户：导航单独叠在托盘上很不自然，要融进窗口；只能拖着关有时很麻烦，要有关闭按钮；手机上不该同时开好几个窗口。2026-10-02 用户：导航只是去掉背景还不够，没背景的图标大部分时候看起来还不是弹出框的一部分，仍有第三层的感觉，要重新设计。场景伴生的音乐、聊天、房间、回忆入口都用同一个托盘（[sheet.tsx](../../../../../src/themes/cinnaglass/ui/sheet.tsx)），日记和照片墙不再用托盘（见 §4）。

> **10-03：坞被否决**（用户：导航在托盘弹出后样子变了、按钮位置也变了，打断体验的连续；真机上还挡住了半开的托盘）。线上暂时还是坞（下面「坞」的几条描述的是它），第二轮比稿——A 浮在导航上方（推荐）/ B 插在导航后面 / C 凹槽托住，导航都保持平时的胶囊——在 [比稿区](../../../codex-visual/nav-dock/nav-dock.md) 和 [看样页 N 节](index.html#nav2-title)，用户选定后替换。

- **流程**：点导航图标 → **导航展开成托盘的标签栏（坞）**，托盘从标签栏后面升到半高（可见高度的一半，至少 340px）→ **从托盘任何地方拖**（2026-10-02 起；按钮和卡片点一下照旧，拖完松手不会误点；输入框和滑杆不拖；拉满时能滚的列表自己滚）：上推到全高、下拉收起，放手按推算的落点停在拉满 / 半开 / 收起 → **右上角的关闭按钮**、再点同一个图标、Esc 或往下甩都能收起，托盘沉回标签栏里，标签栏再收回胶囊，焦点回到入口。点标签栏上别的图标：这个托盘沉下、那个升起，标签栏不收回。
- **往上推展开**（10-03 用户：聊天框往上拉不会展开，一定要按展开）：聊天托盘只有一个高度，它的「全高」就是完整聊天。往上推过顶 36px，或往上甩快于 0.3 px/ms，和右上角「展开完整聊天」一样：托盘停在原处淡出，完整聊天从底边升起（`Sheet` 的 `onPullUp`）；轻推一下会弹回来。**托盘里的列表**照常滚动，滚到头再往同一个方向拖就是在拖托盘（iOS 托盘的做法）：聊天记录在最新一条时往上推＝展开，列表在顶上时往下拉＝收托盘。
- **坞（标签栏）长什么样**（10-02 实装，10-03 否决）（[navigation-glass.css](../../../../../src/themes/cinnaglass/shell/navigation-glass.css)）：贴着屏幕底边、整屏宽、高 64px（另加底部安全区）；底色是托盘的玻璃（`--ui-base`，比托盘略实，不透明度 `0.78 + --ui-boost`，托盘里的内容从它后面经过时被挡住），顶上一道和面板里一样的细分隔线 `--ui-line`；五个图标平分宽度、25px，下面写名字（10.5px）；平时是托盘的次要字色，当前这个用金色 `--ui-accent` 并在图标后垫一块金色小圆角底（金色 16%，按下 26%）；未读红点和音柱挪到图标的右上 / 右下。三种界面风格都跟着变（暖瓷是浅色标签栏、深金字）。
- **为什么是坞**：10-01 的版本只把胶囊底去掉，图标还留着自己的发光底、投影和浮在半空的位置，托盘的内容上下滑时从图标底下穿过——读起来是托盘、导航、场景三层。标签栏占满宽、贴底、用托盘的墨色和字号、写着名字，和手机应用底部的标签栏是同一种读法：它就是这块面板的底边，托盘从它后面出来。没选：①只把图标染成托盘的墨色（仍是浮着的一排，第三层还在）；②托盘打开时把导航整个藏起来（失去一键换到另一个托盘的捷径，「一次一个」要多点一下）。三个方向的实景对比在 [比稿区](../../../codex-visual/nav-dock/nav-dock.md)。
- **一次一个**：开另一个托盘、内容页、任务窗或时辰 / 天气面板，正开着的托盘自己收起（[WorldPage.tsx](../../../../../src/pages/WorldPage.tsx) `others()`）。
- **回忆入口**：导航第四个图标从扳手换成「回忆」（两张叠着的拍立得，前面一张有颗心）；托盘里是三张卡：日记 / 照片墙 / 纪念日。原来工具里属于房间的东西（装扮、纪念日卡和音乐迷你条的开关、回大厅）挪到「房间」里。「回忆」二字用日记的手写体。
- **状态**：半高、全高、拖动中（过顶是橡皮筋，越拉越紧）、回弹中（可以再按住）、收起中；托盘打开时我这边的桌面轻轻压暗，对方保持明亮；键盘弹起时托盘骑在键盘上（导航藏起）。标签栏只在竖屏手机上出现：横屏时托盘是右侧一列，导航仍是自己的胶囊；鼠标悬停才出的名字在手机上不画。
- **动效**：升起 `--spring-smooth`（621ms，不回弹），收起 280ms `--ease-out`；拖完松手走 JS 弹簧：停在拉满或半开用 release（0.38s · 0.12），甩得快（> 0.5 px/ms）用 fling（0.34s · 0.22），收起用 away（0.32s · 0）；低动效改为原地淡入淡出。2026-10-02 用户说往上拖托盘发沉、拖不动：原因是只有手柄和标题条能拖、过顶阻尼太重（多拉 100px 只跟 25px）、松手后用固定的 460ms 曲线、丢了手指的速度，改成上面这一套（看样页 M 节能拖着对比）。
- **标签栏的动效**：**展开是一下切过去**——胶囊在托盘还看不见的时候（托盘先画好再升起，§9）变成标签栏，只有颜色 260ms 过渡、名字 260ms 淡入；逐帧放大标签栏会让托盘升起的每一帧都多一次排版和重画（10-02 帧测）。**收起有过程**：托盘沉下时名字先 150ms 淡出，托盘卸下后标签栏 260ms `--ease-out` 收回胶囊（宽、高、圆角、离底 10px、图标回到 28px），这时别的都不在动。低动效时形状直接换，只有颜色淡变。

## 8. 界面风格：深玻璃 · 描金暗夜 · 暖瓷 · 定稿（2026-10-01；暖瓷 10-02 正式实装）

用户：UI 对场景来说颜色对比、层次太低，弹窗快融进场景里了，参考同类风格的优秀设计重新设计。调研的结论（来源见 [看样页](index.html) 第 L 节）：叠在复杂画面上的玻璃要**垫一层更实、更暗的底**（Apple 的透明玻璃要求下面有压暗层，NN/g 建议 10–30% 实色衬底和 8–20px 模糊）、**一道硬的细边**加**更深的投影**让眼睛抓得住边、**不要玻璃叠玻璃**（里层用实色填充）、**进入内容就把场景压暗**（星穹铁道的全屏菜单、原神不透明的奶油色面板都是这么做的）。

- **默认：深玻璃**（[ui-system.css](../../../../../src/themes/cinnaglass/ui/ui-system.css)）：底色从导航色板里抽出来单独成 `--ui-base`（暮色 31 31 40、黄昏 40 33 27、夜 30 27 26），每个面板的不透明度在原值上加 `--ui-boost` 0.17（原来 0.65–0.74 → 0.82–0.91），模糊 12 → 18px，霜纹 0.18 → 0.1，外加 1px 暗描边 `--ui-hairline` 和更深的两层投影；导航玻璃从 0.17–0.52 提到 0.66；任务窗背后压暗 0.4 → 0.5 并虚化 3px，内容页背后 0.6 + 虚化 6px。边上的金色 / 冷色光仍跟着时辰走。
- **描金暗夜**（设置里可选）：近乎不透明的墨蓝玻璃（不透明度 +0.25、导航 0.86），不要霜纹，描边换成一道金线、顶边最亮。最像游戏 UI。
- **暖瓷**（2026-10-02 用户：浅色风格可以应用实现；[look-porcelain.css](../../../../../src/themes/cinnaglass/ui/look-porcelain.css)）：浅色霜玻璃配深色暖墨字，夜景上对比最强，是很多恋爱游戏的做法。底色 `250 247 241`，不透明度 +0.24，模糊 24px，霜纹 0.05，导航 0.88；字 `#2a231b`、次要字 `#675b4c`；一道 `rgb(70 52 30 / 0.22)` 的暖色细描边和更深的投影，贴着亮墙也看得出边。金色分成两种：字、图标和焦点圈用深金 `#855617`，主按钮、选中的分段、今天这些实心的地方用浅金渐变 `#eecd8e → #d8a960`，上面配深墨 `#2d2012`。原来写死在各组件里的浅色字、白色描边、给深玻璃调的金光都换成了暖瓷的版本；纸、照片、放映的银幕和房间的画保持原色。所有规则都挂在 `:root[data-look='porcelain']` 下，别的风格看不到。按渲染出来的像素量过对比度（三个时辰 × 手机 / 桌面 / 横屏，190 张截图、3005 段字）：正文最差 8.9:1，次要字最差 3.5:1（沉浸歌词的浅底上，别处 4.8 以上），深金小字 4.6:1，金底上的深墨 7.4:1。减少透明效果时每块都是实色 `#f5f0e8`。
- **怎么换**：设置 → 主题外观 → 界面风格，点了立刻换，记在这台设备上（[look.ts](../../../../../src/themes/cinnaglass/ui/look.ts) 的 `setLook`，设置里用 [use-look.ts](../../../../../src/themes/cinnaglass/ui/use-look.ts) 跟着变）。`?look=gilded|porcelain` 在任何页面都能直接试，`?look=default` 回到默认；`?look=classic` 是改之前的玻璃，只作对比，设置里没有。

## 9. 弹窗的流畅度（2026-10-02）

用户：现在弹出框时能看出来有明显的掉帧，是场景的渲染性能太差了吗？——**不全是场景**。测法：在 Chrome 跟踪里取合成器真正把一帧画上屏的时刻（viz 的 `Graphics.Pipeline.DrawAndSwap`），手机 390 × 844 三倍屏、本机 GTX 1080，改前（`454753c`）和改后在同一份样板里各测 4 次；再用 Chrome 软件渲染（SwiftShader）把 GPU 开销放大做旁证。

**掉帧从哪来**

1. **第一次画托盘落在了上升途中**：托盘一出现就开始升，同时才去排版、光栅化（整张托盘的大投影、玻璃描边的遮罩、封面解码），GPU 卡住 100–180ms，托盘停住再跳一截。这是看得见的那一下。
2. **房间和托盘抢 GPU**：房间的 WebGL 每秒 30 帧画满屏（三倍屏上是 1170 × 2532 像素），托盘每动一帧还要重算一次背景模糊。
3. **几处贵的画法**：整张托盘的投影（大半在屏幕外或标签栏底下）；顶边阴影用的是上圆下方的圆角，模糊走了慢路径；唱片的 `drop-shadow` 滤镜；内容页自己的整页背景模糊（页面几乎不透明，模糊看不出来）和逐帧变大的背后虚化；逐帧放大的标签栏（每帧都要重排重画）；看不见的按钮光晕和悬停名字也在画投影。

**改了什么**

- **先画后升**：托盘（[sheet.tsx](../../../../../src/themes/cinnaglass/ui/sheet.tsx)）和内容页（[content-page.tsx](../../../../../src/themes/cinnaglass/ui/content-page.tsx)）都先在停靠的位置排好、画好，透明度 0.01 看不见，等两帧再出发；内容页还会等视野里的照片和纹理解码、字体就绪（最多 300ms）。上升时只是在移动已经画好的像素。
- **动的时候房间暂停**（[scene-hold.ts](../../../../../src/themes/cinnaglass/ui/scene-hold.ts)）：托盘升起 680ms、拖动中、收起到标签栏收回胶囊，内容页升起与退场，房间都停着不画；内容页打开期间房间一直停着（[WorldPage.tsx](../../../../../src/pages/WorldPage.tsx) `active`）。**TA 优先**（10-03）：TA 一有动作（状态变化，以后接上真实在场的开始打字、离开等），房间立刻恢复，之后 2.5 秒里面板不再让它暂停，TA 的动作准时、从头播放（`releaseScene`）；TA 的姿势按真实时钟走，暂停着的房间会让动作晚出现、还跳过开头。场景画布最高 2 倍像素：房间的底图和人物只有 1536 宽，三倍屏多画 2.25 倍像素看不出区别（[room-scene.tsx](../../../../../src/themes/cinnaglass/room/room-scene.tsx)）。
- **便宜的画法，样子不变**：托盘的投影只画顶边一条，四角同样的圆角，浏览器一次就能糊好（下面两个角在托盘里面，外投影本来就看不见）；唱片阴影换成同样的圆形 `box-shadow`（`drop-shadow` 的模糊是标准差，等于 `box-shadow` 模糊的一半，逐像素对过）；内容页去掉自己的背景模糊，背后虚化一开始就是 6px、跟着压暗一起淡入，手机上只压暗；标签栏展开一下切过去（§1）；看不见的按钮光晕不带外圈投影，手机上不画悬停才出的名字。

**改前改后**（第一次打开 = 页面加载后第一次，包含一次性的着色器编译、解码；之后再开没有这些）

**还没解决的**（记在 [TODO](../../../../TODO.md)）：第一次打开仍要准备 180–250ms，多是一次性的着色器编译和解码，可以在空闲时预热；回忆页倾斜的拍立得每张两层模糊投影，转了角度就走慢路径，可换成预先画好的阴影图；以上都是本机显卡和仿真，iOS / Android 真机还没测。

**以后做新弹层的规矩**（[交互规则 §6](../../interaction.md#6-动效全局体系与低动效模式) 同步）：

- 用 `Sheet` / `ContentPage` 外壳就自带先画后升和房间暂停；自己写的弹层也要先画好再动，动的时候 `holdScene(ms)`。
- 动画只动 `transform` / `opacity`，不逐帧改宽高、圆角、模糊半径；形状要变就一下切过去，或者放在别的都不动的时候。
- 大的模糊投影只画在看得见的那条边上，用四角同圆角的盒子；圆的东西用 `box-shadow`，不用 `drop-shadow` 滤镜。
- 几乎不透明的面板不加 `backdrop-filter`；背后的虚化用固定半径、淡入。
- TA 的动作不等任何面板：改 TA 状态、放反应的地方先 `releaseScene(ms)`。

**录屏是怎么录的**：[record-ux.mjs](../../../../../scripts/record-ux.mjs) 抓合成器的屏幕帧，录的时候页面里的时钟、定时器和动画一起放慢 4 倍，合成时按原速、每秒 25 帧，再用 Chrome 自己的编码器出 H.264；场景清单在 [record-ux.json](../../../../../scripts/record-ux.json)。放慢录制保证重负载的瞬间也不漏帧，但也因此录屏看不出卡顿，流畅度以上表为准（帧测脚本 [probe-frames.mjs](../../../../../scripts/probe-frames.mjs)）。
