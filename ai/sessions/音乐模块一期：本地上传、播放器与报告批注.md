## 这一期做了什么（都在 dev）
- 数据库：`supabase/migrations/20261001100000_music_library.sql`（13 张表、私有桶 `music`、RLS）+ `20261003100000_music_ingest.sql`（大文件分片、`music_finish_upload` 核对字节、`music_ingest` 一个事务入库且重试不重复、省流版登记、用量、「我们的歌单」、变更广播到私有话题 `music:<world>`）。
- 播放：`MusicEngine`（`src/lib/music/engine.ts`）在播放器打开时由 `src/themes/cinnaglass/music/use-music.ts` 创建：`<audio>` 直接放原件；CUE 同一文件的相邻段只移动时间窗、不换音源；iOS 点按即播、链接过期重签、解码失败改放省流版、锁屏控制。选哪个版本在 `src/lib/music/sources.ts` 的 `pick()`。
- 上传：`src/lib/music/ingest.ts` 串起解析（标签、GBK 乱码修复、LRC、CUE、封面）→ 查重 → TUS 断点续传（`upload.ts`）→ 核对 → 入库 → 设备上做省流版（`transcode.ts`）。
- 界面：「歌单」改「曲库」，加上传页和音质页（`src/themes/cinnaglass/music/`）。看样页 B 节下半有截图。
- 测试：`bash scripts/check-music-db.sh`（要本机 PostgreSQL 15+ 和 pgTAP，108 条）、`node scripts/check-music-parsers.mjs`（46）；先 `VITE_SUPABASE_URL=https://example.supabase.co VITE_SUPABASE_ANON_KEY=x pnpm dev`，再 `DIARY_NODE_MODULES=$(npm root -g) node scripts/check-music-library.mjs`（9）和 `check-music-transcode.mjs`（20）；手机回归 `MOBILE_UI_BROWSER=chromium … node scripts/check-mobile-ui.mjs`。

## 本轮关键决策
- 零服务器 + Supabase Free；超过 45 MiB 分片存，升 Pro 只改 `DEFAULT_MAX_OBJECT_BYTES`。
- 不做「始终原件」设置，每首选 自动 / 原件 / 省流；iPhone 看不出在不在用流量，自动 = 原件。
- 实时话题用 `music:<world>`、只发 id，不和聊天共用 `world:`（同名话题会共用 channel，退订会把聊天一起断掉）。
- 看样页 artifact 只合并自己的部分，不覆盖别的会话的内容。

## 别踩的坑
