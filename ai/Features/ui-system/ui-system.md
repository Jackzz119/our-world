> 2026-09-12。状态：全项目盘点与迁移计划已完成，补充原画分层与环境光照工作流；尚未开始产品改造。

> 任务状态只记在 [TODO](../../TODO.md)；当前代码事实见 [审计](audit.md)；视觉登记见 [UI 总览](../../design_system/uiux/cinnaglass/ui-system.html#ui-unification)。本文件定义目标和实施顺序，不代表目标已实现。

## 1. 这次要收敛什么

视觉签名：**映着小屋暖光的细纹磨砂玻璃**。场景提供氛围，UI 提供清楚、稳定的操作；打开功能后仍能认出这是同一间小屋。

三类是使用方式与载体的分类，共用颜色语义、文字、控件与交互规则，不能演变成三个互不相干的主题。

| 体系          | 用途与范围                                                                        | 材质方向                                                                                     | 状态                                          |
| ------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------- | --------------------------------------------- |
| A 场景悬浮 UI | 导航、天气、聊天窄窗、音乐折叠/展开、纪念卡、头顶状态、附着小菜单                 | 当前导航的中性细纹磨砂玻璃；按内容密度调整厚度                                               | 用户指定导航为基准；其他组件待迁移            |
| B 任务界面    | 设置、世界设置、日历/闹钟、完整聊天、确认/选择/错误提示；登录/重置/大厅是页面形态 | **建议：同源的较厚中性磨砂壳 + 稳定的阅读/表单底**。保留细边与暖光，不沿用全窗旧纸、苔绿包边 | 推荐方向；需先看设置实景标准板再定具体参数    |
| C 专属物件 UI | 日记等具有专属几何、材质、开合方式的实体载体                                      | 由物件自身定义，外部公共控件遵循共有规则                                                     | 本 session 日记整体冻结；其他专属载体另案设计 |

**入口不决定材质**：点唱片机仍打开 A 音乐浮窗；点挂钟仍打开 B 时钟；点相框和导航照片入口应进入同一个照片界面。照片墙、心愿单目前暂列 B 内容界面；若以后批准相册/许愿罐专属形态，才迁为 C，不能仅因物件可点击就重做它。

本 session 的日记冻结包含：阅读、写作、详情、书本资产、翻页、遮罩、布局，以及这些路径依赖的共享规则。后续修改 `screens.tsx`、`materials.css`、公共 `.modal/.paper` 前必须证明范围只覆盖 A/B；不能顺手清理看似过时的日记文件。

## 2. 导航母材质：现状与建议

### 2.1 已核实的实现

| 看见的效果     | 实际来源                                                                                   | 结论                                                     |
| -------------- | ------------------------------------------------------------------------------------------ | -------------------------------------------------------- |
| 不规则纹理     | 一张生成后固定保存的 512×512 透明 `public/ui/nav/frost.webp`；CSS 按 256×512、42% 50% 取样 | 有自然不规则感；没有运行时随机、每组件随机种子或逐帧噪声 |
| 磨砂透景       | 半透明底 + `backdrop-filter: blur(2.4px) saturate(0.7)`                                    | 浏览器实时模糊后方合成画面；没有折射位移或物理透光计算   |
| 细反光边       | `::after` 的固定角度 `conic-gradient` 经 mask 留下约 1px 边                                | CSS 模拟高光；不采样场景灯、不随真实光向计算反射         |
| 随时辰暖冷变化 | `.rail-wrap` 内的 `--nav-tint/top/cold/rim/ink` 按 `data-mood` 切换                        | 时辰预设驱动；纹理图片没有随时辰更换                     |
| 悬停/按压发光  | 径向暖光、图标 `drop-shadow`、按压缩放                                                     | 独立的交互反馈，不应解释成环境光反射                     |
| 房间变化       | `study-room.ts` 的 golden/twilight/night 三张底图 + Pixi 交叉淡化、天气调色和光层          | “换图片”主要发生在房间；侧栏透过背景间接看到变化         |

当前导航没有直接消费天气或灯位置。晴转雨会改变后方场景，但不会直接改 `--nav-rim`。不能在文档继续把这称为“真实场景反射”。

### 2.2 保留的基准

- 桌面 74×384，圆角 25，左距 38，垂直居中；窄/矮屏 292×62 底部横条。五入口保持房间、聊天、音乐、工具、设置。
- 透明、中性、细纹与局部强弱不同的薄边；保持用户认可的暖光反馈。不要统一成固定绿色面板，也不要回到整条糖果渐变边。
- 导航小菜单已是同源加厚变体：模糊 8px，底色透明度至少 0.5。它是扩大复用的起点，不是另一套材质。
- 纹理、环境高光、交互高光分层，图标与文字处于独立清晰层。

### 2.3 推荐的最终规则（待标准板验收）

1. **纹理静止**。保留同一中性纹理源；宽面板先验证平铺接缝和颗粒尺度。若多个面板明显“复制同一块云纹”，给组件固定取样偏移；不随 render、打开、时辰或动画重新抽样，不做噪声闪动。
2. **光照参数同源**。场景向 UI 提供时辰/天气/主光暖冷与方向参数，A/B 消费同一份环境描述。当前先保留导航三档观感；以后可让边缘高光随参数缓慢变化，仍明确属于艺术化模拟。
3. **不把逐帧场景采样、反射贴图、法线/光追当本轮前置**。这类方案要单独证明视觉收益和常驻性能成本；换房间不能要求重画每一个 widget 的外壳。
4. **厚度跟着内容走**。同源纹理与边缘不等于所有面板都用 2.4px 模糊和同一透明度：图标导航薄；聊天/播放器有稳定阅读底；任务弹窗更厚。文字区域不透出干扰性细节。

### 2.4 原画与环境光照工作流（2026-09-12）

已建立 `art-relighting` 技能，覆盖原画定稿、材质/光色拆分、环境变体与还原验收；项目事实与职责见 [原画分层与环境光照](../../design_system/research/art-relighting.md)，当前原画和光纹理见 [渐变预览](../../design_system/research/art-relighting-preview/index.html)。

后续以共享环境参数连接场景和 UI。先明确天光、窗光与室内灯的职责，再验证 A/B 外壳响应；具体值与图层/shader 取舍尚未定稿。技能首版不代表已有中性房间底图或真实反射，运动与动态阴影技能后置。M1 标准板应纳入这份光照输入的讨论，产品实施仍按具体批准范围推进。

## 3. 共用视觉与组件规范

以下为推荐约束，具体色值/尺寸在 M1 的真实组件标准板上确定；不把未验证数值写成“已定稿 token”。

### 3.1 风格四件套

| 维度           | 建议                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 主色板（五类） | 中性烟灰、柔和米白、暖金、身份蓝、身份粉。红/绿另作错误/成功/在线语义，不作装饰底色                |
| 质感           | 静止细纹、轻雾透景、薄的局部反光、柔和接触阴影；表单底稳定；旧纸只属于获准的内容/物件              |
| 形状           | 柔圆矩形为主；胶囊只用于短条/状态，圆形用于确有需要的图标动作；不把所有按钮做成发光球              |
| 光照           | 环境只影响外壳细微暖冷与边光；操作反馈用暖金；身份/成功/危险不因时辰换义；照片原色不受外壳滤镜污染 |

### 3.2 组件层级

- **基础值**：色彩、字号、行高、字重、间距、圆角、边线、阴影、图标尺寸与描边密度。导航线性图标是视觉锚点，现有 `icons.tsx` 保留路径资产后统一用法，不全部重新画。
- **语义值**：悬浮壳、悬浮内容底、任务壳、任务内容底、主/次文字、边线、focus、hover、selected、danger、disabled。同一语义只有一个负责定义的位置。
- **公共控件**：Button、IconButton、Field、Switch、Segmented、Slider、列表行、Badge、Tooltip、Popover、Dialog、确认框、状态提示。
- **功能组合**：天气、聊天、音乐、设置等只负责内容与行为；不在每个 `<style>` 块里重复定义整套材质。

字体建议：A/B 普通正文和控件统一圆润、清晰的无衬线字体，延用现有 Noto Sans SC/system 回退即可起步；手写/衬线保留给物件和内容。禁止每个弹窗一套标题字体。基础正文以 14–16px 验证，辅助文字 12–13px；小窗减布局，不缩字硬塞。

控件至少覆盖 default / hover / pressed / focus-visible / selected / disabled / pending / error。高光之外还须有轮廓、文字或选中标记，让只用键盘、触屏或降低动态效果时也能识别状态。语义先定，动画曲线和时长后置。

### 3.3 Token 迁移建议

现有 `--nav-*`、`--cg-*`、`--shell-* / --glass-*`、`--craft-*` 各有消费者。先加 A/B 的明确入口并逐个迁移，再让旧名成为兼容别名，最后清理无消费者的旧值。

推荐关系（命名示意，尚未写入产品）：

```text
环境参数（mood / weather / key light）
    ↓
共用玻璃材质：tint / grain / blur / rim / shadow
    ├─ A：navigation / widget / attached popover
    └─ B：dialog / content / form
共有控件：text / field / action / state / focus
C：继续使用自己的物件材质与现有实现
```

不要把“改造 B”做成一次全局替换 `--craft-paper`，也不要用不断增长的全局选择器清单推测每个组件属于哪种文字色域。新 A/B 使用显式表面作用域；旧别名在有消费者时继续存在。

`data-glass` 的云朵/天空/暮光旧材质开关目前不能一致控制导航和 widgets。建议最终只保留一套产品材质；“减少透明效果”作为功能性偏好单列。旧存储值的兼容和设置项移除必须跟迁移一起做，不留下无效果的开关。

## 4. UX 契约

### 4.1 层级与关闭

| 层             | 规则                                                                        |
| -------------- | --------------------------------------------------------------------------- |
| 房间           | 场景与音频按各自生命周期运行                                                |
| A 常驻/悬浮    | 可与场景交互；不开全屏暗幕。多个浮窗使用固定停靠区和避让规则                |
| A 附着层       | 菜单/提示跟触发控件定位，超出边缘时翻转；同组只开一个；Esc/点外关闭并回焦点 |
| B 遮罩与任务窗 | 在 A 之上；打开时背景与 A 不可操作、不参与 Tab，不叠多个全屏磨砂遮罩        |
| B 内附属层     | 选择器/确认框在所属任务窗之上；Esc 只关闭最上层，不能一次连关多个窗口       |

B 需要统一 dialog 语义、标题关联、打开初始焦点、焦点限制、关闭焦点归还和隐藏 `inert`。保存失败时保留输入；带未保存内容的点外/Esc必须按该任务的草稿策略处理。成功提示只在真实成功后出现。不要将日记现有的特殊关闭/草稿逻辑顺带替换。

### 4.2 响应式

- 桌面：以现有左导航为锚点，为左下聊天、右下音乐、顶部天气/纪念卡划定停靠区；展开态不能盖住自己必须使用的控件。
- 中等/矮屏：降低同时展示密度，保留主要入口和当前任务，允许信息卡折叠，不靠整体缩放解决。
- 窄屏：底部导航预留安全区；聊天/音乐展开共享可用工作区，优先互斥；天气与纪念卡错开。所有宽度受容器上限约束。
- B 小屏改为留安全边距的全高任务页或底部面板，标题/关闭、输入区和主动作可达；软键盘打开后仍可提交或收起。
- 触控目标以 44px 为验收起点，细图标可小、点击区域不能随之缩小；加入焦点可见、长文本换行、200% 文本缩放检查。

### 4.3 功能状态必须诚实

1. 音乐的播放/暂停、展开/收起、进度与曲目必须分别来自实际状态；不能用展开态冒充播放态。隐藏 widget 不应销毁音频引擎；导航音乐入口应能恢复隐藏的播放器。
2. “修改密码/绑定邮箱/应用锁”先核对真实能力，再决定接通或收起；不能点完只改本地文字就显示成功。世界设置恢复到“设置 → 我们的小世界”。
3. Presence、天气实况失败、闹钟到时提醒、共享音乐同步等没有接通的状态必须明确；不增加占位在线绿点或虚构更新时间。
4. 纪念卡、日历和世界设置共用纪念日来源；本地事件/心愿与双人同步数据的能力边界清楚。
5. 保留聊天已有的历史加载、发送失败重试、编辑/删除、reaction 和贴纸；先收起服务器/好友导航外壳，数据层另按原计划冻结保留。
