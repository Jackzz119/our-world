# 产品愿景：放置陪伴小屋

> Reboot Kit 之一。定位声明、核心体验、功能迁移映射、MVP 范围与开放问题。
> 来源：2026-08-09 用户重定位决策 + 既有资产盘点（ai/PROJECT.md、ai/TODO.md 当日快照）。

## 1. 重定位声明

### 旧定位（放弃）

Discord-like 私密社交空间 + 3D metaspace：世界 > 房间/文字频道/语音频道，sidebar 导航，WASD 场景移动。

### 为什么放弃

- **结构冲突**：服务器/频道/好友列表是「多人社区」的信息架构，套在两个人身上是空转——两个人不需要频道列表，需要的是「感到对方在」。
- **媒介两头不靠**：metaspace 若不用 3D 就撑不起「空间感」；用 3D 又与「放置陪伴、瞥一眼」的真实使用方式冲突（codex 媒介调研已证实：固定机位 + 轻交互下实时 3D 全是噪点成本，见 `codex-visual/20260809-083950Z/codex-report.md`）。
- **轻量聊天打不过现成 IM**：如果退化成一个普通聊天工具，微信/QQ/Discord 全都比我们成熟。

### 新定位

**放置陪伴小屋（idle companion home）**——对标 Steam lofi 陪伴/放置游戏（Spirit City: Lofi Sessions、Chill Corner、Rusty's Retirement、Desktop Mate）+ 中国虚拟自习室的 presence 机制（CoStudy 式「看见对方坐在那里」），但服务对象是**一对情侣的两个人**，不是陌生人社区。

一句话：**它是一个开着就行的小屋。两只小狗代表我们俩，谁在线谁的角色就醒着做事；窗外跟着真实时间晨昏流转；我们的回忆（时间线/照片/聊天）藏在房间的每一件家具里，点击打开。**

产品内核不变：**管理亲密关系记忆 + 陪伴感**（ai/PROJECT.md 北极星）。变的是壳——从「社交软件的壳」换成「放置游戏的壳」。陪伴感的载体从「频道里的消息流」变成「场景里的两个身影」。

## 2. 核心画面与体验循环

### 核心画面（用户脑中的样子，灵感原点 = codex 04「近景一角」）

- 固定镜头的温馨房间，水彩手绘暖光质感（延续 cinnaglass 大耳狗 pastel）
- 两只原创 Q 版长耳小狗：蓝耳 = 男主，粉耳 = 女主（配色沿用现有作者色体系：我=蓝 / 对方=粉）
- 角色**不走动**——直接在自己的位置上：坐着看书、写日记、倒咖啡、喝咖啡、趴着打盹
- **窗外光照跟随系统时间**：早晨/白天/黄昏/夜晚——直接复用已定稿的「光照递进」体系（D-12：UI 外壳明度随时辰递进，内容纸恒白最亮）
- **天气与现实脱钩**：晴/雨/雪自选，是氛围开关不是天气预报
- 无 WASD、无自由镜头、无场景漫游——**所有交互都是点击**

### 场景物件 → 功能映射（点击触发）

| 场景物件 | 打开的功能 | 现有实现 |
|---|---|---|
| 书桌 / 日记本 | 时间线（日记流 + Composer 发帖） | ✅ 已有（timeline.md ST 系列，接真后端） |
| 相框墙 / 相册 | 照片墙（polaroid 拼贴） | ✅ 已有（接真后端） |
| 信箱 / 床头手机 | 聊天（实时消息 + 贴纸 + reactions） | ✅ 已有（channels/messages 全链路） |
| 挂钟 | 时钟 · 闹钟 | ✅ UI 已有（后端未接） |
| 挂历 | 日历 · 约会 + 纪念日/在一起天数 | ✅ UI 已有（纪念日已接 DB） |
| 唱片机 | 共享音乐 | ✅ UI 已有（共享状态未接） |
| 许愿罐 | 心愿单 | ✅ UI 已有（后端未接） |

| 窗户 / 灯 | 天气切换 / mood 手动覆盖 | ✅ tweaks 体系已有 |

### 体验循环（放置陪伴的一天）

1. **开着**：应用常驻（窗口/小窗/未来贴桌面），自己的角色在房间里
2. **对方上线**：她的角色「醒来」亮起，开始做她的放置动作——**presence 即陪伴**，这是产品最核心的一眼价值
3. **瞥一眼**：任何时刻扫一眼就知道「她在不在、在干嘛」（1 秒可读，codex 报告的核心验收标准）
4. **轻互动**：点她的角色打招呼；新消息以聊天气泡浮在角色头顶，点开进完整聊天
5. **记录**：点书桌写下今天的事、传照片——回忆持续沉淀
6. **回看**：点相框墙翻照片、翻旧日记
7. **时间流动**：窗外晨昏跟着真实时间走，天气随心情切，节日出现装饰（远期）

### Presence 设计（在线状态的视觉语言）

- 对方**在线**：角色回到座位、做放置动作循环、头顶单个绿色点（概念图 06 右）
- 对方**离线**：**空位留痕**——座位空着，但留一盏灯、她的杯子、围巾这类「余温物」，传达「她暂时不在，但这个位置属于她」（概念图 06 左，codex 与 Claude 复核一致推荐；否决灰色睡眠形象——与勿扰/死亡隐喻混淆）
- 对方**忙碌/学习中**（远期）：状态 → 角色动作映射（看书=专注、咖啡=休息）
- **行为翻译**（Bongo Cat 原理的双人版，调研金矿）：对方正在输入聊天=角色执笔写字、翻相册=角色拿起相框、开着页面=角色在桌前——把真实行为实时翻译成场景动作，比任何聊天气泡都更「陪伴」，且聊天/时间线数据已具备

### 陪伴设计三铁律（两线调研共同沉淀）

1. **零成本在场**：只要应用开着，形象就自然在那里；任何要「经营」的 presence（手动打卡/签到才出现）会让更忙的那个人先放弃，产品随之单边死亡
2. **只做正反馈，不做惩罚**：不做「你没坚持所以我们都受损」（Forest 连坐的反面教训），只做「你在的时候我们都变好」；双人场景里排行/竞争/踢人全部有毒
3. **互动长在房间和物件上，不长在信息流里**（Timing 短视频化反噬之鉴）：两个人没有 feed 存在的理由

### 陪伴玩法储备（MVP 后的增长方向，调研验证过的机制）

- **共同养成资产**：两人各自忙碌的重叠时段自动养一株植物/宠物，长成后自动落进 timeline 成为共同记忆（Forest 机制的正反馈版 × 我们的数据层）
- **小纸条**：忙碌中给对方桌上放张纸条/一杯咖啡，对方回来才看到（异步轻互动，不打断）
- **重逢时刻**：两人先后收工时，角色碰头 + 今日共处时长小结——presence 的高光在「下课那一刻」
- **异地时差**：窗外可切换显示「对方那边的天色」，把时差做成情感点
- **离线生长**：几天没开，回来时墙上多了拍立得、窗台植物长高了（回访钩子）

## 3. 功能迁移映射（旧结构 → 新结构）

### 保留（产品内核，全部已接真后端的不动）

| 现有资产 | 新去处 |
|---|---|
| timeline 日记流 + Composer（含多图/草稿） | 点书桌打开，UI 白纸卡浮在场景上 |
| 照片墙 polaroid 拼贴 | 点相框墙打开 |
| 实时聊天全链路（channels/messages/reactions/贴纸/已读） | 点信箱打开大窗；气泡浮角色头顶 |
| worlds 表（两人世界） | 语义改为「我们的小屋」，结构不变 |
| 纪念日/在一起天数（DB 实时计算） | 融进场景（挂历物件）或保留 HUD 小卡 |
| 光照递进体系（D-12 定稿：mood 驱动明度 + 纸恒白） | **直接成为场景时辰系统的 UI 侧**——为新方向天然铺好了路 |
| cinnaglass 玻璃拟态 token 体系 + ui-system.html 真源 | 继续是 UI 薄壳的设计系统 |
| auth（白名单 2 人 + 登录守卫） | 不变 |
| 日历/时钟/音乐/心愿单 UI | 挂到对应物件下，逐个接后端（原计划不变） |

### 退役（Discord 语义的壳）

| 现有资产 | 处理 |
|---|---|
| sidebar（rail + panel、服务器/频道导航） | 退役。导航改为「场景物件 + 极窄玻璃 rail（设置/退出等系统级入口）」 |
| 频道概念的 UI（文字/语音频道列表） | UI 退役；`channels` 表保留当聊天管道（dm/text 型继续用，数据不丢） |
| 大厅（漂浮岛 + 传送门） | 退役。两人产品直接落屋；「串门/公共空间」留作远期畅想 |
| 好友页（Discord 式 tabs） | 收起。好友/DM 数据层保留（账号级基建，远期公共空间可复用） |
| 聊天中心 hub 的服务器式布局 | 简化为单一聊天大窗 |
| WASD 移动 / 空间切换器 SpaceScreen | 废弃 |
| 3D metaspace 计划（metaspace-scene-lighting.md Phase A-E、R3F 接入） | 废弃/转化——Blender 资产转产 2.5D 预渲染层（见 tech-plan.md） |

### 数据库影响预估（拍板后细化）

- **零迁移可开工**：新壳完全可以骑在现有表上（worlds/posts/channels/messages/profiles 语义全兼容）
- 拍板后的清理项（低优先级）：`channels` 收缩为固定一条 world 频道 + dm；`friendships` 冻结不删；新增 `presence/状态` 走 Supabase Realtime Presence（无表）；角色状态/房间装扮如需持久化再加表

## 4. MVP 范围（用户已定基调）

**视觉目标 = codex 概念图（04 近景一角延伸的新批次），角色 = 大耳狗风格原创双狗。**

1. **一个房间场景**（近景构图，不做全屋）：预渲染背景 + 时辰四态（早/午/黄昏/夜）+ 雨天气层
2. **两只角色**：各 3-4 个放置动作循环（看书/写字/喝咖啡/打盹）+ 在线/离线两态——媒介按 tech-plan 拍板结果
3. **presence**：Supabase Realtime Presence 接角色状态（对方打开应用 = 角色醒来）
4. **物件热点 × 3**：书桌→timeline、相框→照片墙、信箱→聊天（三大已完成功能直接挂入）
5. **聊天气泡**：新消息浮角色头顶（现有 Broadcast 已支持）
6. **UI 薄壳**：极窄玻璃 rail（设置/登出）+ 白纸功能卡浮层，沿用光照递进
7. **形态**：按 tech-plan 拍板（倾向：网页先行，桌面壳随后——待调研定稿）

**不在 MVP**：语音、共享音乐真实同步、心愿单/日历后端、房间装扮、多房间、串门、节日系统、角色换装。
