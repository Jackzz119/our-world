# 生成：怎么出一套能动起来的姿势图

> 按需加载。写生成 brief、出图、判断要不要重出时读。brief 模板：`../templates/brief.md`。

## 目标不是「好看的图」，是「一套互相对得上的图」

运行时会把这些图原地叠在一起切换、变形。任何一张的身体、脸、比例漂了，都会在切换时变成跳动、双线或多出来的一块。
所以验收标准的第一条是**一致**，其次才是好看。

## 出图顺序

1. **anchor**：最常出现的状态姿势（通常是默认在场状态），按画布规格从人物设定 / 已定稿的场景图重画一张。
   单独验收：身份对、构图对（头顶位置、截断线、居中）、真透明、主体不透明、边缘干净。**anchor 不过，后面都不出。**
2. **其余姿势**：每一张都是「以 anchor 为输入的编辑」，不是新画。prompt 里写清只改哪些部位。
3. **闭眼帧**：以对应的睁眼帧为输入，只改眼睑。
4. **不参与形变的大动作**（趴下睡觉等）：同样从 anchor 编辑，但允许肩线变化；在 `rig.json` 里标 `probe: false`、`morph: false`。

## 先量场景，再写数字

brief 里的每个位置数字都要从场景量出来，不能估：尤其是**躯干截断线**——它必须正好落在场景里桌面（或别的遮挡物）的远沿上。做法：在底图上量桌面远沿的 y，用 anchor 的配准（assemble 的 `registration`）换算成画布 y，写进 `rig.json` 的 `cut_plate_y` / `cut_y` 和 brief。第一个案例里 brief 写了「截断线 y=900」，实际桌沿在画布 y=968；手和书挡着的姿势看不出来，双手捧杯的姿势一出就在躯干和桌面之间露出一条椅背。新人物的第一张 anchor 出来、配准之后，先做这一步，再出其余姿势。

## 每张 prompt 都要重复的不变量

模型不记得上一张，所以每张都要把不变量写全（模板里是一整段，原样复制）：

- 画布尺寸精确一致，横 / 竖版一致；**真透明背景**（alpha = 0，不是画出来的棋盘格、不是纯色底）；
- 人物水平居中，头顶离上边的距离；肩膀外轮廓的大致 x 范围；
- **躯干截断线**：坐在桌后的人物，截断线以下不画躯干（被桌面挡住），前臂、手、手里的东西可以搭到桌面上、超出这条线；
- 肩、胸、截断线在每个姿势里位置和比例不变，**只有头、手臂、手、表情、道具变**；
- 光：均匀、略暖的正面光，柔和体积，**不要强轮廓光、不要投影到人物外面**（场景光由运行时统一染色）；
- 只画这一个人：没有桌子、椅子、背景、其他人、文字、边框。

## 闭眼帧

- prompt 写「只改两只眼睛为轻闭的眼睑；眼镜框、眉毛、嘴、脸型、头发、头部角度、肩膀、手、道具**全部不变**」；
- 生成模型做不到逐像素不变，几何会漂一两个像素——这由流水线的 align 步骤对齐回来，**不要为了这点漂移反复重出**；
- 但**纹理重画了**（袖子、衣褶、发丝走向变了）对齐救不回，check 会按眼外变化 > 8% 拒掉，那张要重出；
- 重出时给模型两张输入：anchor（锁身体）+ 对应睁眼帧（锁表情），并在 prompt 里点名上一版改坏了哪里。

## 反应姿势怎么设计才好变形

光流形变能补出「同一样东西移动了」的中间帧，补不出「一样东西消失、另一样出现」。所以：

- **小幅、局部的变化最好**：抬眼、闭眼笑、头微微上抬、脸红——形变过渡几乎完美；
- **道具换了**（书换成笔记本）：形变能过，道具会在中段交叉溶解，可以接受；
- **手离开原位去拿别的东西**（从书移到杯子，位移 100px 以上）：光流跟不上，会把原来那样东西一起拖走。
  这类姿势 morph 会被自动拒掉、退回淡入淡出。想要连续，得多生成一张**中间姿势**（手离开书、伸向杯子），
  让每一段的位移都小；
- **大动作**（趴下、转身、站起来）：标 `morph: false`、`slow: true`，用慢速淡入淡出，读起来像「打了个盹」。

## 生成方要交的自审报告

要求出图方（人或 agent）对每张给出：尺寸、是否真透明（透明像素数）、主体包围盒、相对 anchor 的肩线漂移（固定几列测量）、
截断线位置、闭眼帧眼外变化、肉眼可见的缺陷（多指、眼镜断、发丝边缘脏）、重出了几版、为什么选这一版。
**采信它的测量，不采信它的结论**——结论由 check 和你看证据图来下。

## 每张出几个候选，按测量挑

同一条 prompt 每次漂得不一样，所以稳定的做法不是「出一张、不行再出」，而是**每张一次出 3 个候选**，用
`python rig.py pick --config rig.json --pose <姿势> --files <候选…> [--fit head]` 挑：它给每个候选做 check 的验收，
再量它和 anchor 的一致性——头按脸框对上（`--fit head`，给本来就要动头的姿势）、几何对齐之后，头发轮廓还剩多少对不上。
那个残差就是生成模型**画得不一样**的东西，对齐救不回来，所以它越小越好。闭眼帧用 `--open <睁眼帧>`，按眼外变化打分。

分数只量得到轮廓和位置，量不到动作对不对：第一个案例里，得分并列第一的写字候选把眼睛画成了闭着的，
写字要的是睁眼往下看。**挑出来的前两名，要人看一眼 `review/pick-<姿势>.jpg` 再定。**
选定的那张改成正式文件名放进 source，其余候选留在出图批次目录里备查。

## 什么时候重出、什么时候接受

| 情况                                                     | 处理                                                     |
| -------------------------------------------------------- | -------------------------------------------------------- |
| check FAIL（假透明、肩线 > 8px、截断线 > 8px、尺寸不对） | 重出这一张，原稿加后缀保留做对照                         |
| 闭眼帧眼外变化 > 8%                                      | 重出闭眼帧；来不及就接受「这个姿势不眨眼」，记进已知问题 |
| 肩线 3–8px（WARN）                                       | 看 overlay：双线不明显就接受                             |
| 动作幅度没达到设计（比如「缩一下」没画出来）             | 这是设计取舍，报告里写明，不假装做到了                   |
| 纠正稿反而更差                                           | 回到上一版，别为了「重出过了」而用更差的                 |

## 为什么不用视频 / GIF 生成

视频模型一次生成一段连续动作，帧间确实比逐张生成稳；但它生成的是**一段固定的录像**，不能按运行时的状态随时进出、
被打断、和呼吸叠加，而且每段的首尾帧要和姿势图完全一致才能接上，这又回到了一致性问题。
用图片模型生成 GIF 没有意义：GIF 只是把逐张生成的图装在一个文件里，每帧照样漂。
视频模型可用时，比较值得的用法是：生成两个关键姿势之间的**参考动作**，从中挑一两帧作为中间姿势，再走本流水线。
