## 四、复刻顺序建议（每步都动受保护文件或技能，需你逐步授意）

1. **建真源**：新建 `ai/jaSkill/`，把 `.claude/skills/*` 移入（补 `monet` / `ui-tailor` 的 `agents/openai.yaml` 来自 `.agents` 侧）；复制 hyber `scripts/skills-link.sh`；`.gitignore` 加 `.claude/`、`.agents/`、`.agent-toolkit.json`；删除入库的 `.agents/skills` 实体；跑 `bash scripts/skills-link.sh`。**注意**：`.claude/launch.json` 目前入库、被整目录忽略后会退出版本库，需决定是否保留为个人配置。
2. **同步通用技能到 hyber 9 月版**：`intj` `vc` `logman` `custom-skill` `codex-visual` `monet` `ui-tailor` 直接以 hyber `ai/jaSkill/` 为准覆盖；`feature` 覆盖后**删除**「菜单功能走 menu 目录」等 hyber 项目专属段；按需加 `shelf-ops`；`project-audit` 已一致。`blender-create` 留作本项目专属。
3. **建 `ai/JASKILL.md`**：登记本项目专属技能（目前只有 `blender-create`；将来的领域包放这里），写明触发场景与更新方式；`PROJECT.md` 的技能登记表改为只留项目入口，通用技能归协议。
4. **改写协议**：以 hyber `ai/jaAgents/CLAUDE.md` / `AGENTS.md` 为模板重写本仓两份（去掉 Next.js / Turborepo / Multica / 菜单目录等项目专属内容），补：修改授权、规则来源与优先级、Skill 真源与 symlink 规则、通用技能表、会话标题、并行工作区保护、报告规范新版、文档职责表、不读 sessions；两份等义。决定是否同样把根协议 gitignore 并在 `ai/jaAgents/` 留入库副本（团队多人时才值得）。
5. **配套文档**：`PROJECT.md` 加「开工红线」节；新建 `ai/PENDING-DECISIONS.md`；`README.md` 加 AI 协作配置段与文档地图；`.gitignore` 加 `ai/sessions/`（并 `git rm --cached` 已入库的两份存档）。
6. **决定 codex-visual 产物策略**：沿用本轮的 `ai/codex-visual/` 入库归档，或改为 hyber 的 `ai/design_system/codex-visual/` gitignored + 有价值才搬 research；二者选一后同步 `codex-visual` 技能里的落点说明。
7. 仅当要用 Multica 云端 agent：复制 `ai/jaAgents/MULTICA.md` + `bootstrap.sh`，并在 `PROJECT.md` 写本项目的合并/CI 参数。

## 五、复刻时的坑（来自 hyber 的注释与历史）

- 两目录互相软链、真目录一半在 `.claude` 一半在 `.agents` 的老结构会让 worktree 里的 agent 只看见一半技能——这正是 hyber 改成 `ai/jaSkill` 的原因。
- `.gitignore` 里裸 `SKILL.md` 曾静默漏提交技能真源（只剩 reference.md 入库）。
- `npx skills update` 会把 symlink 覆盖成真目录，必须跟 `skills-link.sh --adopt`。
- Codex 无技能调用工具：「触发技能」= 读 `.agents/skills/<name>/SKILL.md` 全文并执行；`${CLAUDE_SKILL_DIR}` / `!命令` 需按 AGENTS.md「调用方式」表代入。
