## 1. 模式与规范化 Brief

本轮目标不是继续细化 Discord-like 空间，也不是做可自由探索的 3D metaspace，而是建立一套可拍板的「双人放置陪伴 / cozy study-with-me」视觉基线：固定近景机位、两只原创长耳小狗常驻、场景物件即功能入口、UI 只作为薄玻璃壳存在。

不可违反的视觉约束已统一为：

- 场景占主导，默认态不出现大型功能面板；最左侧仅保留极窄 rail。
- 男主为蓝耳、女主为粉耳；两者必须同时可见、动作可在 1 秒内读懂。
- 角色采用原创奶油/浅棕脸部块面、锥形垂耳、眉斑与围巾识别，不使用三丽鸥角色的纯白云朵轮廓、脸部比例或标志性造型。
- 功能由日记本、相框、电话/信箱、挂钟、唱片机、许愿罐六类实物映射；默认态只用低干扰光环提示。
- UI 外壳随时辰从近白递进到石墨；内容白纸始终是全场最高明度。
- 图内 UI 不渲染真实文字，只保留 blank 占位和安全区。

## 3. Executive verdict

**建议拍板：以“近景固定房间 + 双角色常驻 + 点击物件 + 按需白纸功能层”为主产品构图；桌宠小窗作为并列入口，而不是主界面的缩小复制。**

这套方向比全屋等距方案更符合私密陪伴：角色脸部在缩略图中仍可读，蓝/粉双方通过不同动作形成“共同在场、各自生活”的关系，而不是把用户注意力消耗在房间导航上。六张概念图已形成完整状态链：默认晨景、同构图夜雨、桌面小窗、功能打开、动作参考、Presence 对照。

可见验收结果：

- 主界面晨景与夜雨采用同一几何构图、同一角色姿态和同一六热点位置。
- 晨景 rail 平均相对亮度约 **137.2/255**，夜雨 rail 约 **24.9/255**；近白到石墨的递进明确。
- 功能打开态中央纸面平均相对亮度约 **236.5/255**，后景约 **42.5/255**；“功能为纸、场景退后”的层级成立。
- 小窗概念把 640×400 比例的挂件放在真实桌面右下角，角色脸部占小窗主要高度，只有两个热点和一个空白聊天气泡。
- Presence 对照无需文字：左侧空椅 + 留灯/围巾表示离线，右侧角色出现 + 单个绿色点表示在线。

亮度数据为对输出 PNG 固定区域的像素抽样（Rec.709 加权平均），用于验证方向，不代表最终设计 token。

## 5. Detailed findings with observed evidence

### 5.1 主构图：关系比空间更重要

主画面采用单房间近景而不是全屋切面。蓝耳角色在左下软椅、粉耳角色在右侧书桌，两者面部尺度相近，中间由台灯、桌沿和视线形成三角连接。用户首先看到“他在读、她在写”，其次才看到可点击的房间物件。这比参考图 2 的多层空间更符合“只有两个人”的产品事实。

建议将运行时相机固定在这类中近景，角色头部高度至少占应用内容高度的约 24%–30%；不要提供 WASD、镜头拖拽或滚轮缩放，因为这些交互会把产品重新解释成探索游戏。

### 5.2 物件到功能的无文字映射

晨/夜主画面统一保留六个热点：

| 物件 | 功能推断 | 当前可猜性 | 建议 |
|---|---|---:|---|
| 打开的日记本 / 书桌 | 时间线日记 | 高 | 作为首次引导的第一个示范热点 |
| 墙上相框 | 照片库 | 高 | 点击后可用相框轻微前倾/闪光确认 |
| 转盘电话 | 聊天 | 高 | 比床头手机更具场景辨识度，但要验证年轻用户是否仍理解“电话” |
| 挂钟 | 时钟 / 闹钟 | 高 | 夜间不要让钟面热点与环境高光混在一起 |
| 唱片机 | 共享音乐 | 高 | 唱针动作可作为播放 Presence |
| 星光许愿罐 | 心愿单 | 中高 | 视觉记忆点最强；应避免把它误解成通用奖励货币 |

热点使用白色细环和小中心点，没有文字标签。它们在概念图中足以验证安全区；正式产品应默认静止，仅在悬停、键盘焦点或首次发现时呼吸一次，避免六个点持续闪烁造成“找物游戏”感。

### 5.3 时辰明度递进

清晨版的 near-white rail 与窗光同属明亮材质，但没有超过内容纸；夜雨版严格保持构图，把 rail、边框和环境压到石墨，角色仍由台灯和许愿罐的暖光托住。配对图的变化集中在窗口、室内色温和玻璃外壳，没有新增夜间专属控件，因此可以作为主题 token 与场景灯光分别实现的视觉基准。

正式落地风险是“同时变暗”导致交互图标低对比：夜间白色 rail 图标应以 WCAG 对比作为实现检查，但场景内装饰不必机械追求文字级对比。

### 5.4 小窗不是缩小的主应用

桌宠小窗移除了 rail 和大部分房间，只留下两张脸、书、咖啡和聊天气泡。它借鉴 Desktop Mate 的“大轮廓、低 UI”以及 Rusty's Retirement 的桌面占位思路，但保留 Our World 最关键的双人关系。小窗外的壁纸和任务栏被主动虚化，只用于说明 always-on-top 语境，不代表具体 OS 实现。

640px 宽下应坚持最多两个热点；任何时间线、播放列表或聊天记录都应在点击后跳回主应用或展开独立白纸，而不是塞进小窗。

### 5.5 功能层级：纸面最高亮

时间线打开态只有一张居中纸卡。背景房间仍可识别蓝耳和粉耳位置，但通过暗幕与景深退出工作层；纸卡内部仅显示时间线路径、圆形头像位、图像占位和底部 composer 安全区。此方案把功能内容从“漂浮 HUD 小窗”升级成稳定阅读表面，同时保留情感场景作为来源语境。

建议默认纸卡宽度保持在舞台宽度 54%–60%；超宽屏可增加外部留景，不要无限拉宽纸面。

### 5.6 Presence：空位留痕优于灰色替身

离线态不把粉耳角色变灰，也不显示半透明幽灵，而是保留她的座位、杯子、围巾和一盏灯。这样传达“她暂时不在，但这个位置属于她”，情绪仍然温暖。在线态让角色回到同一位置并只增加一个绿色点，状态差异集中且可逆。

当前概念中的绿色点靠近椅背与头部上方，正式稿应把锚点绑定到角色头部骨骼或姓名牌安全区，避免被误读为椅子/物件状态。

### 5.7 原创角色边界

本轮角色通过奶油与浅棕头部斑块、眉色、围巾、锥形垂耳和更具毛绒质感的四肢区别于用户点名需要避开的授权形象。尽管如此，“白色小狗 + 蓝/粉长耳 + 极简五官”本身仍接近拥挤的视觉语义区。量产前需要继续扩大原创差异：稳定保留不对称眉斑、围巾结、耳尖色阶和更明确的身体比例，并做一次人工 IP 相似性评审。

## 6. Uncertainty and comparability limits

- 竞品截图来自不同版本、房间皮肤、视口和营销选择，UI 密度只代表公开截图中的典型状态，不是对所有运行状态的穷举。
- 本轮没有实际运行或录制五款竞品，因此对动画节奏、hover、键盘导航和长时间观看疲劳不做结论。
- 参考图 1 是近景应用概念，参考图 2 是全屋等距氛围图，两者内容尺度不同，不能用像素级评分直接判优。
- 六张产物是 AI 辅助的方向稿，不是可直接切图上线的 UI、Live2D rig、逐帧 spritesheet 或无障碍验收稿。
- 小窗图是在 1536×1024 桌面截图中表达 640×400 比例感；尚未做真实 640px 位图缩放、125%/150% OS 缩放和低 DPI 线宽测试。
- 晨/夜是静态帧，未验证光照跨时段插值、雨滴动画、性能或 burn-in。
- UI blank 占位遵守本轮安全区要求，因此没有验证真实中文内容、极端长文本、照片纵横比或滚动状态。

## 7. Recommendation and next actions

拍板建议如下：

1. 以 `01-main-morning.png` 为新的首页构图基线，以 `02-main-night-rain.png` 为同构图夜间主题基线；停止继续深化全屋等距 / 自由镜头方向。
2. 将 `03-desktop-widget.png` 定义为独立产品形态：角色近景、最多两个热点、一次只出现一条聊天气泡；不复制主应用 rail。
3. 采用 `04-timeline-open-state.png` 的单张白纸层级，内容纸宽控制在舞台约 54%–60%，场景暗幕和 blur 分开调节。
4. Presence 采用“离线空位留痕、在线角色回归 + 单绿色点”；不要用灰色睡眠角色同时承担离线语义。
5. 动画优先级建议从高到低为：呼吸/眨眼 idle、翻页、喝咖啡、趴睡、挥手、倒咖啡。倒咖啡涉及双手与液体接触，制作风险最高，可后置。
6. 进入实现前做三项硬验证：把主画面缩到 960px 宽看角色表情；把小窗真实缩到 640×400 看眼睛/嘴线；用夜间最低亮度屏幕检查蓝耳轮廓与 rail 图标。
