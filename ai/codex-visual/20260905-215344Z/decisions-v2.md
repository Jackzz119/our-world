# Timeline v2 最终设计决策备忘

> 决策人：Codex（基于原三方向比稿，接收 Claude 独立复核后重新裁决）  
> 日期：2026-09-05  
> 状态：**设计已定稿，尚未进入产品代码实现**  
> 适用范围：Timeline 的 v2 信息架构、静态形态、开合方式、响应式尺寸、作者色与相关 token 归一

## 结论先行

Timeline 的最终产品形态是 **「我们的日记」**：采用方向 3 的窄幅前视白纸结构，借方向 2 的物件起点做 220ms 开场，但打开后不保留跨场景连接线。页面略偏左，让两只房间角色继续留在同一画面；内容仍是上旧下新的单列日记流。

回忆条目保持白底，不使用淡蓝/淡粉气泡底。作者身份只通过头像光环、作者名与 3px 左边线表达。照片墙、心愿单退出三 tab，分别由相框与许愿罐打开自己的功能页。

`--accent-deep` 的规范值固定为 `#2F9AD3`。当前 CSS 中的 `#268FBE` 及按 mood 覆盖的深蓝属于待实现阶段清理的漂移，不在本轮改代码。

## 一、对 Claude 六条复核发现的回应

### 1. 明度层级：接受，但修正验收表述

接受复算结果。三张稿都证明「纸是全场最高明度」，这是本功能最重要的视觉层级。

右墙被台灯照亮后比石墨 rail 更亮并不是问题。场景里允许存在局部高光，不能把「壳 > 场景」误写成每个像素都必须成立。正式验收改为：

- 内容纸必须明显高于它周围的壳与场景；
- 中性外壳不得比内容纸抢眼；
- 角色脸部可以被暖灯托亮，但不能白到和纸面连成一片。

相对原报告的变化：成功标准从严格的「纸 > 壳 > 场景」改成「纸始终第一；壳与场景按局部光照自然交错」。

### 2. 方向 3 图宽与规格矛盾：接受，图不再作为尺寸真源

方向 3 成图中的白纸约 369px，只能证明构图关系，不能直接当生产尺寸。它的正文、16:10 图片和 composer 都偏挤。

最终尺寸改为三个明确值：

| 验收视口 | 纸页宽度 | 页面水平位置 | 高度策略 |
| --- | ---: | --- | --- |
| `≥1200px`（以 1440×900 验收） | **504px** | 舞台中心向左偏 **40px** | `min(760px, 可用高度 - 48px)` |
| `768–1199px`（以 960px 宽验收） | **432px** | 舞台中心向左偏 **16px** | 可用高度减 32px |
| `≤767px`（以 640×400 验收） | **288px** | 居中，不偏移 | **376px** |

这三个值都只是初始规格。真实书房经过 cover-fit 裁切后，如果角色安全区不通过，应优先把纸页缩窄 16px，而不是让页面全屏或把角色裁掉。

相对原报告的变化：废弃 `560–590px / 460–500px / 260–280px` 的范围写法，改为 `504 / 432 / 288px` 三个可直接验收的值。

### 3. 蓝粉条目底色：接受，并比 Claude 建议更严格

接受「淡色底会把日记读成聊天线程」的判断。三张方向图里的蓝粉底是生图为了强化作者区分而带出的视觉偏差，不进入产品规格。

最终规则：

- 条目底色固定使用与页面相同的纯白纸面；
- 默认态不允许作者色铺底，包括所谓 `≤6%` 的淡色底；
- 作者色只落在头像光环、作者名和 **3px 左边线**；
- 条目之间靠留白、日期贴和 `--paper-line` 发丝边界分组；
- hover/focus 只允许中性纸面反馈，不使用作者色填充。

这样能保留两人身份，又不会长成聊天气泡。

相对原报告的变化：删除「边线/浅色底」中的「浅色底」选项。

### 4. Token 双真源：接受，并裁定固定品牌值

接受。D-9 已把品牌深蓝定为 `#2F9AD3`，`--accent-orb` 的尾色也使用该值；根 token 的 `#268FBE` 是漂移，不应反过来覆盖已拍板的品牌值。

最终规则：

- `--accent-deep` = **`#2F9AD3`**，跨 mood 固定；
- 纸面上的「我」、focus 边界等品牌深蓝都使用该固定值；
- 若夜间外壳需要更亮的蓝以保证对比度，另建语义明确的 shell 专用 token，不能继续覆盖 `--accent-deep`；
- 本轮只把目标值写进设计真源，CSS 迁移与对比度复测放到实现阶段。

相对原报告的变化：不再把「保留 `#268FBE`」列为等价选项，也不允许 `[data-mood]` 改写品牌深蓝的语义。

### 5. 角色可见性：接受，并升级为硬验收

方向 2/3 的角色保留明显优于方向 1。最终页面必须同时保留两张脸的可辨识部分；仅看见耳朵、手或身体不算通过。

方向 1 不作为默认回退稿。即使工期紧，也只能借它的简单平纸实现，不能借它的居中遮挡比例。

### 6. 生图文字与 CSS 可实现性：接受

方向 3 第三条空白不代表空内容设计。三张 PNG 都只是视觉方向证据，不是 CSS 可实现性证据。

最终验收必须使用真实组件、真实 `cinnaglass.css`、真实中文文案和真实数据截图；再做像素明度、角色露出、对比度和小窗检查。

## 二、六个决策点的最终裁决

### 1. 形态与开场

**裁决：方向 3 的静态结构 + 方向 2 的起点感，但删除打开后的长 tether。**

这里的 tether 指图中从纸页连回桌上日记本的长虚线。它在静态画面里更像讲解图的标注线，会穿过场景并增加持续噪声。

最终形态：

- 一张前视、平直、略偏左的白纸；
- 背后只露 6–8px 封皮边；
- 右下保留折角和一段 16–22px 的短书签尾；
- 不保留跨场景虚线、绳子或持续动画；
- 打开时从真实日记本热点出发，220ms 内完成 `缩小起点 → 轻微展开 → 落稳平纸`；
- 关闭时 160–180ms 收回来源，减少完整反演带来的拖沓；
- reduced motion（减少动态模式）只做 120ms 透明度变化。

相对原报告：保留方向 3 与方向 2 混合路线，删除静态 tether，把「物件来源」主要交给开场、封皮边和短书签尾。

### 2. 命名

**裁决：界面标题用「我们的日记」，不采用「回忆日记」；内部 route/type 继续叫 `timeline`。**

「我们的日记」直接表达双人共同拥有，读起来也比「回忆日记」自然；「回忆」已经由内容、日期和照片表达，无需再塞进标题。物件 hover 文案可简写为「翻开日记」。

相对原报告：从「回忆日记」改为「我们的日记」。

### 3. 是否拆三 tab

**裁决：拆。三个物件对应三个独立 surface，不在页面内互切 tab。**

surface 指由一个房间物件打开的功能页：

- 日记本 → 我们的日记；
- 相框 → 照片墙；
- 许愿罐 → 心愿单。

三者可以复用同一个底层页面壳和数据 hook，但用户看见的是三个入口、三个标题、三个独立关闭路径。rail/更多只作为效率入口，打开的仍是同一份物件页面，不创建第二套界面。

相对原报告：不变，但补充「复用实现不等于共用 tab」的边界。

### 4. 卡片底色

**裁决：白卡，不允许作者色铺底。**

条目与母页都属于 PAPER 色域。卡片使用纯白、1px `--paper-line` 和极轻贴地影；身份只用头像光环、作者名、3px 左边线。图片帖仍让 16:10 首图成为主视觉。

相对原报告：从允许浅色底改为明确禁止蓝粉底。

### 5. 纸宽

**裁决：504 / 432 / 288px。**

这组值在桌面给正文和图片足够宽度，在 960 与 640×400 又保留两侧角色安全区。宽度不是按整窗百分比无限增长；超宽屏仍封顶 504px，让日记保持私人、窄幅的阅读感。

相对原报告：用精确三断点取代范围；方向 3 PNG 的 369px 仅作构图参考。

### 6. Token 统一值

**裁决：`--accent-deep: #2F9AD3`。**

相对原报告：从二选一建议升级为唯一规范值；夜间外壳若需要亮蓝，必须另起 shell 语义 token。

## 三、最终设计结构

### 1. 层级

```text
真实房间与两只角色
└── 单层场景降噪幕（scrim：压暗与轻微模糊，不是一个可见面板）
    └── 我们的日记（单张 PAPER 白纸，无玻璃外壳）
        ├── 标题 / 关闭
        ├── 往上翻更早
        ├── 单列回忆流（上旧下新）
        └── Composer（固定在页底，展开时向上生长）
            └── PostDetail / Lightbox（需要时在日记之上临时出现）
```

### 2. 页面形态

- 圆角：22px；compact 降为 18px；
- 页面边框：1px `--paper-line`；
- 页面阴影：沿用 `--paper-shadow`，不增加蓝色外发光；
- 封皮露边：桌面 8px、960 为 6px、640 为 4px；
- 折角：只在桌面与 960 保留，640 删除；
- 书签尾：使用 `--blush`，面积小，不承担作者身份；
- 页面里不出现第二层 `.glass`，也不加 tab bar 或额外吉祥物。

### 3. 回忆条目

- 单列、上旧下新；
- 正文至少 15px，行高约 1.65；
- 日期贴负责章节分组，不使用中央脊线；
- 头像继续像贴纸一样挂在条目左上，但 compact 可收进条目头部以节省横向空间；
- 文字条目纯白，图片条目首图 16:10；
- 长文 6 行截断，完整内容进详情；
- 条目 hover 只轻抬 2px，不改变作者色面积。

### 4. Composer 与关闭规则

- 折叠高度维持 40px；
- 无草稿显示「记录此刻的我们…」；有草稿显示首行预览和图片数；
- 点击纸内空白只收起 composer，不关页面；
- 点场景幕关闭页面但保留草稿；
- Esc 顺序：详情 → composer → 日记页；
- 「取消」是唯一主动清空草稿的入口，发布成功也会清空。

## 四、对原报告规格的修订

### 4.1 修订后的 token 目标

保留：

- `--glass-paper: #FFFFFF`
- `--paper-text: #22335A`
- `--paper-sub: #667087`
- `--paper-line`
- `--paper-shadow`
- `--accent: #59C5ED`
- `--accent-grad`
- `--accent-orb`
- `--blush: #FDD5E7`
- `--stage-content-scrim`

统一或新增的目标语义：

- `--accent-deep: #2F9AD3`，固定品牌值；
- `--shell-accent`，仅在外壳确需随 mood 调亮时使用，值在实现阶段用真实对比度确定；
- `--stage-content-blur: 5px` 与 `--stage-content-brightness: .82`，让模糊和压暗可独立退化；
- `--object-open-duration: 220ms`；
- `--object-open-ease: cubic-bezier(.22,.9,.3,1)`；
- `--author-partner-deep: #D97A96`；
- `--author-partner-ring: rgba(239,157,180,.85)`。

删除：

- `--diary-cover-edge` 的新颜色提案。封皮边先从既有 PAPER 阴影、`--butter` 与场景素材取关系，不为 6–8px 装饰额外制造品牌色；
- 静态 `.diary-tether` 原子；最终没有跨场景 tether。

### 4.2 修订后的组件映射

| 现有位置 | 最终职责 | 实现阶段动作 |
| --- | --- | --- |
| `SubScreen` | 不再是三 tab 容器 | 拆成无 tab 的通用 ObjectSurface，日记/照片/心愿各自挂载 |
| `TimelineBody` | 我们的日记内容核心 | 保留数据与滚动，只换宿主和条目视觉 |
| `Composer` | 页底写字区 | 保留全部草稿与多图逻辑；响应式收窄 |
| `PhotosBody` | 相框独立页面 | 复用 feed/签名，不再属于 Timeline tab |
| `WishlistBody` | 许愿罐独立页面 | 保留数据，迁入自己的 surface |
| `PostDetail` / lightbox | 日记上的临时详情层 | 保留渐进原图；接入统一 Esc/focus 栈 |
| `WorldPage` | 记录入口来源 | 从单一 screen 字符串升级为 screen + origin + source，不改变业务数据 |
| room hotspot | 物件因果起点 | 回传真实点击坐标；键盘入口回落到热点中心 |
| `cinnaglass.css` | token 与共享原子真源 | 实现期统一 deep accent、拆 scrim 参数、新增 object surface 原子 |

明确删除：三 tab、宽屏云朵吉祥物、`.modal.tall` 对日记的依赖、静态长 tether。

完成门槛：三个物件只打开自己的页面；日记没有玻璃外壳；原功能无回归。

## 五、仍需用户本人拍板的事项

### 不阻塞实现的偏好项

- **是否把照片墙、心愿单的完整视觉重做并入同一开发批次。**本备忘的默认裁决是：本次只完成三者结构拆分与独立 surface 适配；Timeline 精修到最终视觉，照片墙/心愿单保留当前内容设计，另开比稿再重做。若希望三页一次全部翻新，这是明确的范围扩大，需要用户决定排期。
- **文案口味。**默认标题已经裁定为「我们的日记」。若用户本人更偏爱「回忆日记」，只改显示文案即可，不影响任何结构或数据。

除此之外，本轮六个核心设计点都已裁决，没有需要继续等待的阻塞项。
