- **模式**：Audit（实现审核）

## 5. 分区域详细发现

### 5.1 Rail

**直接观察**：target 短 rail 比 reference 长 rail 更少占屏，这一有意改动确实让窗边和沙发完整露出；上下圆帽与外框边缘也干净，没有可见裁切。问题不在“短”，而在短 rail 内仍塞入约 9 个入口，且 glyph、按钮板、状态反馈同时缩弱。reference 的每个图标都有约 44px 的独立玻璃按钮语法，target 则更像一列无标签工具图标。

**判断**：方向可保留，但应先减入口、再放大识别与命中，而不是继续缩图标。当前 rail 是高优先级收敛项。

### 5.2 右上纪念卡

**直接观察**：target 的真实数据完整呈现：在一起 432 天、距纪念日还有 298 天；没有文字溢出、重叠或裁切。其信息密度高于 reference，但蛋糕、心形和明确分区被移除，两个数字的层级差不足。

**判断**：内容正确、布局可用，属于“信息实现成功、情感与层级不足”，不是功能 blocker。

### 5.3 Presence

**直接观察**：target 有姓名、绿点和陪伴文案，状态语义比 reference 的占位线更明确；但空间位置贴近墙上相框而不是角色，视觉上不构成“角色头顶状态”。

**判断**：文字方案值得保留，位置锚点必须优先修。对这个产品而言，presence 的空间关系比装饰性玻璃更重要。

### 5.4 音乐迷你条

**直接观察**：target 在右下角非常克制，无裁切并保住唱片机画面；但从 reference 的完整 mini player 缩成约 38px 高后，媒体身份几乎只靠播放三角猜测。短横线同时可能被理解为进度、音量或装饰。

**判断**：这是“场景占用感”与“持续状态可读性”的失衡。建议恢复有限信息，不必恢复 reference 的 438px 大条。

### 5.5 玻璃、圆角、明度

**直接观察**：target 全部壳体在圆角和边缘收纳上是统一的深色方向，没有突兀白卡；但透明借色、磨砂、内高光和面板内分层都明显弱于 reference。外层大圆角框还把整个场景包成一个深色显示器窗口。

**判断**：符合“深色”，尚未充分符合“石墨玻璃”。应从材质层与前景色同时修，不建议仅提升整体 opacity 或亮度。

### 5.6 场景是否仍是主角

**直接观察**：是。target 默认态 UI 只占四周极小面积，角色、书桌、许愿罐与窗景保持完整，且没有面板遮住任何角色。相较 reference，target 的 UI 占用明显更低。

**判断**：这一点已通过，并且是实现最明确的优势；但“主角”不等于“越暗越好”。下一轮应提升关键 UI 可读性和角色局部亮度，而不必增加更多常驻面板。

### 5.7 Reference 可见、target 截图未见的元素清单

下列是**单帧可见差异**，不等同于断言代码中完全没有：

1. 右边缘换房 chevron/tab。
2. 许愿罐金色 hover/热点描边，以及 heart/star 浮动气泡。
3. 粉耳角色旁的省略号聊天气泡。
4. rail 单项圆角按钮底板、明确选中态；reference 的购物袋/装扮入口在 target 没有同形图标。
5. 纪念卡的蛋糕插画、独立心形标记和清晰可见的 eye 控件；target 用小日历与疑似隐藏图标替代。
6. 音乐条的唱片封面、曲名/状态双行、大型暂停按钮、分隔线和明确的收起按钮结构。

以下不列为缺陷：房间三缩略横条、左下聊天卡、顶部展开天气矩阵，因为 brief 已说明 target 默认收起且交互已实现。

## 6. 不确定性与可比性限制

- 两图宽高差仅约 1%，纵横比一致，整体位置、占屏和相对尺度可直接比较；但不是同一像素尺寸，文中坐标均为近似观察值。
- reference 是概念稿，含占位文字、夸张玻璃和多个展开态；target 是真实数据、默认态，因此不能要求面板数量或文字内容逐像素一致。
- 两图的场景渲染亮度、颜色和局部绘制也不同；场景亮度判断只用于层级/可读性，不作为资产还原度评分。
- 单张静态截图无法验证 hover、focus、触屏、点击热区、动效、自动淡出、展开面板、键盘可达性、`prefers-reduced-motion` 或真实背景模糊。因此“未见”只表示截图状态未呈现，不能证明实现完全缺失。
- 未进行正式 WCAG 对比度计算；关于低对比度的结论属于基于真实像素的视觉启发式，下一轮应以像素采样和浏览器实测确认。

## 7. 建议与下一步

按收益顺序执行：

1. **先修 presence 锚点**：下移并绑定角色头部，完成后先截同画幅复核。这是最小改动、最大产品收益。
2. **重构 rail 信息架构与单项尺寸**：一级入口减到 4–6 个，glyph 18–20px，40–44px 按钮框，补选中/未读状态；保留居中短胶囊。
3. **把音乐条恢复为“可识别的 mini player”**：至少提供媒体身份、明确播放状态和一个可靠主控。
4. **统一三档 glass 壳体 token**：补磨砂、借色、内高光与三档前景色，然后在夜景最低亮度下实测 rail/音乐/纪念卡。
5. **第二轮再做情感抛光**：纪念卡数字层级、蛋糕/心形情感锚点、物件热点首访/hover 提示、角色局部暖光。

验收建议：保持 target 当前 1600×1000 默认态，再补一张“所有可召回组件展开”的同画幅截图；两张分别审核默认占用感和交互完整性，避免把收起态的干净误判为功能缺失。
