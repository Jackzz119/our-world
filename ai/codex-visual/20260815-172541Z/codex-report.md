# 闪光粒子交互提示设计报告

## 1. Mode and normalized brief

- 模式：`design`
- 目标：在书房场景的五个功能物件上，用克制的暖金色四芒闪光替代白色细环等 UI 化提示。
- 热点：日记本、置物架相框组、挂钟、唱片机、星光许愿罐。
- 整体稿：1586×992，五个热点共 8 颗可见粒子；不添加环、框、badge、标签或物件光环。
- 细节稿：1024×768，日记本与许愿罐近景；下方以 5 个无文字样本展示出现、成长、峰值、衰减、消散。
- 视觉要求：粒子属于场景内的魔法微光，主色接近 `#FFE6B5`，与台灯和许愿罐共用暖光色温；单颗视觉包围盒约 6–16 px。

交付方向成立。整体稿的闪光与台灯、许愿罐处于同一暖金光族，最亮粒子的面积很小，仍由场景和物件主导画面；8 颗的上限密度足以暗示“这里有东西”，又没有形成 UI 标记阵列。细节稿明确给出了四芒星的结构以及五段生命阶段，可直接作为程序粒子的调参视觉基准。

推荐把两张图作为动效与实现规格，而不是替换现有底图：运行时继续使用原始无提示场景，通过 PixiJS 粒子层叠加微光，可避免生成式编辑产生的细微底图漂移，并能真实实现随机节奏。

## 5. Detailed findings with observed evidence

### 5.1 整体场景

- 直接观察：相框组、挂钟、日记本、唱片机和许愿罐均获得局部星光，没有在非热点区域形成连续轨迹。
- 直接观察：星光主要由细长水平/垂直芒、紧凑亮核和轻微暖色晕组成；轮廓不依附屏幕坐标，也没有统一大小的标记感。
- 直接观察：最亮位置与原图的台灯、许愿罐暖光相容；蓝紫暗部没有出现冷白或霓虹色污染。
- 直接观察：全场同时可见 8 颗，已经是建议硬上限；常态运行不应长期保持该密度。
- 推断：因为粒子位于物件边缘、书页、玻璃接触处和唱片机机身附近，用户更可能把它理解为物件自身冒出的微光，而不是覆盖式 UI。

### 5.2 粒子形态

- 直接观察：峰值样本是四芒星，纵横主芒明显长于斜向杂光，中心核最亮，外圈只有低对比暖晕。
- 直接观察：下方 5 个样本由左至右呈现微点、短芒、全亮、缩小余晖、离散微尘，形态与透明度共同表达阶段变化，不依赖文字。
- 直接观察：消散段保留 1–2 个分离微尘，可避免单纯做缩放淡出时产生“UI 图标 fade-out”的感觉。
- 推断：运行时加入轻微尺寸、旋转和间隔抖动，会比固定循环更像自然出现的星尘。

### 5.3 程序粒子参数建议

| 参数 | 建议值 | 说明 |
|---|---:|---|
| 单颗视觉包围盒 | 6–16 px | idle 峰值不超过 16 px；中心亮核约 1.5–3 px。 |
| 主芒比例 | 长芒为包围盒 70–90%；短向厚度 1–2 px | 使用窄、尖、略带手绘不对称的十字芒。 |
| 颜色 | 核心 `#FFF8E8`；主芒 `#FFE6B5`；外晕 `#FFC978` | 外晕只用于低透明度混合，不应出现橙色实心块。 |
| 生命周期 | 1.6–2.4 s，随机抖动 ±20% | 避免所有热点同步呼吸。 |
| 阶段占比 | 出现 0–22%；全亮 22–48%；消散 48–100% | 峰值短、尾段长，形成安静余韵。 |
| Alpha 曲线 | `0 → 0.18 → 0.88 → 0.62 → 0` | 建议关键点：0%、12%、30%、48%、100%；使用 ease-out 出现、ease-in 消散。 |
| Scale 曲线 | `0.35 → 0.75 → 1.0 → 0.72 → 0.25` | 消散阶段同步缩短光芒，并把 1–2 个 dust mote 向外漂 2–5 px。 |
| 旋转 | 基准十字 ±4° 随机 | 不持续旋转；每次生成只选一个轻微偏角。 |
| 每热点同时数量 | 常态 0–1；日记/许愿罐可偶发 2；hover 最高 2 | 全局硬上限 8，常态目标 3–6。 |
| 生成间隔 | 每热点 3.5–8 s 随机 | 同一热点连续生成至少间隔 1.8 s；使用去同步随机种子。 |
| 漂移 | 0–3 px，向上或沿物件表面切向 | 主体应像原地闪烁，不做明显飞行轨迹。 |
| Blend | `screen` 或低强度 `add` | 建议先用 screen；add 容易把许愿罐局部烧白。 |

### 5.4 Hover 建议

- 指针进入后 120–220 ms 内，在热点最具识别性的边缘生成 1 颗 12–16 px 峰值星光，再补 1 颗 6–8 px 微光；不显示轮廓。
- hover 期间该热点生成间隔缩短到 0.9–1.4 s，Alpha 峰值最多提高约 10%，数量上限仍为 2；若全局已到 8，优先抑制其他热点的新粒子。
- 指针移出后不立即掐断，允许当前粒子按原曲线完成 0.6–1.2 s 的尾段，再恢复 idle 随机间隔。
- 不建议连续脉冲、同步闪烁或 hover 时整体物件发光；这些都会重新变成 UI 状态提示。

## 6. Uncertainty and comparability limits

- 两张交付图任务不同：整体稿用于密度与场景融合，细节稿用于形态与时序规格，不能按同一构图或粒子尺寸直接比较。
- 静态图片只能展示不同生命阶段的截面，不能验证真实节奏、hover 响应、帧率和长时间观看疲劳；这些需要在 PixiJS 运行态中验收。
- `sparkle-scene.png` 是基于参考图的生成式编辑，构图和内容高度保留，但不保证除粒子外逐像素完全相同。因此实现时应在原始底图上程序叠加，而不是把 mockup 当作新的生产底图。
- 6–16 px 是在 1586×992 设计基准上的 CSS/渲染像素建议；若场景响应式缩放，粒子应跟随场景缩放并设置屏幕空间最小值，避免小窗口下完全消失。

## 7. Recommendation and next actions

1. 以 `sparkle-scene.png` 作为全场密度和色温基准，以 `sparkle-detail.png` 作为纹理、亮核和 Alpha/Scale 曲线基准。
2. 在 PixiJS 中制作 3 张小纹理即可：微点、四芒峰值、余晖微尘；通过 scale、alpha、少量旋转和 dust 子粒子组合出完整生命周期。
3. 首轮运行态采用“常态 3–6、硬上限 8、每热点 0–1”为默认，先进行 10 分钟静置观察，再微调生成间隔。
4. 用鼠标 hover、触屏首次进入和低亮度夜间三种状态验收；任何需要依靠环框才能找到热点的情况，应优先调粒子频率和落点，而不是恢复旧提示。
