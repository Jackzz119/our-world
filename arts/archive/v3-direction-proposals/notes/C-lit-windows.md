## 1. 归一化简报与视觉验收点

只探索 C「灯火小楼」：真实的伴侣与朋友各住一间房，整栋剖面楼提供“大家在哪里”，进入房间提供“对方在回应我”。不评价另外两条未提供的概念方向。

- 五层街角小楼，咖啡馆计入五层，屋顶花园另计；蓝色雨夜与不同室内光源构成情绪。
- 人物为原创手绘 Q 版人类，小满、阿屿、圆圆、老K、七七复用身份特征；目标约 3.5 头身。群聚图明确六人，额外一人的身份作为本轮补充假设记录。
- 场景有前景遮挡、中景生活空间、远景空气透视；设计可拆成 2D/2.5D 层，不能把静帧当成已交付分层、骨骼或实时 3D。
- 桌面/手机保留 Cinnaglass 中性磨砂、薄浅边、暖金反馈和边缘停靠；中文短词优先。
- 互动必须产生社交结果：咖啡送达、给朋友浇花、敲墙收到回应、留下信物。无枯萎惩罚、维护门槛、排行或连续签到。
- 不使用物件热点光圈、发光描边、halo 或 pin；自然灯光、实体圆窗、UI 按钮边界、微小星芒不属于这些禁用提示。
- 七张图依次覆盖主视觉、桌面、双手机、群聚、编辑器、互动、分层与镜头。

用户此次 brief 优先于现行设计文档中的“双犬、固定单房间、物件作为功能入口”。仅继承本轮明确要求的产品铁律与 UI 语言。

## 3. 执行结论

**此方向值得进入最低成本动态样板：整栋楼的社交空间组织很强，单房间的直接回应也已画出来；尚不能据此断言解决了高质量真人陪伴。**

最强证据是 C1 的“不同活动、不同灯色、一个暗窗”和 C3 的“整楼找人 → 单房间挥手”。C2 让两位角色同时看向使用者，减轻旧双犬互相交流带来的旁观感。C4 说明第三、第四位朋友可以自然成为邻居或屋顶同伴。C6 给出物件活动的结果，已经超出“点唱片机打开播放器”的重复入口。

主要保留意见：最终画风更接近精细动漫绘景，彩铅/水粉粗颗粒不足；部分角色只有约 2.5–3 头身，C5 又略修长，跨图比例尚未统一。人物可爱，但成人年龄感和成熟吸引力弱于“高品质年轻人陪伴”的愿望。它是一个明确的取舍，不应借整体画面精致掩盖。

## 5. 逐图检查与制作说明

### C1 — 主视觉

![C1 主视觉](../img/C1-keyart.jpg)

**看见什么：** 五层可数；底层空咖啡馆、上一层老K做饭、中间小满绘画与阿屿吉他、上层圆圆游戏、顶层七七阅读与暗窗猫。连接墙的圆窗可见。屋顶有温室、花盆与灯串。近景伞/叶、楼体、远城形成三层，街道有破碎暖色倒影。无 UI、无犬角色。

**如何回应目标：** 房间位置、灯色与活动共同组织多人 presence，暖灯与蓝雨形成长时间观看的氛围。首稿屋顶被切，最终拉远后温室与主要花园完整，16:9 中央裁切能保留建筑主体，少量最高树梢属于边缘装饰。

**可见不足：** 楼景角色很小，无法在该尺度精确验收眼睛和首饰；它负责找人，不承担直接陪伴。场景细节接近精细 CG 绘景，手绘材质还不够统一。只有一处暗窗能示意离线，不能证明真实状态已接入。

**制作建议：** 天空/远城、街道、楼体骨架、五层房间单元、门窗前框、角色、室内光、雨、倒影、前叶伞约 10–14 类层。独立室内灯光遮罩，雨只在外部；倒影可用预绘贴图加低幅度扰动。远景角色使用低频 idle，进入房间才加载完整 Spine/Live2D 式 2D rig。压缩首载暂估 3–5 MB，不含所有高清房间。

### C2 — 桌面双房间

![C2 桌面](../img/C2-desktop.jpg)

**看见什么：** 两间房、两个主角、连接圆窗；两人看向镜头，阿屿举拳敲墙，一枚小心形表达回应。左轨恰好五图标且顺序正确；双圆、纪念卡、聊天、未读信封、音乐、五层邻居导航均可辨。中文“在一起 1221 天”“敲敲墙～”“悄悄话”等可读。

**如何回应目标：** 保留各自生活空间，又用眼神与墙上回应形成陪伴。UI 位于边缘，没有遮住脸。人物首稿偏正常长身，已单张纠正为明显 Q 版，并将长时间 pill 改回两枚圆钮。

**可见不足：** 地图高亮从上数第二层，与主视觉第三层的伴侣房不一致，属于中优先级拓扑问题；生产必须从同一房间数据生成。玻璃较平滑厚重，细纹不足。聊天卡较大且没有明显收起动作。猫出现在阿屿沙发上，说明它可以游走，不能把“猫出现”作为唯一离线判断。

**制作建议：** 房间后墙、两侧窗景、后置家具、角色、前置家具/绿叶、共享墙、独立光源、雨窗、DOM UI 约 10–12 类层。小满抬头/眨眼/落笔、阿屿敲墙与吉他手臂单独动画；共用骨架方向可行，但手、道具和前后遮挡须逐动作绘制。双房间近景按需资源暂估 3–6 MB，含两位角色，不与 C1 缓存重复下载。

### C3 — 手机楼景与房间

![C3 手机](../img/C3-mobile.jpg)

**看见什么：** 横画布放两部竖屏，左为五层建筑和姓名 chip/滚动提示，右为小满近景挥手、气泡和输入框；顶部双圆与纪念卡、底部音乐与五入口保留。右侧眼睛与手掌清楚，场景未被输入栏挡住脸。

**如何回应目标：** 将“找谁”与“陪着谁”分到两种尺度，避免手机始终只看极小人物。楼景保留纵向空间结构，近景优先表情与回应。

**可见不足：** 姓名小字只能支持概念阅读，不能用于生产文字资产。时钟简化到近似三叉针，需用正式 icon。输入/音乐/导航三排会在键盘弹出时挤压场景；静帧没有验证这一状态。小满近景比 C4/C6 更成熟，比例仍有差异。中间版左咖啡馆出现三位未定义顾客，独立复核判为错误 presence，已单图移除并再次查看像素。最终暗窗猫过小且难以辨认，不声称手机屏保留了清楚的猫。

**制作建议：** 建筑低清总览和房间高清近景分层级加载；只显示近邻房间的完整角色。房间后景/物件/角色/窗雨/前叶独立，玻璃用真实 UI。近景 rig 可从 16–24 个部件、挥手 4–6 个关键姿态开始。移动首载暂估 3–5 MB，进入一个房间追加 1–2 MB；键盘状态应收音乐、压缩输入区，再验证安全区与触摸。

### C4 — 六人屋顶

![C4 群聚](../img/C4-group.jpg)

**看见什么：** 恰好六位人类和一只黑白猫。小满星夹与奶油上衣、阿屿眼镜/深帽衫、圆圆白耳机/黄毛衣、老K毛帽/橄榄上衣、七七银发/黑上衣均可辨。第六位是本轮补充的栗棕卷发、雾蓝围裙朋友。温室、灯笼灯串、小烤架、实体色牌与一盆有星芒的盛花齐全。

**如何回应目标：** 多人不必同时挤在情侣房里，共享空间容纳各自活动；小满与阿屿仍看向使用者。色牌让植物具有主人，花的结果可成为礼物，未画枯萎或任务倒计时。

**可见不足：** 金色地面反光与星芒略强，久看可能抢脸。缩身修正后部分人物约 2.5–3 头身，成人感偏弱。色牌缺名字，静态画面不能知道全部归属，只能看出可区分。

**制作建议：** 远城/天空、屋顶地面、温室后层、盆栽与桌椅、六角色、前花叶、灯光、局部粒子约 10–14 类层。六人共用基础骨架，衣发 slot 换装；浇水、叶摆、猫尾和花朵反馈独立。共享环境暂估 2–4 MB，六位角色图集与骨骼共追加约 3–7 MB。动作优先做 idle、浇水、抬头，别一次生产完整动作库。

### C5 — 角色与房间编辑器

![C5 编辑器](../img/C5-avatar-room-creator.jpg)

**看见什么：** 左侧“发型/五官/穿搭”与完整小满预览、服装网格、六色 swatch、保存；右侧斜俯视房间、大家具预览、八格目录与完成。植物和灯是自然色半透明摆放预览，植物旁有手光标；初稿的绿色发光外缘已移除。没有物件选中圈或 pin。

**如何回应目标：** 自定义形象和私人房间都具备可理解入口，装修体现属于自己的家。较大的编辑 UI 是主动任务态，结束后恢复场景优先。

**可见不足：** 全身仍约 4 头身，比目标略修长。两预览物中灯具透明度较弱，容易与已放家具混淆。等距编辑镜头与楼景房间并非同一投影；要固定切镜头规则或额外资产，不能以一句“2.5D”掩盖。家具密度可能造成拖放遮挡。跨图下装有所漂移，五位的发型与上装一致，但尚未达到整套服装逐件锁定。

**制作建议：** 墙/地板/窗/固定结构 + 每件家具 sprite + 光照遮罩 + 人物换装 slot + DOM 目录。选中预览以程序化透明度表示，落位后成为普通家具；无需发光边。头像头发/上衣/下装用统一锚点与骨架，先限制少量可兼容组合。编辑器追加压缩图集/缩略图暂估 2–4 MB；同屏纹理内存目标可先设 24–48 MiB，再实测。

### C6 — 四个有社交结果的仪式

![C6 互动](../img/C6-interactions.jpg)

**看见什么：** 2×2 四格，标题“拉花咖啡”“帮你浇花”“敲敲墙”“信箱”。第一格同时出现倒奶画心和 302 门口送杯；第二格圆圆名字牌、浇水与星芒；第三格双方各在共享墙一侧举拳，飘小心；第四格有信封、合照拍立得和语音磁带。无物件光圈。

**如何回应目标：** 物件变化的终点是“对方收到/看见/回应”，不是打开现有导航页面。信箱把异步内容留在世界里，适合时差与离线。

**可见不足：** 阿屿拳头与墙略有距离，真实动画要做接触点；图中双人表情只能表达建议的结果，不能擅自用自动动画伪造对方回应。小满在该图的下装与 C2/C5 不完全一致。大眼短身进一步变幼。底部标题贴近画幅边，不能直接中心裁成 16:9。

**制作建议：** 咖啡杯/奶流/奶泡图案、花与水粒子、双侧敲墙动作、信封/照片/磁带分别独立。杯子交付可用短路径移动和接收动作；墙壁回应只由对方操作或明确的已录制回应触发，离线则留下轻量便条。录音播放属于用户留物，而非虚构实时交流。复用房间/角色后，新增道具与效果图集暂估 0.5–1.5 MB；音频另计。

### C7 — 模块与三段镜头

![C7 分层](../img/C7-scene-layers.jpg)

**看见什么：** 六个中文标签均存在，独立复核确认连接目标正确：房间单元、室内光源、外立面、雨层、街道倒影、天空。右边“整栋楼 → 楼层 → 房间”以三幅清晰度不同的图表达镜头接近，近景小满挥手。初稿外立面误指雨片，已精准纠正。

**如何回应目标：** 建筑可由房间 cell 拼装，住户变化不必重画整楼；光、雨、外墙与反射具有独立职责。房间近景比无限放大总图更适合加载高分辨率人物。

**可见不足：** 这是制作示意，尚无真正分层文件；天空板仍画有雨纹，生产必须把它清除，避免与雨层叠两遍。层间投影不构成精确工程尺寸。底部与顶部仍靠边，板应完整 contain 展示，不能宣称全图满足 16:9 裁切安全。

**制作建议：** 整楼低细节视图 → 楼层 → 近房间采用三档预绘资产与遮挡层，镜头过渡用平移/缩放/交叉淡化；只做小角度视差，不承诺围绕建筑自由旋转。景深先用预模糊背景，避开整屏高成本动态模糊。该板本身不进入运行时，预算由 C1/C2/C3 的共享图集承担。

## 6. 缺陷、修正与不确定性

| 严重度 | 证据 | 影响 | 具体处理 |
|---|---|---|---|
| 高，已处理 | 初稿 C2/C4/C6 明显长身，C5 荧光预览，C1 屋顶裁切，C7 外墙指线错误 | 偏离本方向与禁用规则 | 只对对应单图纠正，留档首稿，不整批重抽 |
| 高，已处理 | C3 中间版咖啡厅三位无身份人形 | 会被误读为真实成员 | 单图移除；最终楼景只见五位具名住户，右屏为同一小满的另一视图 |
| 中，保留 | C4/C6 很幼，C5 约 4 头身 | 同人跨屏成熟度和辨识不稳定 | 生产前统一成年 Q 版标准体、发型、下装和动作比例 |
| 中，保留 | C2 地图选中层与 C1 第三层不一致 | 导航理解可能错误 | 地图直接读房间位置，不手绘独立选中态 |

## 7. 制作预算与最低成本验证

以下全部为**工程起点估算，不是测速或已压缩资产的结果**，不能把这些交付 PNG 的字节数当运行时预算。

| 场景/增量 | 预计压缩传输 | 资源策略 |
|---|---:|---|
| 手机或桌面整楼首屏 | 3–5 MB | 小楼总览、少量房间缩略图、远景 idle |
| 单房间/双房间近景 | +1–2 / +3–6 MB | 进入才加载高清 cell 与完整人物 |
| 六人屋顶 | 环境 2–4 MB，角色合计 3–7 MB | 复用图集、裁掉不可见角色、控制粒子 |
| 编辑器 | +2–4 MB | 先少量衣装与家具，目录用缩略图 |
| 四种仪式 | +0.5–1.5 MB | 复用角色/房间，只新增道具和效果 |

以上不能简单相加：共享图集应缓存，视图退出可释放高分辨率资源。2048×2048 RGBA8 贴图解码约 16 MiB，完整 mip 链约 21.3 MiB，因此下载很小也可能占用较多显存。先给手机活动场景设约 48–96 MiB 的可观测纹理预算、桌面约 96–160 MiB，超出则降级分辨率/卸载邻房；这些只是待验证门槛。前台微动可从 24–30 fps 起，背景/不可见时暂停或大幅降频；不靠静帧保证流畅。

**最便宜的原型只做“一个窗、一间房、一次回应”。** 用总楼图作为远景，点击小满窗后切入独立房间层；小满做抬头、眨眼、挥手三个短动作。第二个真实账号发一条消息，近景气泡出现；敲墙由对方真实点击触发回应。用同一套手机 UI 检查键盘避让。暂不做六人动作库、任意换装、等距装修和四套小游戏。

邀请一对情侣或两位好友实际挂着使用，检查能否立即认出对方、是否知道当前在陪伴谁、是否感觉头像在回应自己；同时记录进入耗时、纹理内存、前台/后台负载。这个样板可以淘汰最关键的概念风险，不需要先量产整栋楼。
