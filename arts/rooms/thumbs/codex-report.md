# Codex 视觉交付报告

## 1. 模式与归一化 brief

- **模式**：Design
- **目标**：为「放置陪伴小屋」房间切换器补齐两张可直接使用、同时可作为未来房间概念预览的缩略卡。
- **输出规格**：PNG、768×512、3:2 横版；无 UI、文字、角色、动物、光环、边框与水印。
- **共同视觉要求**：沿用书房基准的水彩手绘、毛绒触感笔触、pastel 暖色、深蓝暮色环境与琥珀局部灯光；使用略俯视的固定机位和“房间一角近景”构图；缩至 120×80 后仍应一眼辨认房间类型。
- **棋牌室识别锚点**：中央方形绿毡棋牌桌、棋盘与散落棋子/牌块、四把木椅、桌上方暖吊灯。
- **植物园识别锚点**：清晰的玻璃温室骨架、中央绿植架、吊篮与花盆、透过玻璃可见的夕阳海平线。

生成路径采用 bundled `imagegen` skill 的内置 `image_gen`；两张不同资产分别生成，未使用 CLI/API-key fallback。生成后仅做高质量等比缩小到交付尺寸，没有改画面内容。

## 3. Executive verdict

两张图均达到交付条件，可作为 rail 展开态的房间概念缩略卡使用。棋牌室以“吊灯—棋盘—方桌”形成最强、最集中的识别链；温室以“玻璃斜顶骨架—植物架—海上夕阳”形成与书房明显不同的通透轮廓。两图在水彩颗粒、深色轮廓、暖木/陶盆材质和紫蓝暮色上与书房保持同一世界观，同时没有引入角色或 UI。

实际制作了 120×80 临时缩略预览并逐像素查看：棋牌桌轮廓、中央棋盘、温室斜顶与海平线仍清楚可辨。临时 QA 文件未列入交付并已清理。

## 5. Detailed findings with observed evidence

### 5.1 棋牌室

- **层级**：吊灯是最亮区域，光束自然落到棋盘；视线由灯罩向棋盘，再沿方桌四边扩散到椅背。主体没有被前景遮挡。
- **房型识别**：中央棋盘具有明确 8×8 几何感，桌边另有圆形棋子和骨牌状牌块；即使细小散件在缩略图中弱化，绿色方桌与中央棋盘仍足以表达“棋牌室”。
- **风格一致性**：木板、椅垫、窗帘、盆栽与画框都采用与书房相近的暗轮廓和手绘纹理；窗外紫粉天色与参考书房同属 twilight 档。
- **色彩证据**：64×64 像素采样的平均亮度为 35.0，低于书房参考的 45.3；暖色像素启发式比例约 50.2%，高于书房的 29.9%。这与“更集中、更暖的吊灯 + 大面积木桌”相符。画面整体更暗暖，但窗景保留了必要的紫蓝冷色制衡。
- **约束检查**：未见角色、动物、UI、文字、选择光环、边框或水印。

### 5.2 植物园/温室

- **层级**：深色玻璃屋架勾出大尺度轮廓，海上夕阳是远景光源，中央植物架与右侧工作台形成稳定的近景层次。
- **房型识别**：斜顶梁、连续玻璃窗格、吊篮、盆栽层架和园艺工具同时出现，明确是室内温室而非户外阳台；中央海平线强化“通透、户外感”。
- **风格一致性**：花盆、木架和叶片保留水彩颗粒与深色手绘边缘；紫蓝天空、桃粉夕光和暗暖木材与书房的暮色语言协调。
- **色彩证据**：64×64 像素采样平均亮度为 46.0，接近书房参考的 45.3；暖色像素启发式比例约 36.3%、冷色约 10.7%，后者与书房参考约 10.8% 几乎相同。该统计只验证整体色温关系，不替代视觉判断。
- **约束检查**：未见角色、动物、UI、文字、选择光环、边框或水印。

### 5.3 跨图一致性

- 两图均使用相同的 3:2 画布、略俯视近景机位、深色边缘定义、手绘颗粒与“冷环境 + 暖焦点”的 twilight 关系。
- 棋牌室偏封闭、暗暖；温室偏开放、明亮。这是由房间功能和玻璃采光造成的有意差异，而不是时辰不一致。
- 两图都把一级识别物控制在一个大形体簇内，适合放入参考 UI 的小卡，而未依赖文字或人物行为解释房型。

## 6. Uncertainty and comparability limits

- 参考书房和 UI 稿约为 1.60:1，而本次交付严格为 1.50:1；因此只能比较画风、光色和机位逻辑，不能逐边比较裁切或物件占比。
- UI 稿含角色、玻璃面板和选中态光效，新交付是纯场景底图；两者内容和任务不同，不应以 UI 稿的局部对比度直接衡量最终卡片在真实组件中的表现。
- 120×80 QA 验证的是房型识别，不代表所有显示器、浏览器缩放和玻璃遮罩下的最终对比度；集成后仍需在真实 rail 卡片中复测。
- 平均 RGB/亮度和暖冷像素比例是低分辨率启发式统计，会受黑边、窗景面积与构图影响，只能作为色彩一致性的辅助证据。

## 7. Recommendation and next actions

1. 两张图可直接进入房间切换器原型，建议保留当前完整 3:2 构图，使用 `object-fit: cover` 时避免额外裁掉棋牌桌四角或温室屋顶梁。
2. 在真实 rail 中以 120×80、选中与未选中两种状态复测；选中描边应放在组件层，不烘进图片。
3. 若后续制作四时辰版本，应固定当前几何和物件位置，只改变环境光、窗景与灯具强度，避免切换时画面跳动。
4. 棋牌室未来可在大图资产中继续细化棋子种类，但缩略卡不应增加更多散件；温室未来可把雨/雪留给独立天气层，不烘进底图。
