# 阿屿喝水姿势 R3：生产验收报告

## 1. 模式与归一化任务

- 模式：**design / 生产资产局部再生成**，不是概念设计。
- 从提供的 R2 a8 sip 图出发，将卫衣、下半袖自然续画至 y=968；保留 y<820 的人物像素。
- 1536×1024、8-bit RGBA、真实透明背景、人物内部完全不透明、底边水平且 y>968 无内容。
- 肩线首个 alpha≥128 像素：x=350/400/1150/1200 对应 y=590/541/553/593，容差±4。
- 底边最后一个 alpha≥128 像素：x=600/768/950 均须在 y=964–972。
- 睁眼最多八次；闭眼三张均编辑最佳 R3 睁眼候选，只改眼睑。
- 只使用内置 image_gen；没有调用 CLI/API-key 生图，没有裁切、拉伸、抠图、补像素、合成或光流修图。
- 本报告为同一 agent 的 MONET / MARIONETTE 自审；没有独立第二审核人。

## 6. 不确定性与可比性边界

1. 场景底图不是同尺度孤立人物，不能直接拿其像素坐标和姿势图逐像素对齐。y968及“plate y646注册”的关系来自caller，本轮采用为验收真值，未重新拟合运行时注册。
2. 未接入场景，未截图运行时；“露椅背”“跳帧”是由失败配准推断的风险，不是本轮实际运行观测。
3. PNG测量由自含Node/zlib解码器执行，支持输入的8-bit、非交错RGB/RGBA及五种PNG行滤波。没有外部图像库交叉复算；解码源码与原图一并交付，可独立复算。
4. 一个要求冲突：原始R2 sip图侵蚀后内部alpha均值为253.019，并非255。因此若“y<820完全相同”包含RGBA全部通道，就不能同时把该区域变成完全不透明。即使将冻结解释为仅RGB，本轮仍有颜色/几何重绘，不能放行。此处只报告冲突，没有私自放宽要求。
5. 闭眼prompt重复了指定的y968不变量，同时明确只改眼睛；选中的失败母图底边956，使这两项无法同时按原样继承。实际三张底边953–955，均如实拒收。
6. Shell执行器初始化失败（helper_unknown_error / setup refresh had errors），Python子进程也返回EACCES。改用可用Node工具读写文件和纯JS只读像素分析；未绕过审批、未安装依赖。工作树同步脚本未能执行，协议文件未修改。
7. 中途一次批量测量超时导致测量会话重置；所有已生成图片此前已复制落盘，随后用保存的验收模块重新测量并落盘证据。
8. 本轮只生成与验收原始资产；没有装配、网格、运行时或产品代码变动。

## 7. 建议与后续动作

- **生产决定：本批全部拒收，不晋升arts/source，不替换现有运行时。**
- 下一轮返工参考选a3；它在人物上方接近原母图的同时，底边距离目标12px。a4虽然两列多出1px，但上方重绘更多；a5上方较稳但底边过长；a8不因底边容差通过而获准。
- 在生成前先澄清“冻结RGBA”与“主体alpha255”的优先级，并在生成端确认存在可验证的区域锁定能力。维持当前纯生成规则时，不能承诺重复自然语言提示就会命中逐像素边界。
- 本轮已用满八次睁眼生成预算，不追加第九次，也未用修图凑够三个通过项。
