亮度定义是对 **sRGB 编码通道**做 `Y′ = 0.2126 R′ + 0.7152 G′ + 0.0722 B′`，范围 0–255，不做线性光转换。百分位在全部像素排序后取 `floor(0.01 × (N−1))`。它不是 WCAG 使用的线性相对亮度；不把这组数当成 UI 对比度测试。

最暗点位于原稿 **(x=1129, y=993)**，左上角为零点，RGB=(239,235,231)，Y′=235.5616；全图 1,572,516 个像素中仅该 1 个低于亮度 236。若把下限解释为每个通道均不得低于 236，则有 **44 个像素**至少一个通道越界。两种解释均没有被本稿严格满足。

**接缝与重复。** [offset-paper-tile.png](offset-paper-tile.png) 在横、纵各移 627px 后，中心没有显著亮度台阶或十字；细纤维不是逐根严格周期连续，不能据低反差外观声称数学意义上的完美周期。[tile2x2-paper-tile.png](tile2x2-paper-tile.png) 为 2508×2508，整体接近白纸，没有一眼抢出的重复地标。左右边界平均 RGB 跳变 1.2132，上下 1.7065，均为较低绝对值。

### 5.4 检查方法与运行问题

- 读取原生 PNG 的文件头与全部解码像素，尺寸不取自聊天预览。工具预览的木纹一度显示约 2048×688；此前进度口述使用了预览值，**此报告和 qa-metrics.json 已以真实文件头更正**。
- PNG 原稿均为 8-bit RGB；解码到 RGBA 后 alpha 全为 255。原始生成文件只复制，不重编码。
- 2×2 图用原像素重复四次；偏移图用模运算重排原像素。无插值、无色彩变换、无混合；10 张检查图已逐像素验证映射完全一致。
- 接缝数值是相对边缘对应像素的平均 RGB 绝对差，并附同方向内部邻接差；它只辅助定位异常，**不是通用的自动验收阈值**。粒状材料天然噪声会影响该比值，视觉检查仍是独立证据。
- 命令终端在执行任何 shell 命令前报 `helper_unknown_error: setup refresh had errors`；之后用可用的 Node 文件工具完成读取、复制与统计。sharp 动态导入不可用，使用已提供的 pngjs 解码与生成诊断 PNG；没有安装依赖、启用 API key 或转用 CLI 生成。
- 没有修改输出目录以外的仓库文件，也没有提交或接入运行时。内置生成器会自动保留默认目录中的原图；本目录含全部六张副本，SHA-256 与逐字节比对结果见 qa-metrics.json。

## 6. 不确定性与可比性限制

1. 指定的当前 UI 截图包含 CSS 色层、光照、纸框及有损图像，而本轮产物是未接入的原始材质，两者不能逐像素对比为同一成品。书房图有复杂实景照明，也不能直接拿桌面单点颜色当均匀扫描目标；本轮数值以 brief 的色值为准。
2. 提示词要求方图 2048×2048，工具实际两轮均返回 1254×1254；木纹返回约 2164–2167×726–727。当前工具接口只提供提示词与参考图参数，没有可设定的 size 字段。这里只报告**本轮实际得到的原生尺寸**，不能证明它是该工具理论最大尺寸；没有放大到 2048 冒充原生母版。
3. 两张木纹稿尺寸略不同，但均为同样目标的平面纹理。色值与单位像素统计可比，不能把尺寸差当改进，也不能做逐坐标同图差分。
4. 已检视全图与偏移／平铺证据；聊天中的缩略显示会降低小接缝的显著性。文件保留原尺寸，调用方应在目标缩放下复核。
5. 本轮没有将素材乘到真实奶油 CSS 上，也没有跑手机版或桌面组件。因此不宣称纸上正文 6.5:1、次要字 3.2:1、照片层级、木框角接、实际 512px 平铺或运行时体积通过。
6. 自审是同一 agent 完成。调用方 Monet 的独立复核与后续批准尚未发生；报告没有代替它。

## 7. 建议与交接结论

- 三张选用稿可以作为**带已知缺陷的原始生成材料**交给 Monet；本轮不建议直接登记为合格无缝素材。
- 纸优先进入调用方复核：最接近外观与整体数值目标，需明确处理或接受单点亮度越界及轻微通道色偏，不能偷偷四舍五入抹掉问题。
- 软木需先判断偏色、色域与可见截断是否可接受；木纹需先解决左右断纹。调用方 brief 已把后续尺寸、WebP 和任何接缝处理交给 Monet 的仓库脚本；**即使后续处理成功，也属于另一个处理后的版本，不代表本轮原始生成通过“天然无缝”**。本报告不为尚未执行的处理背书。
- 所有处理后的素材都需重新做偏移／2×2（木纹只查 X），再在指定页面复核。图钉仍保留现有 CSS，未生成、未接入。
