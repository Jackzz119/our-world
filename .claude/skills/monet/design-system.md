# Design System 规范（项目内 arts/ 文件夹）

## 目录结构（每个项目目录下）

```
<project>/arts/              # 美术素材总库（图书馆）：全部素材含候选与淘汰稿
├── tokens.md                # 四件套：色板/质感关键词/形状语言/光照逻辑 + 画风锁定词表 + threadId
├── moodboard.html           # 临时生成的可视化 mood board（见下）
├── refs/                    # 外部参考图与定调依据
└── <分类>/                  # bg / characters / props / symbols / items / ui / audio ...
                             # 生成管线的全部产出先落这里
<project>/public/assets/generated/   # 运行时采用中的素材（货架）：游戏实际加载
```

- **图书馆→货架**：生成管线先把素材写入 `arts/<分类>/`（含淘汰稿，可追溯）；集成时把采用的复制进 `public/assets/generated/`
- 两边各有 manifest.json，货架 manifest 是图书馆 manifest 的"采用中"子集
- 替换素材时旧版留在 arts/，货架上覆盖——风格演化史全程可查

## tokens.md 模板

```md
# <项目名> Design Tokens
视觉签名：<一句话，如"深夜甜点塔的暖可可水粉">
## 色板（≤5）
- --cocoa #2a1c16 底色 / --cream #f6e7d3 主文字 / ...（名称+hex+用途）
## 质感关键词
手绘软边、水粉、轻微纸张颗粒、糖霜高光、拒绝塑料3D
## 形状语言
圆角>直角、短肢大轮廓、果冻弹性
## 光照逻辑
单一暖光源自上、金黄点缀=奖励专用色
## 画风锁定词表（生成用，原样携带）
<codex 批次1回复的锁定关键词>
## threadId
<xxx>（工具/日期）
```

## Mood Board 生成方法

用户想看整体风格、或风格审计需要全景对比时，临时生成 `assets/<project>/moodboard.html`：
- 内容：视觉签名标题 + 色板色块条（hex 标注）+ 质感关键词 chips + 素材网格（`<img>` 引项目 public 内素材，按分类分区，深色底衬透明图）+ 每张标注文件名/尺寸/用途（读 manifest.json 生成）
- 打开方式：preview/浏览器直开；需要分享时走 Artifact
- mood board 是**快照不是资产**，风格更新后重新生成覆盖

## 风格审计清单（新素材入库前）

- [ ] 色板：取样 3-5 个主色，是否落在 tokens 色板±轻微容差内
- [ ] 质感：边缘处理/颗粒感/高光逻辑与基准图一致
- [ ] 形状：轮廓语言（圆角度、比例夸张度）一致
- [ ] 光照：光源方向与色温一致
- [ ] 缩小测试：游戏实际显示尺寸下可辨识、与邻近素材和谐
- [ ] Alpha：无脏边/半透明残留
- [ ] 禁文字：图内无任何文字/数字/水印
- 轻微偏差→修正指令；系统性偏差（≥3 处或基准图问题）→ **询问用户是否全盘复查**
