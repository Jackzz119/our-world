# UX 决策登记簿（Our World）

> ux skill 的项目决策存档：网上调研结论 + 用户拍板的交互规则。追加式登记；推翻旧决策时标注「已废弃 → 见 D-x」，不删除历史。

## D-1 时间线 = 单列日记流（2026-07-05）

亲密内容用单列日记流（Between / Day One / 恋爱记 / SumOne 行业共识）；中央脊线 + zigzag 是企业「发展历程」页的技术叙事，禁止回潮。位置只管节奏、颜色管身份。详见 `ai/Features/ui-system.md` 六。

## D-2 composer 草稿规则（2026-07-06）

隐式动作永不销毁内容：点外部 / Esc → 收起保草稿（文字+图）；「取消」是唯一显式清空路径；折叠 pill 有草稿时必须可见（✎ 草稿贴纸 + 首行预览 + 图数）。对齐 X / Gmail 的 draft-on-dismiss 惯例。

## D-3 语音与场景的耦合模型（2026-07-06 调研 + 用户拍板）

**结论：耦合模型（Gather / VRChat 系），不采用 Discord 的解耦模型。**

调研对照：
- **Discord**：产品里没有「场景」，语音频道本身就是「地方」；连接与浏览解耦（人在语音频道 A，眼睛可以看任何文字频道/其他服务器）；提供 闭麦(mute) / 静音(deafen) / 断开(disconnect) 三级控制；「重启自动重连语音」被社区诟病隐私问题
- **Gather.town**：在场即语音——音视频随 avatar 接近度自动激活，离开空间 = 离开音视频；语音是「身在房间」的属性
- **VRChat / Rec Room**：语音随 world instance，离开实例即断开

本产品「房间 = 场景 + 语音」（`ai/Features/channel.md`）属于空间在场模型，规则如下：

1. **退出场景 = 自动退出语音**（共享音乐一并停止）——退出走场景上的悬浮 UI，回大厅，非破坏性、随时回来
2. **「退语音不退场景」不设 disconnect 态**：由 闭麦（不发声）/ 静音（不收听，= Discord deafen）覆盖——保持「连接 = 在场」的单一心智模型
3. **「退场景不退语音」不存在**：离开房间即不在场。但 **UI 导航 ≠ 退出场景**——打开时间线弹窗、切文字频道、看照片墙时语音保持（吸收 Discord「看哪儿与站哪儿解耦」的洞见，只是把「站哪儿」定义为房间而非语音频道）
4. **不做重启自动重连语音**；回房间重新走「进房自动接语音、默认闭麦」（channel.md C-4）

## D-4 退出三层体系（2026-07-06 用户拍板）

| 层 | 语义 | 入口 | 性质 |
| --- | --- | --- | --- |
| 退出场景（房间） | 离场回大厅，语音随之断开 | 场景内悬浮 UI | 非破坏，随时回来 |
| 退出世界 | = Discord「Leave Server」：脱离成员关系，需确认，需重新被邀请才能回 | 世界层菜单（位置待定） | 破坏性，需确认 |
| 退出账号 / 换账号 | 登出 auth 会话 | 设置页（`ai/Features/settings.md`，later） | 会话级 |

补充规则：**owner 不能「退出」自己的世界**（对齐 Discord：服主只能转让或删除服务器，不能一走了之留下孤儿世界）。

## D-5 「连语音但不出现在场景」的分流（2026-07-06 用户拍板）

**原则：「在场」永远诚实——不想活跃换姿态，不想在场换信道，隐身不存在。**

- **幽灵模式（avatar 隐身但语音在线）明确不做**：破坏场景在场真实性（「闹鬼」）；两人语境下隐身瞒不住（成员列表/声音都在），只传递「不想被你看到」的伤信任信号；Discord 也不允许隐身呆在语音频道
- **需求 A「连着声音但我在忙」→ 挂机态**：avatar 不消失而是换可视化姿态（小憩/打盹云朵/Zzz，视觉走 mockup 比稿），语音保持、默认闭麦规则照旧——参考 WoW 系 AFK 可视化：状态改变而非存在消失；陪伴感加分项
- **需求 B「想说话但不想进房」→ 私信语音通话（DM call）**：独立于房间的纯通讯层，不产生场景在场（吸收 WoW「语音与角色位置解耦」，但装进私信语境不打穿房间模型）；排期在语音基建之后

## D-7 聊天消息状态与操作体系（2026-07-10 调研 + 用户委托裁决）

mockup：`ai/design_system/cinnaglass/chat-message-states.html`。用户拍板范围（发送中/失败/编辑/删除粒子/reaction/已读讨论/reply 规划），形态由 UX 比稿后代选：

1. **发送中 = 乐观上屏 + 半透明微光 + 云朵伴飞**（Discord 乐观渲染；玻璃拟态用透明度当状态语言，弃 WhatsApp 时钟——meta 行存在感太弱）
2. **失败 = 腮红粉警示气泡 + 「🌧️ 没送出去 · 重试/删除」行**；沿用 D-2 原则：隐式动作永不销毁内容，重试前文字一直在
3. **已读：游标头像形态，~~频道 + 私聊~~ → 仅私聊（2026-07-10 用户裁决修订）**：世界频道**不显示任何已读状态**，游标头像（Messenger 式，hover 显示「已读 HH:mm」）只在私聊里做（DM 阶段实现）。频道侧仍**静默记录**自己的已读游标（`channel_reads` upsert 保留），供未读红点与 DM 复用——记录与显示分离。原调研结论（情侣产品已读=陪伴感、游标头像可扩展多人）在私聊语境继续成立
4. **消息操作唯一入口 = hover 浮出操作条**（Discord 式）：快捷表情 ×3 + ➕picker（预留世界表情库）+ 编辑/删除（仅自己的消息）+ 回复（占位，reply 阶段启用）；移动端长按 later
5. **reaction chips 贴气泡下缘**，自己点过的高亮蓝框、再点取消，hover 显示是谁点的
6. **编辑 = 气泡原位变输入框**（Enter 存 / Esc 撤）+ 「(已编辑)」小标
7. **删除 = Telegram 式粒子消散**（用户指定），配色换玻璃碎星（蓝/粉/白/奶油），左→右溶解 ~600ms；双端同删（DB 删 + DELETE 广播，对端也播粒子）；仅能删自己的消息，v1 不设时限
8. **reply 引用回复形态（2026-07-10 补进 mockup ⑧，实现排 DM/表情之后）**：发起 = 操作条 ↩︎ → composer 上方「回复中」pill（×/Esc 取消）；展示 = 气泡顶部引用条（竖线 + 作者名 + 单行截断原文），点击滚动跳转原消息并高亮一闪（Telegram/Discord 共识形态）；**原消息被删除 → 引用条直接消失，不显示墓碑**（`reply_to_id` 置 null 不级联删回复）；**已删除的消息不可被回复**——初版墓碑态设计被用户裁决推翻（2026-07-10）

> D-7 追记（2026-07-12 用户拍板）：**消息排列默认全部靠左**（Discord 式，自己的消息也进左侧消息流，身份靠蓝气泡 + 「我」meta 区分）；设置 → 主题外观 提供「全部靠左 / 左右分侧」切换（tweaks.chatAlign，本地持久化、每端各自生效）。

## D-8 好友与 DM 分离 + Discord 式好友页（2026-07-10 用户拍板）

mockup：`ai/design_system/cinnaglass/friends-page.html`（A Discord tab 页 ✔ 采纳 / B Steam 分组单页存档备查）。推翻同日早些的「好友行合并私信行」构想（home-panel-friends.html ②③ 作废，① Home 面板功能入口形态仍待拍板）：

1. **好友（关系管理）与 DM（会话列表）分离**：聊天中心左栏 = 置顶「好友」入口（收到申请挂粉色红点）+ 私信列表；点好友 → 右侧整页切换为好友页
2. **好友页 = Discord 式 tab 过滤**：页头 tab 键 全部 / 待处理（红点计数）/ 在线（禁用占位，presence 基建后启用——不做假在线）/ ＋添加好友（绿色动作键，视图 = 邮箱输入 + 发送申请）
3. **好友管理只住好友页**：sidebar Home 面板不再内嵌添加/申请/好友列表，只留入口行；好友行动作 = 💬 开私信（跳转左栏对应会话）+ ✕ 解除（confirm 提示保留聊天记录）
4. **DM 行副题 = 最后一条消息**（会话感，承载未来未读数字与最近活跃排序）
5. 调研备注：Discord 用户长期抱怨缺「置顶好友」（Steam 有收藏分组）——将来可在 tab 模型内加「特别关心」组
6. Home 面板定位（用户 2026-07-10）：**个人功能收藏栏**——好友/商店/未来的收藏、相册、小游戏皆从此进；功能入口形态**已拍板：列表流（①A，2026-07-12）**——一行一个入口，与世界栏语言一致；收藏架（①B）存档，功能多起来后可重议
7. mockup 勘误（2026-07-12 用户发现）：比稿里的在线绿点曾偏离产品既定 `.odot` 规范（#5fcf8e + 白描边 + 荧光光晕，见 sidebar.tsx），已修正——**比稿必须同源复用产品 token/组件样式，不得自绘近似物**

## D-9 配色体系「晴空琉璃」：白玻璃壳 + 白纸内容层（2026-07-12 调研 + 用户委托裁决）

mockup：`ai/design_system/cinnaglass/color-palette.html`（三方案同景比稿）。用户观察到白底 mockup 更好读、更贴大耳狗，委托 UX 调研后选型落码。

调研依据（两条外部证据指向同一分层法则）：
- **大耳狗官方色**：白 #FFFFFF 占绝对主面积、天蓝 #59C5ED 只做灵魂点缀（logo/眼睛）、腮红粉 #FDD5E7 是唯一暖点 —— 白是主角
- **Apple Liquid Glass（WWDC25）**：玻璃材质只留给导航层；内容坐在可读实底上；**玻璃叠玻璃是反模式**；玻璃在浅色内容上变亮、前景文字变深

选型结论（方案 C「晴空琉璃」，胜过全白 B 与现状 A）：
1. **导航层 = 白玻璃壳**（sidebar / modal / HUD / dock）：默认 74% 白 + saturate 1.6（透进的场景色更鲜，模拟 Liquid Glass 折光）
2. **内容层 = 纸面 token `--glass-paper`**（新增）：卡片/设置行/聊天气泡/输入区一律坐纸面（.90~.96 白；twilight 用深纸 rgba(32,45,78,.86)）；**玻璃壳内不再套第二层玻璃**
3. **文字加深提对比**：正文 #2A3A5E → #22335A，副文字 62% → 70%
4. **accent 对齐官方色**：#7CC6EC → #59C5ED，deep #4FA9DC → #2F9AD3；--blush → 官方 #FDD5E7
5. 三档玻璃质感保留并重定调：云朵 = 瓷白（最贴大耳狗）、天空 = 白提亮的淡蓝染（默认）、暮光 = 夜用深玻璃 + 深纸面（顺带修复白卡浅字的可读性隐患）

追记（2026-07-12 同日）：**用户拍板确认方案 C**（以比稿 DAY 格观感为准；中途曾误解为方案 B，已回退）。落地时发现并修复关键实现偏差——**多处内容卡在玻璃壳内套第二层 `.glass`**（设置 set-group、日历纪念卡/事件行/闹钟行、心愿卡、时间线卡/composer/详情卡），正是「玻璃叠玻璃」反模式，导致内容始终坐不上纸面。新增全局 `.paper` 工具类（cinnaglass.css，= var(--glass-paper) 实底 + 细边 + 浅影），上述内容卡全部由 `glass` 改挂 `paper`。**后续新组件规则：壳用 `.glass`，壳内内容卡一律 `.paper`，禁止嵌套 `.glass`。**

第二轮全面排查（同日，用户反馈 sidebar 未变后全主题走查）補充规则与落地：
- **表面三分类**：壳（.glass）/ 常驻内容卡与输入框（--glass-paper）/ 交互态 hover·选中·按钮·控件轨道（--glass-bg-2 / --glass-hi，保持半透明作为反馈语言）
- 追加上纸面：sidebar 房间语音卡 sb-rcard、成员卡 sb-pcard、底部用户栏 sb-user；全部文本输入框（.field 原语、聊天 dock、频道 composer、好友页、日历事件/闹钟、设置密码/日期）；reaction chip 常驻态
- **玻璃壳渐变尾端 --glass-bg-2 提亮**（默认 .52→.6，sky .48→.6，cloud .62→.68）：全高面板（sidebar）下半段不再透进大量场景色——这是「sidebar 看起来没变」的直接原因

第三轮实景校准（同日，用户反馈「灰、不统一、白卡间无分隔」后定稿）：
- **根因**：比稿压在明亮薰衣草底上、app 场景是深紫——同一透明度实景发灰。**壳提到近实底白**（默认 rgba(248,252,255,.94)→rgba(255,255,255,.87)，sky 带一丝天蓝，cloud 瓷白 .97）；--glass-paper = 纯白 #fff
- **新增三 token，「白当底、蓝分层」**：`--glass-line` rgba(33,57,92,.1)（发丝分隔线/卡边/滚动条——白上白的边框全部替换）、`--glass-hover` 浅天蓝悬停、`--glass-active` 天蓝选中（替换原先白色 hover/on，白上白隐形）
- 设置 seg 控件 = 浅蓝轨道 + 白瓷选中钮；开关 .sw 轨道浅蓝；心愿勾选框蓝边 rgba(79,169,220,.45)
- **全窗口截图自检通过**（大厅/世界 sidebar/设置/日历/空间/时间线三 tab/聊天中心+好友页/HUD 工具箱/聊天 dock）；比稿 color-palette.html 已补「落地修正 v2」注记（比稿背景亮度必须贴实景，否则透明度失真）

质感层定稿（同日第四轮，用户要求保住渐变/玻璃质感/阴影层次，在白底体系内实现）：
- `--glass-paper` = 釉光渐变（纯白 → 底部微天蓝 #f5fafd~#fafcff；twilight 深釉），配 `.paper` 三层影：贴地影 + 环境影 + 顶部高光内线
- `--glass-active` = 天蓝玻璃渐变（135deg 左上受光），选中态不再平涂
- `.glass` 壳补底部冷色 rim light（inset 0 -1px rgba(174,223,242,.3)），与顶部白高光线成对
- 分隔线 = 两端淡出的渐变发丝（设置行分隔、rail 分隔）；控件轨道（seg/sw）内凹阴影，选中钮白瓷凸起
- 体系口诀：**白当底、蓝分层、光影造深度**——透明度让位给可读性后，玻璃感由高光线/rim light/釉光渐变/阴影栈承担

第五轮全局复检（同日，用户委托按 UX 判断精修）：**主行动渐变收编为 token**——新增 `--accent-grad`（135deg #8ed7f4→#4fb0e4，主按钮/FAB/我的气泡/开关 on/图标底，twilight 有专属柔化档）与 `--accent-orb`（球面渐变，FAB/chip-accent），替换全主题 20+ 处硬编码旧蓝（#9fd6f4→#5fb0e2、#7CC6EC 系 radial、90deg 进度条变体）；配套发光阴影 rgba(79,169,220,*) → rgba(47,154,211,*) 对齐新 deep；hud 本地 .sw 轨道同步内凹样式。至此主题内不再存在游离于 token 之外的品牌色（登录页太阳球为场景艺术，豁免）。全窗口截图复检通过。

## D-10 色彩气质「晴空水彩」+ 光照暖化 + 悬浮糖果 dock（2026-07-12 比稿 + 用户拍板）

mockup：`ai/design_system/cinnaglass/texture-palette.html`（三色彩气质 × 质感四件套 × rail 两式）。用户裁决：

1. **色彩气质 = 方案 B 晴空水彩**：壳升级为三段水彩渐变 token `--glass-shell`（白 → 天蓝 → 薰衣草收尾），`.glass` 改用它（保留 bg/bg-2 作后备），三档玻璃质感各有专属水彩；解「壳是死白平涂」
2. **光照自适应暖 active（A 方案奶油的活用，用户激赏）**：`[data-mood=golden/night]` 时 `--glass-hover/--glass-active` 自动切换为奶油/黄油渐变（夜里的暖灯感），暮色保持天蓝；`data-glass=twilight` 下有降亮度的暖档组合选择器——纯 CSS 联动，零 JS
3. **rail = R-B 悬浮糖果 dock（2026-07-13 用户两次修订后定稿）**：展开时 rail 保持通栏长条与 panel 融为一体；**收起时形变为垂直居中的糖果胶囊，直接悬浮在场景之上——没有任何自己的条状背景**（修订 v2 推翻了初版的氛围条带方案）。实现：railzone 宽度动画归零（场景随之扩到全宽），zone `overflow:visible` 让胶囊溢出浮在场景上方并保持点击；胶囊带糖果渐变描边（白→天蓝→腮红粉）+ 高光 + 浮起投影 + 独立 backdrop-blur（模糊透出身后场景）。**两态之间 0.45s 同步形变**：rail 用可动画的 flex-grow 做高度收缩 + width/border-radius/margin/box-shadow 过渡（长条 → 胶囊），panel 走宽度收合（保持挂载、`.closed` 宽度归零，子元素固定宽度防文字回流——像拉幕布一样裁切）；`prefers-reduced-motion` 全部禁用动画。旧的左侧选中指示条移除（与胶囊圆角冲突，选中态由方圆变形 + accent 环承担）
4. 质感四件套范围维持 D-9 定稿：描边渐变（rail 胶囊专属）/高光/阴影全局，流光 sheen 仅纪念时刻（未实现，排后）

全窗口自检：大厅胶囊态/收起态、世界内、黄昏奶油 active、夜晚暖灯 active、暮色保持蓝 —— 截图全过。

## D-12 光照递进定稿：明度交给时辰，玻璃档退回材质档（2026-08-07/08 codex 设计 + 审核 + 迭代）

**推翻 D-11 的「全局中性暗色」**：用户裁定「黄昏不够白，之前的白其实不错，问题在场景光暗；三档应是递进，有 Stripe 明暗双主题的感觉」。设计与审核均由 codex（`codex-visual` skill）执行，Claude 给上下文、定标准、复核并落码。

设计稿与报告：`ai/design_system/cinnaglass/mood-progression-codex/`（3 张 1440×900 + codex-report.md，含 Stripe/Linear/Apple HIG/Day One/Sanrio 调研）。

### 架构

1. **明度由 `[data-mood]` 驱动**（黄昏近白 → 暮色雾灰 → 夜晚石墨），PAPER 恒为 `#FFFFFF` 不随时辰变——记忆永远是全场最亮
2. **`[data-glass]` 退回材质档**，只管 blur/saturate（云朵厚 34px/104% · 天空默认 · 暮光薄 14px/142%），消除与明度轴的语义重叠
3. **`--shell-*` 为规范名，`--glass-*` 为别名**；纸面重映射改的是别名，需要退出重映射的元素引用 `--shell-*`
4. **新增 `--app-ground`**（codex token 表没有，因它不知道本产品布局）：sidebar 是 in-flow，玻璃背后是 app 底色而非场景。**必须是渐变不能是实色**——实色让 backdrop-filter 无输入，玻璃塌成平板（codex 审核 High #3）
5. 新增 `--stage-content-scrim` / `--stage-content-filter`，产品 `.modal-scrim` 与验证页共用
6. 新增 `--shell-focus-border`：夜晚档给打开的 modal 一圈冷蓝 rim，与普通暗 chrome 拉开层级；**不给整条 sidebar**

### 两个必须记住的坑

- **CSS 变量别名在声明处求值**：`:root{--glass-text:var(--shell-text)}` 会被冻结在基准档，夜晚档出现「暗壳深字」。解法是在 `[data-mood]` 宿主上重新声明一遍别名
- **改半透明壳的透明度 = 同时改了文字对比度**。codex 让压暗暮色壳、又给了基于旧亮壳算出的副文字色 `#414D66`，两条建议互相打架，实测掉到 3.84:1。最终按像素采样反解：壳 alpha .66/.60/.58，正文 `#212C48`，副文字 `#313C58`，实测最差 4.73:1 通过

### 验收方法（已固化）

`ai/design_system/cinnaglass/impl-three-up.html` —— `<link>` 直接引用真实 `cinnaglass.css` 的三档同屏验证页，headless Chrome 出图后**像素采样算对比度**，再交 codex audit。验证页必须复现打开内容的 scrim、用 `currentColor` 真实图标（emoji 自带颜色会造成对比度假阳性）。

**遗留**（codex 标注、本轮未做）：Golden 色温略冷（他建议先只改 app-ground，二次再议）、验证页应直接挂产品组件而非缩小替身、夜晚长时间观看舒适度需真机暗室实测。

## D-11 沉浸感转向「星夜书房」+ UI Design System 建册（2026-07-13 调研 + 用户拍板）

mockup：`ai/design_system/cinnaglass/immersion-palette.html`。**推翻 D-9/D-10 的白色外壳路线**（白底方向本身没错，错在只优化可读性、丢了明度层级）。

诊断：沉浸感 = **明度阶梯**。旧版 UI 壳 96% / 内容纸 100% / 场景 82% 全挤在高明度区，差值 <20% → 画面平、眼睛找不到主角。行业共识（Spotify/Netflix/Apple Photos/Day One）：**暗外框让内容成为主角**。大耳狗 ≠ 只能白底——它的经典形象本就是睡在星空弯月上，天蓝该当「发光点缀色」而非大面积背景。

用户拍板（三项全采纳）：

1. **方案 C 星夜书房**：外壳转暮色玻璃（浅色字），**内容纸保持纯白 + 深色字**——照片/日记像暗室书桌上的实体照片一样跳出来
2. **随光照自动切换**：`[data-mood]` 联动，「UI 明度永远比场景低一档」——黄昏（场景亮）外壳提为暖紫暮色 + 奶油强调色；夜晚（场景暗）外壳再沉 + 天蓝辉光加强；暮色保持基准星空蓝
3. **场景三开关全开**：`.stage::after` 常驻暗角（博物馆打光）、`.stage::before` chrome 侧压暗、`.modal-scrim` 加 `brightness(.82)`（进入回忆的仪式感）——挂在 stage 级，2D/大厅/3D metaspace 全覆盖

**关键实现：双色域 token + 纸面自动重映射**。`--glass-*` 为外壳域（浅字），新增 `--paper-text/sub/line/hover/active/shadow` 为纸面域；`cinnaglass.css` 里一段选择器清单把纸面表面的 `--glass-*` 重指向纸面值——组件 CSS 无需改动即在两个色域都正确。**新增白底组件必须登记进那份清单**，否则白底浅字。三档玻璃改为暮色深浅梯度（云朵=薄暮/天空=星夜/暮光=深夜）。sidebar 底部账号栏判定为 chrome（不给白纸，白条会盖过记忆）。

**UI Design System 建册**：`ai/design_system/cinnaglass/ui-system.html`（六节：概念/双色域/Token 总表/档位预览台/组件库/维护规则），token 实时 `<link>` 引用 `cinnaglass.css` 永不过期；维护职责已写入 ux skill 第 7 条。

追记（同日，用户反馈「暮色太深、颜色太明确、应该更中性」后定稿）：**外壳改为中性烟熏玻璃**——初版用了饱和藏蓝/紫（rgba(44,58,98) 系），会与照片/头像/强调色抢戏且易看腻。新法则写进体系：**Chrome 中性 · Accent 彩色 · Paper 纯白**——外壳几乎不带色相（三档改为石板灰梯度 rgba(106,110,124)/rgba(76,81,98)/rgba(48,51,64)，整体提亮、饱和度 150%→135%），hover 改为无色相白洗，**唯一保留色相的外壳元素是选中态**（它是 accent 信号）；mood 档只做「微微偏暖/偏冷」的倾向，不再变成彩色面板。
